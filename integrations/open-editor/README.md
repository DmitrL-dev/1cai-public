# Рентген в VSCodium / Cline

Adapter готовит отдельный профиль для уже установленного ядра **0.1.0.dev7**
с MCP **1.30.0**, Windows x64 / Python 3.11. Собственный код MIT; Cline 4.1.17 —
Apache-2.0. Это интеграция черновиков; полный комплект редактора и ежедневный
цикл диагностика → тесты → применение пока не приняты.

В профиль включён собственный [просмотр проекта](../vscode-rentgen/README.md):
модули снимка, поиск, история черновиков и сравнение версий в проводнике.
VSIX собирается из соседнего каталога `vscode-rentgen` без сети, копируется
в профиль и проверяется установщиком по SHA256. Запускайте генератор из полного
checkout, сохраняя оба каталога интеграции.

Используйте установленный редактор и локальный VSIX из
[официального релиза Cline 4.1.17](https://github.com/cline/cline/releases/tag/v4.1.17).
SHA256 VSIX закреплён в `prepare.py` и повторно проверяется установщиком:
`82875472744ded4a360e22c726bb6101962ecf0a178aa8efe84a5c7ea728d2f5`.
Загрузок из сети эти скрипты не выполняют. Лицензия Cline остаётся внутри VSIX.

Открытый редактор для текущей проверки:
[VSCodium1.135.06055 Windows x64 ZIP](https://github.com/VSCodium/vscodium/releases/tag/1.135.06055),
SHA256 `0bec978f201238624bc9ad43966f5e201ed8afacc37d77035a822252d9c9c200`.
Архив250898961байт; после распаковки укажите его `VSCodium.exe` в `--editor`.
MIT license и уведомления сохранены внутри исходного архива.

## Подготовка

Сначала установите [офлайн-ядро](../../docs/product/CORE-INSTALLATION.md),
зарегистрируйте проект и создайте снимок публичным CLI. Для существующего
проекта schema3 выполните явную миграцию workflows по инструкции ядра.

Из корня этого репозитория (замените пути и `PROJECT_UUID` своими):

```powershell
python integrations/open-editor/prepare.py --python C:\Rentgen\env\Scripts\python.exe --registry C:\Rentgen\registry.sqlite3 --project-id PROJECT_UUID --editor 'C:\Program Files\VSCodium\VSCodium.exe' --cline-vsix C:\Downloads\claude-dev-4.1.17.vsix --output C:\Rentgen\editor-profile --scanner C:\Rentgen\bsl-scan.exe
& C:\Rentgen\editor-profile\install.ps1
& C:\Rentgen\editor-profile\launch.ps1
```

Для проверенного локального варианта добавьте `--ollama-model qwen3.5:4b`.
Модель должна быть заранее доступна в Ollama на `127.0.0.1:11434`;
название здесь — пример установленной модели, не обещание качества разработки.
Без этого параметра выберите провайдера/модель в настройках Cline.
API-ключи подготовка не принимает и не копирует. Для диагностики установите
BSL runtime из заранее полученных файлов:

```powershell
C:\Rentgen\env\Scripts\python.exe -I integrations/open-editor/install_bsl_runtime.py --java-home C:\Downloads\jdk-21.0.12.1+1 --jar C:\Downloads\bsl-language-server-1.0.5-exec.jar --local-app-data C:\Rentgen\diagnostics
```

Каталог `C:\Rentgen\diagnostics` должен существовать. Добавьте тот же путь в
генератор профиля как `--diagnostics-local-app-data C:\Rentgen\diagnostics`.
Он задаёт `LOCALAPPDATA` только процессу MCP. Это также позволяет выбрать
обычный каталог вне виртуализируемого AppData приложения MSIX.
Без параметра используется унаследованный `LOCALAPPDATA`.
Установщик не скачивает и не запускает Java: он проверяет каждый файл JDK и
JAR по манифесту установленного ядра, сохраняет лицензии и отказывает при
несовпадении. Существующий runtime проверяется, но не перезаписывается.
После ошибки каталог незавершённой установки сохраняется для разбора.
Точный профиль и ограничения приведены в инструкции ядра.

Без `--scanner` доступны чтение/черновики, но
новый capture не выполняется. Отсутствующий runtime диагностики даёт явный отказ.

Откройте Cline → MCP Servers: сервер `rentgen` должен подключиться.
В проводнике доступны «Рентген: модули» и «Рентген: черновики». Кнопка поиска
фильтрует пути во всём выбранном снимке; обновление явно переключает снимок.
Нажатие на черновик открывает diff, раскрытие — историю. После работы агента
обновите список. Просмотр не обращается к модели и не применяет изменения.
Рабочее место содержит `START-HERE.md` и `.clinerules/rentgen.md` с точным ID
проекта и последовательностью действий. Попросите агента найти модуль и
сохранить предложенную правку как черновик. Все автоматические согласования
в свежем профиле выключены. Согласуйте нужные вызовы через UI Cline. Если
включаете отдельные автосогласования MCP, оставьте общий `actions.useMcp=false`:
Cline 4.1.17 использует OR между общим флагом и списком инструментов. Общий
флаг разрешает все MCP-инструменты. Настройка UI не заменяет права ядра.

Профиль фиксирует ID проекта в инструкции и параметрах MCP, а права проверяет ядро по SID.
Launcher передаёт `RENTGEN_EDITOR_PROFILE`; companion читает Python, registry
и project_id только из этого startup profile. Требуется доверие к рабочей папке.
Новые профили требуют dev7: кроме ограничения проекта и инструментов, сервер
объясняет ошибки схемы, указывая недостающие поля и ожидаемый формат.
Агент может читать русский текст через
`rentgen_draft_read` с `encoding=utf-8`, не декодируя base64 самостоятельно.
Companion 0.1.4 поддерживает просмотр на dev4–dev7; локальная правка требует dev7.
dev4 также содержит исправление
явных `--limit`/`--status` CLI. Существующий registry schema4 мигрировать не нужно.
В MCP разрешены девять инструментов: head, поиск исходников, создание/чтение/
правка/диагностика черновика, квитанция операции, список и история черновиков.
Сервер скрывает и отклоняет остальные; другой project_id, в том числе во
вложенной ссылке, получает отказ. Capture и управление архивом доступны через
отдельный доверенный CLI, а не эту сессию агента. Это профиль разработки с
сохранёнными черновиками; для их создания/изменения нужны права `source:edit`.
Параметры закреплены при запуске; изменение инструкции агента не расширяет их.
Изоляция других процессов того же Windows SID этим не обеспечивается.
Чтение исходного модуля и изменение черновика выполняются через MCP.
Каталог рабочего места отделён от живой конфигурации.

## Версии и сохранность настроек

Подготовка отказывает до записи при недоступном проекте, неверном VSIX,
неподдерживаемом core/runtime или неоднозначном расположении CLI редактора.
Существующий каталог профиля не перезаписывается. Если запись оборвалась,
сохраните неполный каталог для диагностики и укажите новый.

У Cline 4.1.17 разные хранилища: настройки модели идут в `CLINE_DATA_DIR`,
а VS Code MCP transport читает
`editor/User/globalStorage/saoudrizwan.claude-dev/settings/cline_mcp_settings.json`.
Этот путь подтверждён запуском расширения, а не только актуальной веб-справкой.
Автоматическое обновление расширения в профиле отключено. Обновление Cline
требует новой проверки adapter; изменение только номера версии недостаточно.

VSIX4.1.17 содержит два движка (`legacy` и `next`) с механизмом rollout.
Launcher явно задаёт `CLINE_BUNDLE_OVERRIDE=legacy`: именно этот движок прошёл
проверку совместимости и использует описанные пути. Переменная вызывающего
PowerShell восстанавливается после запуска. Профиль, созданный более ранним
генератором без этого закрепления, следует создать заново в новом каталоге.
`next` не включается автоматически и требует отдельной проверки.

Скрипты записывают настройки и расширения только в выбранный каталог профиля.
Launcher восстанавливает переменные вызывающего PowerShell.
Сам редактор/Cline может обращаться к своим служебным сетевым сервисам; полная
сетевая изоляция редактора этим профилем не заявлена. Проверен VS Code1.127.0.
В VSCodium1.135.06055 подтверждены установка Cline, activation, подключение MCP,
чтение снимка и создание черновика. Полный запуск с локальной9B-моделью достиг
таймаута до сохранения правки. На том же снимке вариант4B завершил сценарий
за88,1секунды; точные ревизии и сохранность исходника подтвердил отдельный CLI.
Модель4B с окном32K целиком поместилась в GPU RTX4060/8GB. Это приёмка
искусственной правки, не оценка качества сложной разработки1С.

## Проверка adapter

`tests/unit/test_open_editor_profile.py` проверяет отказы, сохранность и аргументы.
`scripts/verification/run_open_editor_host.py --profile PROFILE` запускает
настоящий Cline в отдельном Extension Development Host и записывает версии,
место установки и activation. Опциональный `--prompt-file FILE` запускает
реальный запрос к выбранной в профиле модели: используйте искусственный проект
и заранее проверьте настройки провайдера. Ограничение попытки — 240 секунд /
9 запросов после старта задачи. Весь процесс имеет отдельный предел300секунд;
при его превышении проверочный runner завершает своё дерево процессов с кодом124,
без повторного запуска модели. Завершение модели не является критерием успеха; проверяйте результат
через отдельный CLI и хеши исходных байтов.

Для искусственного сценария `BeforeEditor` → `AfterEditor` есть отдельный
`scripts/verification/verify_open_editor_draft.py --profile PROFILE --source MODULE --output NEW_JSON`.
Он связывает журнал MCP с настоящими квитанциями и ревизиями, прочитанными
новым процессом CLI. Незавершённая модельная задача даёт `accepted=false`
даже при нулевом exit code редактора. Это проверка одного заданного сценария,
не верификатор произвольных чужих отчётов.

В development checkout также есть [управляемая локальная правка](../../docs/product/LOCAL-REPAIR.md)
через `run_repair.py`: служебные запросы формирует адаптер, модель возвращает
только замены текста. Этот CLI также включён в companion 0.1.4 и запускается
командой «Правка с локальной моделью» у строки модуля.
Две попытки на Qwen3.5:4b не прошли содержательную приёмку. На Qwen3.5:9b
без рассуждения принят один искусственный сценарий исправления подавленного
исключения: новая ревизия и независимый BSL-анализ проверены. Это ещё не
приёмка произвольных задач или платформы 1С.


Профиль из ветки разработки теперь принимает также установленный core dev8
с MCP 1.30.0 и собирает companion 0.1.5. Версия ядра записывается по результату
проверки установки. Просмотр и нативная проверка dev8 описаны в
[README расширения](../vscode-rentgen/README.md); управляемая локальная правка
остаётся доступна только для dev7. Опубликованные сборки не перезаписываются.
