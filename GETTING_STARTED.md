# Первый запуск: от выгрузки до открытого модуля

[Главная](README.md) · [Пользовательское руководство](docs/USER_GUIDE.md) · [Все инструкции](docs/README.md)

**Первый результат:** сохранить снимок своей выгрузки и получить список модулей.
Для этого модель и установленная 1С не нужны. Затем можно подключить редактор,
подготовить черновик и добавить проверки.

## Перед началом

Поддержанный профиль установки — **Windows x64 / CPython 3.11**.
Подготовьте копию небольшой папки с исходниками конфигурации: XML-файлами и
BSL-модулями. Один файл `.cf` или `.dt` не подходит вместо этой папки в данном
маршруте. Если выгрузки ещё нет, попросите разработчика 1С подготовить её.

| Что вы выбираете | Для чего это нужно |
| :--- | :--- |
| Папка выгрузки, например `C:\MyConfiguration` | Исходные файлы проекта, доступные вашему Windows-пользователю для чтения |
| Новая папка состояния, например `C:\RentgenState` | Реестр проектов, снимки, история и результаты; требуется возможность создавать и читать файлы |
| Новая папка окружения Python | Отдельная установка Core и его зависимостей |
| Новая папка профиля редактора | Настройки интеграции и рабочие копии черновиков; понадобится на шаге 4 |

Папка состояния и профиль должны находиться отдельно от выгрузки.
Запускайте команды из обычной учётной записи, под которой будете работать:
доступ к проекту ядро связывает с Windows-пользователем. Чужому пользователю
права назначает администратор проекта по [отдельной инструкции](docs/product/PROJECT-ACCESS.md).

В PowerShell проверьте установленный Python:

```powershell
py -3.11 --version
```

Ожидается `Python 3.11.x`. Если команда не найдена, сначала установите CPython
3.11 для Windows x64. Комплект Рентгена Python не устанавливает.

## 1. Установите ядро

Выберите один маршрут:

| Маршрут | Когда выбирать |
| :--- | :--- |
| **Готовый ранний выпуск, команды ниже** | Хотите начать с опубликованного Core dev15 без сборки Python-пакета и scanner |
| [Сборка выбранных открытых исходников](docs/product/CORE-INSTALLATION.md#сборка-из-открытых-исходников) | Хотите работать с текущим checkout; версия читается из его `pyproject.toml`, сейчас это Core dev16 |

Готовый выпуск и текущие исходники имеют разные версии. Возможности и
подтверждения проверок сверяйте с [состоянием поставки](docs/product/READINESS.md).

### Готовый Core dev15

В [релизе Core dev15](https://github.com/DmitrL-dev/1cai-public/releases/tag/core-v0.1.0-dev15)
скачайте `rentgen-core-0.1.0.dev15-windows-py311.zip`.
Сначала откройте PowerShell в папке загрузки и выполните:

```powershell
Get-FileHash .\rentgen-core-0.1.0.dev15-windows-py311.zip -Algorithm SHA256
```

Полученный SHA256 должен совпасть со значением принятого выпуска:

```text
30040b536163a8b92f7aa611392c1bed29701819b1fd9ceb024248bf4482f867
```

**SHA256** — контрольная сумма файла: она помогает убедиться, что скачаны
те же байты, которые опубликованы в выпуске. При несовпадении установку
этого файла продолжать нельзя.

Распакуйте архив в новый каталог. Внутри папки
`rentgen-core-0.1.0.dev15-windows-py311` должны находиться
`mcp-requirements.lock`, `bsl-scan.exe` и папка `wheels`.
Откройте PowerShell именно в этой папке и выполните:

```powershell
py -3.11 -m venv .venv
.\.venv\Scripts\python.exe -m pip install --no-index --only-binary=:all: --require-hashes --find-links . --find-links .\wheels -r .\mcp-requirements.lock
.\.venv\Scripts\python.exe -m pip check
.\.venv\Scripts\rentgen.exe --help
.\.venv\Scripts\rentgen-mcp.exe --help
```

`.venv` — отдельная папка окружения Python: в неё устанавливаются ядро и
нужные этому сценарию зависимости. Вызовы `.venv\Scripts\...` используют
именно эту установку.

**Признак успеха:** `pip check` не сообщает о нарушенных зависимостях,
а последние две команды показывают справку. Если команда завершилась ошибкой,
разберите её до следующего этапа. Подготовка окружения не регистрирует проект.

Установка использует файлы из архива. В комплект входят ядро, его исходники,
scanner, зависимости MCP, лицензии и контрольные суммы. **Scanner** — отдельная
программа, которую ядро использует при захвате и построении графа связей.
Python, редактор, модель и Java / BSL Language Server устанавливаются отдельно.

Дальнейшие примеры предполагают, что вы остались в той же папке и той же сессии
PowerShell. Для установки из исходников используйте свои пути к `rentgen.exe`
и собранному scanner из [инструкции Core](docs/product/CORE-INSTALLATION.md).

## 2. Зарегистрируйте проект

Замените `C:\MyConfiguration` на **существующую папку вашей выгрузки**.
Для `C:\RentgenState` выберите новый путь: приведённый пример не предназначен
для повторного создания существующего реестра.

```powershell
New-Item -ItemType Directory -Path 'C:\RentgenState' -ErrorAction Stop
$rentgenCommand = (Resolve-Path .\.venv\Scripts\rentgen.exe -ErrorAction Stop).Path
& $rentgenCommand registry-init --registry 'C:\RentgenState\registry.sqlite3'
& $rentgenCommand project-register --registry 'C:\RentgenState\registry.sqlite3' --source-root 'C:\MyConfiguration' --state-root 'C:\RentgenState\project' --name 'Мой проект'
```

**Признак успеха:** регистрация возвращает JSON-ответ с `project_id`.
JSON — текстовый ответ программы с именованными полями. Скопируйте значение
`project_id`: это постоянный идентификатор проекта, а не его название.

Пример значения выглядит как `12345678-1234-5678-1234-567812345678`.
В следующих командах нужен **ваш** идентификатор из ответа.
Если папка состояния уже используется, выберите новую или следуйте инструкции
существующего проекта; реестр и состояние не перезаписываются этими командами.

## 3. Сохраните первый снимок

В первой строке вставьте полученный `project_id`, сохранив кавычки:

```powershell
$projectId = 'ВАШ-PROJECT-ID-ИЗ-ОТВЕТА'
& $rentgenCommand capture --registry 'C:\RentgenState\registry.sqlite3' --project $projectId --scanner .\bsl-scan.exe
```

**Признак успеха:** команда возвращает объект `snapshot` с `snapshot_id`.
Этот идентификатор относится к сохранённой версии файлов. Скопируйте его
в следующую строку и получите модули именно этой версии:

```powershell
$snapshotId = 'ВАШ-SNAPSHOT-ID-ИЗ-ОТВЕТА'
& $rentgenCommand source-list --registry 'C:\RentgenState\registry.sqlite3' --project $projectId --snapshot $snapshotId --kind module --limit 20
```

**Первый результат получен, если в ответе есть пути ваших BSL-модулей.**
Если список пуст, проверьте выбранную папку и наличие модулей в выгрузке.
Этот поиск показывает пути; содержимое модулей здесь не ищется.
Для следующей страницы и чтения файлов есть [инструкция CLI](docs/product/CORE-INSTALLATION.md#первый-проект).

Захват не обновляет рабочую информационную базу 1С. Новый снимок не
перезаписывает старый. Если захват был прерван, сохраните `operation_id`
из сообщения `recovery` и проверьте квитанцию по
[инструкции прерванного захвата](docs/product/CORE-INSTALLATION.md#прерванный-захват).

## 4. Откройте модуль в редакторе

Сначала подготовьте VSCodium, Cline и **отдельный профиль Рентгена** по
[инструкции интеграции](integrations/open-editor/README.md#подготовка).
Она задаёт закреплённые версии и хэши внешних файлов, проверяет установленный
Core, собирает Companion из выбранных исходников и создаёт новые настройки.
Текущие исходники Companion имеют версию 0.1.17; это разработка, а не
подмена опубликованного Companion 0.1.15.

Укажите генератору профиля:

- Python из установленного окружения: полный путь к `.venv\Scripts\python.exe`;
- реестр `C:\RentgenState\registry.sqlite3` и свой `project_id`;
- существующие `VSCodium.exe` и VSIX Cline;
- новую папку профиля и путь к `bsl-scan.exe`.

Запустите созданные `install.ps1`, затем `launch.ps1`. Рабочей папке профиля
нужно разрешить доверие в редакторе: расширение запускает локальный CLI.
Сам профиль уже ограничивает проект; разрешения на чтение и правки проверяет ядро.

В проводнике редактора найдите **«Рентген: модули»**, откройте поиск и введите
часть пути модуля. Нажмите на найденный модуль.

**Признак успеха:** открыт код сохранённого снимка, а в панели или вкладке
виден его короткий идентификатор. Вкладка предназначена для просмотра.
Дерево **«Рентген: черновики»** пока может быть пустым — это нормально.

Готовый [Companion 0.1.15](https://github.com/DmitrL-dev/1cai-public/releases/tag/companion-v0.1.15)
также опубликован отдельно. Его VSIX не заменяет профиль: расширению нужны
Python, реестр и ID проекта. Контрольные суммы доступны в выпуске;
SHA256 опубликованного VSIX —
`57a3f8f9b3193e2d6284df542010384ac13000695becbe1dfff887f6c5a872fa`.

## 5. Подготовьте первый черновик и проверки

После просмотра выберите небольшой понятный модуль. Для сценария с локальной
моделью заранее установите Ollama, загрузите выбранную модель и подготовьте
закреплённый BSL runtime по [инструкции профиля](integrations/open-editor/README.md#подготовка).
Команда **«Правка с локальной моделью»** у строки модуля создаёт отдельный
черновик, запрашивает модель и сохраняет результат с диагностикой BSL.
Произвольное качество задач 1С этим сценарием не подтверждено.

В **«Рентген: черновики»** откройте сравнение и историю.
Проверьте, что новая версия содержит именно ожидаемое изменение.
Журнал правки сохраняет код и текст задания; учитывайте это при передаче
диагностических материалов другим людям.

Для сохранённой версии доступны [BSL-проверка](docs/product/EDITOR-BSL-CHECK.md),
[проверка компилятором 1С](docs/product/EDITOR-PLATFORM-CHECK.md) и
[тесты YAxUnit](docs/product/EDITOR-TESTS.md). Для последних двух нужна
установленная платформа; тестовый профиль заранее регистрирует администратор.
Проверки выполняются отдельно от рабочей базы и относятся к выбранной ревизии.

Применение — следующий самостоятельный этап для поддержанного сценария.
Успешная диагностика или сохранение черновика не разрешают его автоматически.

## Если что-то не получилось

| Что вы видите | Что проверить |
| :--- | :--- |
| Python или `rentgen.exe` не найден | Версию Python, рабочую папку PowerShell и путь к отдельному окружению |
| Scanner не найден | Для готового комплекта это `bsl-scan.exe` в корне распакованной папки |
| В списке нет модулей | Правильную папку выгрузки, наличие `.bsl` / `.os` и фильтр поиска |
| `PROJECT_FORBIDDEN` | Текущую учётную запись Windows и [права проекта](docs/product/PROJECT-ACCESS.md) |
| В редакторе не появились деревья Рентгена | Запуск через `launch.ps1`, установленный Companion и доверие к рабочей папке |
| Правка или проверка прерваны | Команду чтения сохранённого результата; не повторяйте изменяющую операцию вслепую |

Для существующего старого проекта прочитайте [миграцию состояния](docs/product/STATE-MIGRATION.md)
и [обновление истории](docs/product/CORE-INSTALLATION.md#переход-существующего-проекта-на-schema4).
Полный цикл работы и объяснение ошибок — в [пользовательском руководстве](docs/USER_GUIDE.md).
