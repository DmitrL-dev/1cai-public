Основной репозиторий: `DmitrL-dev/1cai-public`. Ветки изменений — `codex/...`
или обычные тематические ветки участников. Собственный код распространяется
под MIT; зависимости сохраняют свои лицензии.

Правила работы с кодом, проверками и ветками собраны в [AGENTS.md](AGENTS.md).
Текущая [сверка планов и gates выпуска](docs/product/RELEASE-PLAN-20261015.md)
отделяет кандидат от опубликованной поставки.

## Проверки

Для полной существующей Windows-матрицы нужны Windows x64, Python 3.11,
Go 1.25.5 в PATH и Node 24.15.0. Отдельные переносимые проверки не заменяют
этот набор или native-приёмку. Linux и macOS квалифицируются отдельно
по [матрице платформ](docs/product/PLATFORM-SUPPORT.md).
Тесты используют временные искусственные проекты. Модель, клиент 1С и
пользовательская база для этого набора не требуются.

```powershell
py -3.11 -m venv .venv-test
.\.venv-test\Scripts\python.exe -m pip install -r requirements-test.txt
.\.venv-test\Scripts\python.exe -m pytest -q
node --test integrations/vscode-rentgen/test/*.test.cjs
go -C go test ./...
```

Сборка ядра описана в [CORE-INSTALLATION.md](docs/product/CORE-INSTALLATION.md).
Сборка расширения: `python integrations/vscode-rentgen/build.py --output NEW.vsix`.
VSIX содержит исходники и собственный packager; он не требует npm-зависимостей.

### Экспериментальные Linux GUI и Rust

Для ZIP reader используется закреплённый Rust 1.92.0 с `--locked`:
[сборка и проверки input core](rust/input-core/README.md#build-and-test).
Изменения HTTP API, поиска, сравнения и frontend проверяйте по
[инструкции GUI](docs/product/LOCAL-GUI.md#проверки). Настоящий HTTP→Rust импорт
требует собранный Linux binary в `RENTGEN_INPUT_CORE_TEST_BINARY`.
JavaScript model-тесты запускаются отдельно:

```sh
node --test tests/gui/*.test.mjs
```

Браузерные проверки GUI выполняются на Linux с обычной sandbox Chromium;
порядок установки test-only зависимостей и запуска приведён в
[приёмке GUI](docs/product/LOCAL-GUI.md#проверки).
Не заменяйте этот прогон браузером macOS или отключённой sandbox.
Локальный прогон фиксируйте как локальный; результат GitHub CI относится
к точному commit запуска.

Текущую матрицу и точные команды задают workflows:
[Windows/Core](.github/workflows/core-ci.yml),
[Linux portable](.github/workflows/portable-ci.yml),
[GUI browser](.github/workflows/gui-browser-ci.yml),
[synthetic diagnostic kernel](.github/workflows/diagnostic-ci.yml) и
[статический атлас](.github/workflows/anatomy-browser-ci.yml).
В Linux полный Python suite сравнивается с явно зафиксированной Windows-specific
baseline; успешный baseline gate не означает, что весь продукт принят на Linux.
Атлас имеет отдельную [инструкцию сборки и проверок](tools/anatomy-atlas/README.md)
и не входит в приёмку GUI.

## Изменения

Опишите задачу, изменение поведения и проверки. Для нового публичного контракта
обновите документацию и добавьте тест реального результата или отказа. Не
включайте выгрузки заказчиков, локальные профили, API-ключи и журналы с кодом.
Проверяйте diff перед коммитом. Отчёты о дефектах должны содержать минимальный
искусственный пример и версии компонентов.

## Переносимость и документация

Сохраняйте поведение Windows при выделении адаптеров. Недоступная операция
должна явно отказать до побочных эффектов; не заменяйте системную гарантию
просто похожим вызовом на другой ОС. Проверяйте CLI/MCP в настоящем процессе,
а не только импорт и monkeypatch-тесты. Права не выводятся из аргументов модели.

Обновляйте README, пользовательские инструкции, матрицу платформ и roadmap
согласованно. Отделяйте выпущенное от проверяемого и запланированного.
Не переносите исторические test counts на новый commit. Улучшение скорости
подтверждайте замером на одинаковых входах; Rust сам по себе не является таким замером.

## Релизы

Core и companion версионируются отдельно. Принятый артефакт одной версии не
перезаписывается: изменение доставляемых байтов требует новой версии и проверки.
Теги `companion-v*` запускают сборку, проверку фиксированного SHA256 и создание
черновика prerelease. Публикация после проверки активов — отдельный шаг.
Порядок и команды: [scripts/release/README.md](scripts/release/README.md).

При переносе исходников из другого дерева копируйте только проверенные продуктовые
файлы. Не сливайте историю частных рабочих задач в публичный репозиторий.
