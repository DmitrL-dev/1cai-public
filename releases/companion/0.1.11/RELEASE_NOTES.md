# Рентген Companion 0.1.11 — профиль для core dev11

Предварительный выпуск расширения VSCodium/VS Code для установленного
`rentgen-core 0.1.0.dev11`. Опубликованные Companion 0.1.10 и core dev10,
их теги и файлы остаются прежними.

## Что изменилось

- Профиль редактора принимает **точную** версию `0.1.0.dev11` установленного
  ядра. Поддержка ранее принятых dev4–dev10 сохранена; неизвестный dev12
  отклоняется. Расширение не подменяет выбранный Python автоматически.
- Просмотр снимков, сохранённых черновиков и контекстных команд, BSL-анализ,
  тестовый прогон, проверка версии в установленной 1С и управляемый ремонт
  применяют к dev11 те же проверенные границы, что к dev10. Повторное чтение
  сохранённой квитанции не запускает анализ, тесты или применение заново.
- Подготовка профиля проверяет Windows, Python 3.11, установленный core dev11
  и MCP 1.30.0. CLI ремонта сверяет core и MCP с профилем, а также точный путь
  интерпретатора; отдельной проверки версии Python он не выполняет. Установщик
  BSL runtime проверяет Windows, Python и core, но не MCP. Профиль по-прежнему
  связывает Python, registry и project ID.

## Установка и границы

Установите проверенный core dev11, затем создайте **новый** профиль по
[инструкции](https://github.com/DmitrL-dev/1cai-public/blob/main/integrations/open-editor/README.md)
и установите VSIX. Один VSIX без профиля не подключает проект. Существующий
профиль сохраняет свой путь Python и версию ядра; переключение на dev11 требует
явного выбора пользователя.

Для опубликованных VSIX 0.1.10 и core dev10 ранее выполнена ограниченная
нативная проверка пути «редактор → установленное ядро → 1С» на искусственном
модуле. Новый VSIX 0.1.11 отдельно на платформе 1С пока не принят. Расширение
не развёртывает HTTP-службу и не управляет сертификатами. Типовые конфигурации,
живая рабочая ИБ и production deployment требуют отдельной приёмки владельца.

[Большая цветная схема Рентгена](https://github.com/DmitrL-dev/1cai-public/blob/main/docs/assets/how-rentgen-works.svg)
показывает этапы работы без технических внутренних обозначений.
