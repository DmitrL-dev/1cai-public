# Рентген Companion 0.1.13 — совместимость с Core dev13

Предварительный выпуск расширения VSCodium/VS Code для установленного
`rentgen-core 0.1.0.dev13`.

## Что изменилось

- Профиль и команды редактора принимают точную версию Core dev13.
  Поддержка dev4–dev12 сохранена с прежними ограничениями команд:
  локальная правка требует dev7 или новее, BSL/платформенные проверки
  и тестовые профили — dev8 или новее. Неизвестные версии отклоняются.
- Генератор профиля и проверочные генераторы принимают установленный dev13.
  Установщик BSL runtime также принимает dev13 и использует исправленную
  проверку каталогов из этого ядра.
- Команды чтения проекта и черновиков, BSL-анализа, тестирования, платформенной
  проверки и управляемой правки сохраняют проверки Python, registry,
  project ID, разрешений и привязки результата к выбранным байтам.
- Существующий профиль не переключается автоматически. Выбор нового Python
  выполняется явно; прежние релизы и профили не перезаписываются.

Исправления чтения метаданных каталогов и сравнения прав Windows находятся
в Core dev13.
Подробные причины, установленная проверка и ограничения приведены в
[его заметках](https://github.com/DmitrL-dev/1cai-public/blob/main/releases/core/0.1.0.dev13/RELEASE_NOTES.md).

## Проверка пакета

VSIX `rentgen-companion-0.1.13.vsix`: **209 308 байт**, SHA-256
`cefb0b365951ad3dd072794c414211bce0425177d75b101bb62e99f164f98d03`.
Локальные Python-контракты проверили повторную сборку пакета и привязку
подготовленного профиля к его точным байтам. Прошли 65 Node-контрактов;
профильные и релизные Python-проверки входят в локальный прогон из 77 тестов
совместимости, поставки и live apply/recovery.

В каждом исходном [push CI](https://github.com/DmitrL-dev/1cai-public/actions/runs/36295543652)
и [PR CI](https://github.com/DmitrL-dev/1cai-public/actions/runs/36295545877)
прошли 2439 Python-тестов без failures/errors/skipped, 65 Node-контрактов, Go,
двойная сборка и установленные CLI/MCP, snapshot comparison и observer.
Все 429 локально квалифицированных Python-случаев найдены в каждом JUnit.
В каждом — 24 успешных шага; предварительные 48 ACL/runtime случаев входят
также в итоговые 2439, не прибавляются к ним как уникальные проверки.
Фактический PR checkout — `ab110acb4cef32a1baf00e9038800a9ae4b82438`; его Git tree
`71bfd35fa85e0a0380717877feed8f3f1ccd8f51` совпал с деревом исходного кандидата, родители проверены.
GitHub digest обоих JUnit-артефактов и обоих архивов поставки сверены после скачивания.

Релизный workflow отдельно запускает Node-контракты, собирает VSIX из
закоммиченных входов, проверяет хэш и размер по манифесту, затем проверяет
скачанный артефакт перед созданием GitHub Release. `release.json` связывает
пакет с конкретным коммитом релизных входов. Публикация выполняется как prerelease.

## Установка и границы

Установите проверенный Core dev13 и этот VSIX, затем создайте отдельный
профиль по [инструкции](https://github.com/DmitrL-dev/1cai-public/blob/main/integrations/open-editor/README.md).
Запись версии ядра в профиле должна совпадать с выбранным установленным
Python. Архивы и контрольные суммы Companion 0.1.12 остаются доступными.

Этот VSIX проверен в отдельном extension host VS Code 1.139.1 с установленным dev13
и 1С 8.3.27.2342/YAxUnit 25.12. Редактор выбрал сохранённую ревизию 1 при
текущей ревизии 2: baseline дал один ожидаемый failure, candidate — один passed.
После отключения профиля новый процесс редактора прочитал тот же отчёт без
нового запуска. Исходники и head сохранились, модель не вызывалась.
Состав и SHA256 всех файлов отдельной копии редактора совпали в снимках до первого
и после второго процесса. Временный harness использовал ожидаемую версию
Companion 0.1.13 и отключал обновления редактора и расширений в отдельном профиле;
продуктовый VSIX не менялся. Прямой CLI отклонил новый запуск отключённого профиля
с TEST_PROFILE_DISABLED, а повтор завершённой операции сохранил файлы результата.
Предыдущие функциональные проверки прошли, но установка VS Code между снимками
сменилась с 1.138.0 на 1.139.1; этот опыт не принят как доказательство неизменного
runtime. Поэтому выполнен описанный выше повтор на отдельной фиксированной копии.
[Квитанция](https://github.com/DmitrL-dev/1cai-public/blob/main/docs/product/evidence/tests-editor-dev13-20260927.json).
Системные библиотеки и внешняя аттестация не входят в снимки установки.
Приёмка типовых конфигураций, рабочей ИБ, live apply из редактора, Windows SCM
и полная продуктовая готовность не заявляются.
Production deployment требует отдельного ревью и разрешения владельца.

[Большая цветная схема Рентгена](https://github.com/DmitrL-dev/1cai-public/blob/main/docs/assets/how-rentgen-works.svg)
объясняет последовательность работы.
