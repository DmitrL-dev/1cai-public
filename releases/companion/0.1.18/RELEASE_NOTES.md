# Рентген Companion 0.1.18

Предварительный выпуск расширения для принятого Windows-маршрута с
Core **0.1.0.dev17**. Общая готовность продукта не заявлена.

## Возможности этой пары

Деревья «Рентген: модули» и «Рентген: черновики» показывают сохранённые данные Core.
Можно открыть модуль и diff, прочитать историю, работать с существующей ревизией
черновика и получить квитанцию операции. Первый draft создаётся через CLI/MCP.

Новая пара уточняет workflow восстановления прерванной правки и просмотра
результата: обнаруженные посторонние изменения не перезаписываются автоматически.
Выбор локальной модели и размера контекста, введённый ранее в 0.1.17, сохранён.
Просмотр, сохранение версии и запуск проверки не заменяют отдельное применение.

## Установка

1. Установите Core dev17 и создайте снимок по его инструкции.
2. Сверьте `rentgen-companion-0.1.18.vsix` с `SHA256SUMS` и `release.json`.
3. Подготовьте отдельный профиль из полного checkout `companion-v0.1.18` по
   [инструкции адаптера](https://github.com/DmitrL-dev/1cai-public/blob/companion-v0.1.18/integrations/open-editor/README.md).
   Укажите Python этой установки Core, свои registry/project_id и scanner.
4. Установите точный VSIX командой редактора **Extensions: Install from VSIX…**
   именно в нужном доверенном профиле. Проверьте версию расширения.
5. Откройте деревья Рентгена. Для истории используйте команды просмотра черновика
   и сохранения следующей версии, а не повторное применение прежней операции.

Старый профиль сам не переключается на новый Python/Core. Без scanner доступны
существующие данные; новый capture требует поддержанного scanner. Права Windows
SID, доверие workspace и проверка версии остаются обязательными.

При прерывании сначала прочитайте квитанцию по operation_id. Сохраните
идентификаторы операции и ревизии; не запускайте repair/apply вслепую.

## Что проверено и что остаётся открытым

Принятый VSIX: **274730 байт**, SHA256
`7e3c6ade123390ad608fd3173061c4f040d46fd446eabaef6a29d9bfcf0dcd8e`.
Локальная сборка совпадает с принятыми CI bytes. Windows CI выполняет Node-контракты
расширения и Python/Core сценарии. Tag workflow повторно собирает пакет и
проверяет его точное совпадение перед созданием draft release.

Для 0.1.18 не заявлена новая установка/активация в настоящем редакторе,
native 1C business acceptance, реальное задание модели или cold OwnerIPC.
Историческая приёмка прежних версий остаётся привязана к прежним пакетам.
Экспериментальный Linux Rust import Core не означает Linux/macOS поддержку
Companion или live apply.

Публичные assets: VSIX, `SHA256SUMS`, `release.json`. Последний связывает bytes с
точным коммитом release records и тегом `companion-v0.1.18`. Notes служат телом
GitHub Release. Встроенный README сохранён с исходной формулировкой development
candidate, чтобы не подменять уже проверенную сборку.
