# Рентген Companion 0.1.10 — профиль для core dev10

Это отдельный предварительный выпуск расширения VSCodium для ядра
`rentgen-core 0.1.0.dev10`. Он сохраняет поддержку ранее принятых профилей;
опубликованные Companion 0.1.9 и core dev9 не меняются. Основное изменение
этого VSIX — явное разрешение новой версии установленного ядра в редакторе и
адаптерах профиля. Сам HTTPS-приёмник находится в core dev10 и не запускается
расширением.

## Что изменилось

- Проверка профиля редактора принимает точную версию `0.1.0.dev10`. Профиль
  по-прежнему связывает выбранные Python, registry, project ID и установленный
  core; расширение не ищет автоматически другой Python и не заменяет профиль.
- Просмотр снимков и история черновиков поддерживают core dev4–dev10. Локальная
  правка и управляемый ремонт доступны с dev7; BSL-анализ, запуск тестового
  профиля и проверка версии в установленной 1С — с dev8. Dev9 остаётся
  поддержанным для этих сценариев.
- Контекстные команды, проверка сохранённого результата и чтение квитанций
  разрешены для dev10 по тем же контрактам, что и для dev9. Повторный просмотр
  результата не запускает анализ, тесты или применение ещё раз.
- Адаптер подготовки профиля VSCodium/Cline, установщик BSL runtime и CLI
  управляемой правки принимают dev10 при точной проверке MCP `1.30.0` и
  установленного пути Python 3.11. Неподдержанный следующий номер dev11
  по-прежнему отклоняется.

## Проверка пакета

VSIX собирается локальным сборщиком без npm-зависимостей. Для принятого файла
`rentgen-companion-0.1.10.vsix` зафиксированы размер **208263 байта** и
SHA256 **`b136bc63c63130d61709724f7e52904eb549120016372caee7df330f93193f25`**.
Релизный workflow заново прогоняет Node-контракты, собирает VSIX из исходников,
сравнивает размер и хэш с закоммиченным манифестом, затем перепроверяет
скачанный артефакт перед созданием GitHub Release. Локально также выполнены
Python-тесты профиля редактора для dev10.

Product CI точного исходного коммита
[`ef0501b`](https://github.com/DmitrL-dev/1cai-public/commit/ef0501bea47a3e955a466b9f8908922d59ba0855)
завершился успешно в [push-прогоне](https://github.com/DmitrL-dev/1cai-public/actions/runs/35827291776)
и [PR-прогоне](https://github.com/DmitrL-dev/1cai-public/actions/runs/35827295021):
58/58 Node-контрактов, 2327 Python-тестов без ошибок и пропусков, Go scanner,
воспроизводимая сборка core и офлайн-проверки установленного CLI/MCP.
VSIX из push-артефакта побайтно совпал с зафиксированным выше SHA256.

## Совместимость и установка

Рекомендуемая пара после публикации обоих выпусков: core `0.1.0.dev10` и
Companion `0.1.10`, Windows x64 / CPython 3.11. Сначала установите core из
проверенного офлайн-комплекта, затем создайте **новый** профиль редактора по
[инструкции](https://github.com/DmitrL-dev/1cai-public/blob/main/integrations/open-editor/README.md)
и установите VSIX. Существующий профиль не перезаписывается: в нём
зафиксированы путь Python, версия core, registry и проект. Один VSIX без
профиля не подключит проект. Хэши редактора и Cline проверяются отдельно.

## Границы предварительного выпуска

На момент публикации dev10 были подтверждены контракты расширения,
генератора профиля и воспроизводимая сборка VSIX. Отдельный ограниченный
editor-to-platform прогон опубликованного VSIX выполнен позднее и описан
в обновлении приёмки выше. Искусственный сценарий не является приёмкой
произвольной конфигурации.
Расширение не развёртывает HTTP-службу, не управляет TLS-сертификатами и не
обрабатывает входящие уведомления. Применение правки остаётся явной командой
пользователя с ограничениями соответствующего core-выпуска.
