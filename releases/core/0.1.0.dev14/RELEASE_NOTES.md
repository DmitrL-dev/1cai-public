# Рентген Core 0.1.0.dev14 — ранний отказ проверки при отключённых assertions

Предварительный выпуск для Windows x64 и CPython 3.11. Проверочный скрипт
миграции метаданных теперь отказывается от запуска с `-O` или `-OO` до импорта
зависимостей. Рабочие файлы ядра совпадают с опубликованным dev13.

## Что изменилось

`scripts/verification/verify_metadata_migration.py` использует assertions для
проверки результата нативного испытания. Оптимизированный Python отключает их.
Раньше явная защита выполнялась после импортов; теперь такая попытка сразу
заканчивается `RuntimeError` с сообщением:

> Verification requires assertions; do not use Python -O

Обычный запуск сохраняет прежнюю последовательность операций. Нижняя проверка
также сохранена. AST обычного пути сверен с предыдущим main; проверки UUID,
данных, отката и десятисекундный лимит subprocess не менялись. Это изменение
включено в sdist отдельной версией: архив dev13 не перезаписывается.

Два теста проверяют ранний отказ при `-O` и `-OO` через контролируемый запрет
импортов. До изменения они падали, после — прошли вместе с семью соседними
сценариями. Это доказательство порядка исполнения. Причина исторического
таймаута [issue #25](https://github.com/DmitrL-dev/1cai-public/issues/25) не
выводится из этих тестов; устранение всех нестабильных CI не заявляется.

## Совместимость и установка

1. Скачайте ZIP из этого релиза и сверьте SHA-256 по `SHA256SUMS` и
   `manifest.json`.
2. Установите его в отдельное окружение по
   [инструкции Core](https://github.com/DmitrL-dev/1cai-public/blob/main/docs/product/CORE-INSTALLATION.md).
3. Для нового профиля редактора используйте Companion **0.1.14**.
   Генератор профиля принимает dev14 и записывает версию фактически
   установленного ядра. Совпадение профиля и установки проверяется.
4. Проверочный скрипт запускайте обычным Python с assertions.

Существующие профили автоматически не переключаются. Явная поддержка прежних
версий и отказ для неизвестной версии сохранены. Обновлены текущие fixtures,
пути сборки CI и версии четырёх delivery-verifier; зависимости не обновлялись.

## Проверки исходного кандидата

В [push CI](https://github.com/DmitrL-dev/1cai-public/actions/runs/36306417536)
и [PR CI](https://github.com/DmitrL-dev/1cai-public/actions/runs/36306421451)
каждый полный JUnit содержит **2443 теста**, без failures/errors/skipped.
В каждом прошли **67 Node-тестов**, Go, все **24 шага**, двойная сборка,
установленные CLI/MCP, snapshot comparison и observer. Все **440** ранее
принятых и новых локальных случаев найдены в каждом JUnit. Предварительные
ACL/runtime проверки входят в итоговый набор, не считаются второй раз.
Сверены GitHub digest скачанных архивов и реальные checkout из logs.
PR checkout `57d98daf5a7c050722d1c7d7fcfcb9290d05711b` имеет проверенных родителей и то же дерево
`23c6959b8f83eab760106f118ca70a6d4267c768`, что исходный commit. Квитанция приёмки исходного CI
публикуется в `docs/product/evidence/release-dev14-ci-20260927.json`.

Локальная проверка совместимости сначала получила ожидаемые отказы: один из
двух Python-сценариев уже проходил, второй и оба Node-сценария отвергали новую
версию. После изменения списков прошли 34 Python- и 67 Node-тестов, включая
старые версии, несовпадение профиля/установки и неизвестную версию.

## Воспроизводимость и состав

Две локальные сборки, включая повторную сборку из sdist, совпали побайтно.
Повторная упаковка дала тот же ZIP. Все 103 файла Core/Graph/Diagnostics
совпали с Git archive, wheel, установленной копией и рабочими файлами
опубликованного dev13. Сканер и все 30 wheels зависимостей также совпали.

В wheel изменились METADATA и RECORD. В sdist изменились только PKG-INFO,
`packaging/core/README.md`, `pyproject.toml`, ранняя проверка в
`verify_metadata_migration.py` и ожидаемая версия в
`verify_test_profile_delivery.py`. Новых или удалённых записей в этих
архивах нет. Хеши и размеры остальных записей проверены.

Принят именно ZIP исходного push CI. Он отдельно установлен с внешним
SHA-256, `--no-index` и `--require-hashes`: проверены 40 файлов, 30 wheels,
32 MCP-инструмента. Wheel, sdist, scanner и зависимости совпали с локальным
комплектом; различия ZIP ограничены provenance и производным SHA256SUMS.
Все 103 рабочих файла отдельной установки из CI совпали с локальной установкой,
на которой выполнен новый нативный опыт. Локальный ZIP не подменяет принятый
CI ZIP, а дальнейшие документационные коммиты не меняют выбранный архив.

Реальный probe адаптера редактора принял установленный dev14. После чтения
реестр проекта сохранил прежние байты. Это отдельная проверка ветки
совместимости с настоящим пакетом, без подмены версии в ответе.

## Нативная проверка новой пары компонентов

Companion **0.1.14** с установленным Core **dev14** выполнил свежий сценарий
в отдельном профиле VS Code **1.139.1**, на 1С **8.3.27.2342** и YAxUnit **25.12**.
При актуальной ревизии 2 выбрана сохранённая ревизия 1. Baseline дал один
ожидаемый failure: ошибка записи не передавалась вызывающему коду. Candidate
прошёл тот же тест — один passed. Все **23 нативных шага** завершились с кодом 0.

Второй процесс редактора после отключения профиля прочитал тот же результат
без нового запуска. Прямой CLI повторно прочитал завершённую операцию, а новая
операция получила `TEST_PROFILE_DISABLED`. Все **909 файлов** завершённого
запуска сохранились побайтно; сохранены шесть исходных файлов, head и выбранный
proposal content ID. Модель не вызывалась.

В снимках до и после совпали все **2651 файл** отдельной закреплённой копии
редактора. Автообновление редактора и расширений отключено только в тестовых
user-data. Системные библиотеки и изменения между снимками этим не аттестованы.
Использован локальный wheel; его байты и все 103 файла установленного runtime
проверены на равенство принятой CI-поставке.
[Квитанция](https://github.com/DmitrL-dev/1cai-public/blob/main/docs/product/evidence/tests-editor-dev14-20260927.json),
SHA-256 `38a706e0a2cc38c99a615df671a708eb48b3bb9c5ec66d051adfd8d418ca8efa`.
Это испытание test/recovery на собственном синтетическом проекте; editor live
apply, типовые конфигурации и полная платформенная приёмка не заявляются.

Отдельно в репозитории опубликован
[свежий опыт EDT → Core dev13 → 1С → данные → Undo](https://github.com/DmitrL-dev/1cai-public/blob/3d36b5ac83ce36e3418378a104d7ba52ede0f9d1/docs/product/EDT-LIVE-NATIVE-DEV13-20260927.md).
Он выполнен именно dev13: десять MCP-запросов с тремя сохранёнными ранними
ошибками metadata, preview/rename, 36 шагов платформы, три записи, контроль
UUID и восстановление пяти файлов. Этот опыт не переименован в испытание dev14.

## Границы проверки

MIT/self-hosted компонент остаётся prerelease. Типовые конфигурации, полная
матрица метаданных и расширений, обновления поставщика, live SCM, live producer
бизнес-метрик и защищённый модельный маршрут не приняты. Spectorn в адаптер
не интегрирован. Работа выполнена основным агентом без субагентов; новое
независимое peer review не заявляется. Production deployment не выполнялся.
