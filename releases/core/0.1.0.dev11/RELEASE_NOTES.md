# Рентген Core 0.1.0.dev11 — проверяемый архив нативных запусков

Предварительный выпуск для Windows x64 и CPython 3.11. Он фиксирует текущее
состояние ядра отдельной версией после core dev10. Опубликованный комплект dev10,
его тег и контрольные суммы не меняются.

## Что изменилось в ядре

Нативный архив сохраняет полные идентификаторы файлов Windows при формировании
запечатанного inventory. Значения в каноническом диапазоне JSON остаются числами,
как в ранее выпущенных квитанциях. Более широкие 64-битные идентификаторы тома и
128-битные идентификаторы файла записываются строками фиксированной ширины в
шестнадцатеричном виде. Перед записью проверяются тип и диапазон обоих значений.
Это устраняет ошибку архивации при больших реальных Windows file ID, сохраняя
читаемость старых квитанций. Повторная архивация сверяет привязку к тем же
файлам; подмена даже старшего бита идентификатора отклоняется.

## Вошедший путь работы и имеющееся доказательство

В комплект входят локальные CLI/MCP для снимков проекта, BSL-анализа, проверки
предложений и управляемых операций с исходным Designer XML. Прямая BSL-правка
имеющегося модуля и `undo` проверяют head, снимок и полный inventory, ведут
запечатанный журнал и не перезаписывают чужие изменения. Операция переименования
атрибута каталога применяет только сохранённый preview к разрешённому base-слою;
для неё действует тот же проектный lock. После прерывания запись остаётся в
`OUTCOME_UNKNOWN` до явного восстановления, а неожиданный recovery stage
блокируется для разбора владельцем.

После dev10 опубликованы отдельные ограниченные проверки **установленного
dev10**: нативный apply/undo одного BSL-модуля в новой файловой базе 1С
8.3.27.2342; импорт и обратная выгрузка изменённого Designer XML; один
EDT preview с последующей нативной проверкой; запуск Source Observer console
из установленного комплекта. Квитанции и ограничения находятся в
[документации проекта](https://github.com/DmitrL-dev/1cai-public/tree/main/docs/product/evidence).
Они показывают, откуда взят текущий код, но не являются приёмкой новых байтов
dev11 на живой или типовой конфигурации.

Сверьте SHA256 скачанного ZIP с `SHA256SUMS` и следуйте

После установки создайте отдельный профиль Companion 0.1.11 с явным путём к
этому Python. Существующий профиль редактора не перезаписывается.

## Границы предварительного выпуска

Для этих **новых байтов dev11** пока подтверждены контракты, воспроизводимая
сборка и офлайн-установка, но не проведена отдельная нативная приёмка в 1С.
Предыдущие нативные сценарии были на синтетических данных и dev10. Типовые
`.cf/.cfe`, расширения, формы/СКД, рабочая информационная база, внешний
конкурентный writer, публичный HTTPS/DNS и служба Windows не приняты. Запись в
дерево исходников не равна обновлению ИБ. Production deployment требует
отдельного review и разрешения владельца.

Крупная [цветная схема работы Рентгена](https://github.com/DmitrL-dev/1cai-public/blob/main/docs/assets/how-rentgen-works.svg)
показывает путь от выгрузки 1С до решения о правке.
