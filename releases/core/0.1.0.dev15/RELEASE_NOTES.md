# Рентген Core 0.1.0.dev15 — установка выбранной версии по поставляемой инструкции

Предварительный выпуск для Windows x64 и CPython 3.11. Исправлены инструкции,
которые входят в исходный пакет: команды Core и MCP выбирают wheel той версии,
которая записана в `pyproject.toml` выбранных исходников.

## Что исправлено и зачем выпущена новая версия

В поставляемой инструкции dev14 оставалось имя wheel dev13. После сборки
выбранного пакета команда могла искать отсутствующий старый файл. Теперь оба
блока установки самостоятельно читают `project.version` через `tomllib` и
вызывают `Resolve-Path -LiteralPath -ErrorAction Stop` для точного имени wheel.
Если файла выбранной версии нет, установка Core не начинается. Другой wheel
из той же папки не подставляется; путь с пробелами передаётся pip одним аргументом.

Команда MCP использует `requirements/locks/mcp-py311-windows.txt`: закреплённые
версии и SHA-256 зависимостей этого сценария, также используемые офлайн-комплектом.
Полный профиль остальных частей продукта сохранён отдельно. Сам список
зависимостей и его хеши этим выпуском не обновлялись.

В инструкции офлайн-комплекта убран номер старой версии из рабочей выходной
папки. Версию и provenance определяет выбранный commit, а для повторной сборки
нужна новая выходная папка. Исторические ссылки на предыдущие релизы сохранены
с их исходными версиями.

Два исправленных документа входят в sdist, поэтому изменение доставляется
новым пакетом. Опубликованные dev14, его tag, ZIP и notes не перезаписываются.

## Как установить

1. Скачайте `rentgen-core-0.1.0.dev15-windows-py311.zip` из этого релиза и
   сверьте SHA-256 с `SHA256SUMS` и `manifest.json`.
2. Для готового комплекта выполните
   [инструкцию офлайн-установки](https://github.com/DmitrL-dev/1cai-public/blob/a792e638bd736a6ac075140e02d0dd972802cb34/docs/product/CORE-OFFLINE-KIT.md).
   Для самостоятельной сборки используйте
   [инструкцию выбранных исходников](https://github.com/DmitrL-dev/1cai-public/blob/a792e638bd736a6ac075140e02d0dd972802cb34/docs/product/CORE-INSTALLATION.md).
3. Для нового профиля редактора установите Companion **0.1.15**. Генератор
   профиля записывает версию фактически установленного Core после probe.
4. Существующий профиль сам на новую установку не переключается. Укажите
   runtime, registry и scanner своего отдельного окружения и проверьте профиль.

## CI и настоящая служба Windows

В [push CI 36346205723](https://github.com/DmitrL-dev/1cai-public/actions/runs/36346205723) и [PR CI 36346211891](https://github.com/DmitrL-dev/1cai-public/actions/runs/36346211891) каждый полный JUnit содержит **2488 тестов**, без failures/errors/skipped. В каждом прошли **69 Node-тестов**, Go, **24 этапа Windows**, двойная сборка, офлайн-установка, CLI/MCP, snapshot и observer. Все **521** ранее проверенных локально случаев найдены в обоих JUnit. Привилегированный DACL round trip реально выполнен, а не пропущен.

Фактические checkout обоих заданий каждого workflow сверены по логам. PR checkout `663dd23a65ed9ee115dfb314e3db4a5c1e827c18` имеет проверенных родителей и то же дерево `709190b2f1655555c404d1a748802c634ab9b572`, что source `a792e638bd736a6ac075140e02d0dd972802cb34`. GitHub digest, размеры и содержимое скачанных артефактов проверены. Это квалификация исходного кандидата; записи выпуска, final/main CI и публичные assets проходят следующие этапы.

В обоих отдельных native-scm заданиях настоящий SCM запустил по **пять процессов LocalService**. Подтверждены PID, SID, закреплённый прямой интерпретатор и ImagePath, первый отчёт, повтор без дубликата, STOP во время capture, восстановление прерванной операции после завершения scanner и отказ неверного проекта с SCM 1066 / service code 2.

После опыта служба отсутствует. В push/PR восстановлены соответственно **6066 / 6066** исходных записей DACL и владельцев; временные права LocalService на новых объектах удалены, привилегии проверяющего процесса возвращены в исходное состояние. Архивы проверены по точному набору файлов и хешам командных логов. Приёмка относится к Source Observer schema 1 на собственном синтетическом стенде. Нативный Git/BSL schema 3 и непрерывный Git-аудит этим не приняты.

## Нативный редактор, 1С и восстановление результата

Companion **0.1.15** с установленным Core **dev15** выполнил свежий сценарий
в отдельном профиле VS Code **1.139.1**, на 1С **8.3.27.2342** и YAxUnit **25.12**.
Исходный commit этого локального опыта —
`242ed98bf51bf4dd10dd925de093c3b83f7ce368`; его provenance сохраняется.

При актуальной ревизии 2 выбрана сохранённая ревизия 1. Baseline дал один
ожидаемый failure, candidate прошёл тот же тест. Все **23 нативных шага**
завершились с кодом 0; хеши JUnit и журналов сверены.

После отключения профиля отдельный новый процесс редактора прочитал тот же
результат без нового тестового запуска. CLI повторно прочитал завершённую
операцию; новая операция получила `TEST_PROFILE_DISABLED`. Все **909 файлов**
завершённого запуска, шесть исходных файлов, head и выбранная ревизия сохранились.
Модель не вызывалась.

В снимках до и после совпал **2651 файл** отдельной закреплённой копии редактора.
Системные библиотеки и изменения между снимками этим не аттестованы. Совпали
также 103 файла установленного Core с wheel опыта. Связь этих байтов с окончательной
CI-поставкой фиксируется отдельной проверкой payload.

[Квитанция нативного опыта](https://github.com/DmitrL-dev/1cai-public/blob/a792e638bd736a6ac075140e02d0dd972802cb34/docs/product/evidence/tests-editor-dev15-20260928.json),

Editor live apply, типовые конфигурации и полная платформенная приёмка остаются
отдельными требованиями.


Привязка завершена: отдельная установка принятого push CI имеет те же 103 рабочих файла, а CI wheel и VSIX совпали с нативно испытанными байтами. Нового нативного запуска после интеграции SCM main не заявляется.

## Границы проверки

MIT/self-hosted компонент остаётся prerelease. Типовые конфигурации, полная
матрица метаданных, форм и СКД, перенос доработок при обновлении поставщика,
измеренная эффективность на представительных задачах разработчика, живой
источник бизнес-метрик и защищённый модельный маршрут ещё не приняты.
Spectorn в маршрут адаптера не интегрирован. Свежий editor test/recovery на
синтетическом проекте не является editor live apply или приёмкой типовых баз.
Исторические опыты dev13/dev14 сохраняют свои версии и не переименованы в dev15.
Работу и ревью выполнил основной агент без субагентов; независимое peer review
не заявляется. Production deployment не выполнялся.
