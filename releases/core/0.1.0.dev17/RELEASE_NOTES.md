# Рентген Core 0.1.0.dev17

Предварительный выпуск компонентов. Основной готовый комплект предназначен для
Windows x64 / CPython 3.11. Отдельное дополнение для Linux x86_64 имеет
экспериментальный статус. Общая готовность продукта: `full_product_ready=false`.

## Изменения

- Восстановление прерванной правки не перезаписывает обнаруженные посторонние
  изменения. Квитанции, сравнение состояния и отдельное подтверждение применения
  сохраняют самостоятельный смысл.
- Контракты миграции состояния проверяют SQLite/WAL, резервную копию, повторное
  открытие и потерю ответа после публикации.
- MCP явно сообщает свойства изменяющих инструментов. Это описание инструмента,
  а не разрешение на выполнение: права проверяются отдельно.
- Команда `capabilities` показывает реализованные возможности текущего OS adapter.
  Неподдержанные маршруты закрыты до чтения исходников и запуска инструментов.
- На Linux появились явный локальный профиль владения, ограниченное чтение
  состояния/истории и существующие планировщики без применения к исходникам.
- Первый Rust-компонент принимает готовую ZIP-выгрузку на Linux. Команда
  `export-analyze` возвращает ограниченный список метаданных, поиск и хеши модулей.
  Она не создаёт снимок, граф вызовов или диагностику корректности конфигурации.

Go scanner сохранён. Новая модель и внешний LLM-сервис для этих сценариев не нужны.
Специализированная диагностика с проверяемыми гипотезами остаётся следующим этапом,
а не принятой возможностью данного выпуска.

## Установка Windows-комплекта

Скачайте `rentgen-core-0.1.0.dev17-windows-py311.zip`, `manifest.json` и
`SHA256SUMS`. Сверьте размер и SHA256 с manifest до распаковки:

```powershell
Get-FileHash -LiteralPath .\rentgen-core-0.1.0.dev17-windows-py311.zip -Algorithm SHA256
```

Распакуйте в новую папку. В каталоге `rentgen-core-0.1.0.dev17-windows-py311`:

```powershell
py -3.11 -m venv .venv
.\.venv\Scripts\python.exe -m pip install --no-index --only-binary=:all: --require-hashes --find-links . --find-links .\wheels -r .\mcp-requirements.lock
.\.venv\Scripts\python.exe -m pip check
.\.venv\Scripts\rentgen.exe --help
.\.venv\Scripts\rentgen-mcp.exe --help
```

Python, редактор, Java, модель и платформа 1С в комплект не входят. Для регистрации
проекта и первого снимка используйте
[регистрацию проекта и первый снимок, шаги 2–3](https://github.com/DmitrL-dev/1cai-public/blob/core-v0.1.0-dev17/GETTING_STARTED.md#2-зарегистрируйте-проект).
Шаг установки в том source-bound руководстве описывает прежний опубликованный
комплект; для dev17 используйте команды выше и начинайте с шага 2.
Companion этой пары: **0.1.18**. После смены Core пересоздайте профиль редактора с
правильными Python, registry и project_id.

При прерывании сохраните operation_id и прочитайте существующую квитанцию.
Не повторяйте применение вслепую. Recovery не является разрешением затереть
чужую правку. Предыдущие теги, пакеты и release records сохранены.

## Экспериментальное дополнение Linux

Три отдельно проверяемых файла:

- `rentgen-core-0.1.0.dev17-experimental-linux-x86_64.tar.gz`;
- `experimental-linux-manifest.json`;
- `experimental-linux-SHA256SUMS`.

Дополнение содержит тот же Python wheel, что принят в Windows-комплекте, и
отдельный Rust executable из Linux CI, лицензии и инструкцию. Это не полный
офлайн Linux-комплект: MCP-зависимости, Go scanner и редактор в него не входят.
Нужны GNU/Linux x86_64, glibc 2.34+, `libgcc_s.so.1`, kernel 5.9+,
memfd sealing и `/proc/self/fd`. Инструкция внутри архива описывает отдельное
окружение и явную локальную identity, не импорт чужого state.

ZIP должен быть заранее закончен и передан с ожидаемым SHA256. Полностью принятые
bytes удерживаются Rust до конца сессии. Хеш не доказывает происхождение данных,
полноту выгрузки или одновременный снимок живой базы. Исходный ZIP не распаковывается
в файловую систему. Лимиты: 16 MiB ZIP, 4096 записей, 4 MiB на файл, 32 MiB
распакованных данных, 128 MiB address space sidecar, 10 s import и 60 s session.
Права проверяются до чтения и повторно перед выдачей результата; отмена завершает
принадлежащий операции дочерний процесс.

Linux capture, retained snapshot access, запись черновиков, Observer, live apply,
native 1C и Companion этим дополнением не приняты. На Windows/macOS
`export-analyze` закрыт. Полный Linux suite остаётся диагностическим с известными
Windows-контрактами; зелёный целевой набор не означает полный зелёный продукт.
Ускорение относительно эквивалентной реализации не заявлено.

Подробные границы: [Rust input](https://github.com/DmitrL-dev/1cai-public/blob/core-v0.1.0-dev17/docs/product/RUST-INPUT-CORE.md)
и [local ownership / capabilities](https://github.com/DmitrL-dev/1cai-public/blob/core-v0.1.0-dev17/docs/product/PORTABLE-CORE.md).

## Привязка и область приёмки

Исходники принятого комплекта и цель Core tag:
`25743f7066a139e0f197746c70b713953966294d`.
Размеры, SHA256 wheel/sdist/комплекта и идентификаторы CI приведены в `manifest.json`
и [qualification.json из release records](https://github.com/DmitrL-dev/1cai-public/blob/companion-v0.1.18/releases/core/0.1.0.dev17/qualification.json);
Linux имеет собственный manifest и отдельную проверку состава.
Release records сохраняются более поздним коммитом. Его новые сборки не подменяют
уже принятые bytes исходного комплекта.

Windows CI проверяет Python/Node/Go контракты, новую офлайн установку, официальный
MCP SDK, сравнение снимков, Observer и отдельные native SCM/Git сценарии.
Linux CI проверяет Rust, CLI/IPC, отмену и parent-death, воспроизводимый wheel,
свежую установку и неизменность исходников/project head. Точные отчёты и численные
результаты сохранены в записи квалификации рядом с manifest.

Этот выпуск не получает автоматически историческую native 1C/редакторную приёмку
старых версий. Новые типовые базы, установленный редактор с реальным заданием модели,
cold OwnerIPC и end-to-end business workflow отдельно не квалифицированы.
Тексты README внутри неизменённых пакетов описывают development candidate на момент
сборки; актуальный статус публикации определяют эти release notes и manifest.
