# Рентген core 0.1.0.dev9 — проверяемые правки и наблюдение за проектом

`0.1.0.dev9` — новый prerelease локального ядра после `0.1.0.dev8`. Он
поставляет накопленные возможности работы с выгрузкой 1С, ограниченного
применения правок, восстановления и аудита Git. Это выпуск компонента для
Windows x64 и CPython 3.11; полной приёмкой продукта он не является.
Архив `core-v0.1.0-dev8` и его контрольные суммы остаются неизменными.

## Что нового после dev8

### Метаданные 1С и EDT

- Снимок умеет читать ограниченный набор EDT MDO/XML и сохранять identity,
  UUID и принадлежность объектов. CLI предоставляет привязанный к снимку
  inventory и доказательства для реквизитов каталога.
- Добавлены планирование и материализация проверяемых кандидатов
  трёхстороннего слияния. Неоднозначные изменения, смешанные корни EDT и
  Designer XML, столкновения путей и чужие XML-объявления отклоняются.
- Workspace writer создаёт отдельную принадлежащую копию, проверяет исходный
  inventory, сохраняет backup и квитанцию и поддерживает явные status, undo и
  recover. Native EDT adapter повторяет выбранный preview только в такой копии;
  опубликованная рабочая информационная база не меняется этим сценарием.
- Отдельный bounded live writer поддерживает один base Designer XML слой и
  операцию переименования реквизита каталога. Ещё один writer применяет
  запечатанное предложение к одному существующему BSL-файлу. Для обоих нужны
  зарегистрированный исходный каталог, точное совпадение ожидаемого состояния
  и явная команда на запись.

### Восстановление после прерывания

- Live writers ведут журнал с привязкой к проекту, операции и исходному
  inventory. Undo проверяет фактические байты перед заменой; Recover
  восстанавливает только проверенный backup. Посторонние изменения в
  исходниках блокируют автоматическое продолжение.
- Исправлено согласование прерванных квитанций Apply, Undo и Recover.
  Корректная временная запись состояния или результата сверяется с исходной
  операцией, result ID и inventory перед завершением. Повторный Recover
  проверяет собственный staging, восстанавливает перенесённые файлы из backup
  и может продолжить после очередного прерывания. Повреждённые или
  противоречивые записи требуют разбора владельцем.
- Журнал и исходное дерево должны находиться на одном файловом томе: иначе
  атомарная замена файла невозможна, и новая live-операция отклоняется до
  записи. Эта граница действует для обоих writers.

### Наблюдение, отчёты и нативные проверки

- Наблюдение за Git получило ограниченный scheduler, проверку непрерывности
  истории, привязку commit к снимку и сохранённые findings. Локальный outbox,
  owner reports, bounded SARIF и read-only BSL adapter сохраняют
  воспроизводимую цепочку доказательств.
- Добавлены контракт Windows ServiceMain/SCM, входная точка службы,
  ограниченная подготовка Git audit и ядро приёмника уведомлений с
  идемпотентностью и проверкой конфликтов. Это поставленные контракты и
  локальные сценарии; live SCM deployment и внешний HTTPS receiver ещё не
  принимались как продукционная служба.
- Для платформенных операций добавлены native archive с явными правами
  администратора и owned `ibcmd` fixture executor с квитанциями. Сценарии
  данных и переименования Article → SKU проверялись на принадлежащей
  синтетической базе 1С 8.3.27.2342; типовые конфигурации не квалифицированы.

### Удобство и поставка

- Новые команды CLI и локального MCP дают доступ к inventory, плану,
  workspace и live status/recovery, owner reports и архивированию native-run
  при соответствующих правах. Расширение Companion `0.1.9` добавляет профиль
  для core dev9; история черновиков и проверка результата остаются привязанными
  к сохранённой ревизии.
- README получил [крупную схему из шести шагов](https://github.com/DmitrL-dev/1cai-public/blob/main/docs/assets/how-rentgen-works.svg),
  которая показывает путь от выгрузки 1С до решения о применении правки.

## Как устанавливать и проверять

Скачайте ZIP, `manifest.json`, `SHA256SUMS` и эти заметки из
[GitHub Release](https://github.com/DmitrL-dev/1cai-public/releases).
Сверьте SHA256 ZIP с манифестом, распакуйте в новый каталог и следуйте
[инструкции первого запуска](https://github.com/DmitrL-dev/1cai-public/blob/main/GETTING_STARTED.md).
Комплект содержит ядро, исходники, scanner, закреплённые wheels MCP, лицензии
и контрольные суммы. Python 3.11, платформа 1С, EDT, модель и доверенный CFE
YAxUnit устанавливаются отдельно. Уже работающие окружения dev8 не меняйте
поверх: для dev9 создайте отдельное окружение и профиль редактора.

Поставленные файлы должны соответствовать принятому успешному CI для точного
коммита в манифесте. Тег `core-v0.1.0-dev9` указывает на этот коммит исходников;
манифест с хэшами фиксируется следующим коммитом после сборки и не меняет тег.
На локальном Windows-кандидате полный Python-набор завершился результатом
**2295 passed, 3 skipped** (три пропуска связаны с недоступным созданием
symlink); Node-контракты Companion — **56 passed**, тесты Go scanner — успешно.
Отдельные fault injection тесты проверили прерывания Apply, Undo и Recover
перед записью исходника, временного состояния и терминального результата.

## Границы готовности

Live writer покрывает только указанные Designer XML и BSL-сценарии. Не
заявлены произвольный round-trip `.cf/.cfe`, полная семантика расширений,
форм и СКД, применение в рабочую ИБ через EDT/1С, внешняя concurrent CAS,
типовые конфигурации, production SCM/HTTPS deployment и интеграция Spectorn.
Результат BSL-анализа и синтетические тесты не доказывают корректность
бизнес-логики. Подробная таблица — в
[границах готовности](https://github.com/DmitrL-dev/1cai-public/blob/main/docs/product/READINESS.md).
