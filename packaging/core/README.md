# Рентген: локальное ядро

Открытое ядро проекта, снимков исходных файлов и графа вызовов 1С. Лицензия MIT.
Версия 0.1.0.dev8 является сборкой для разработки, а не заявлением о полной
готовности Рентгена.

Пакет содержит rentgen_core, адаптер rentgen_graph и rentgen_diagnostics
с закреплёнными профилями BSL-LS. HTTP-приложение,
портал, частные конфигурации, модели и ключи не входят в эту поставку. Для
захвата конфигурации нужен Windows и отдельно собранный Go scanner. Граф отражает
ограниченный статический анализ; оценки качества пока недоступны. Временная
атомарность захвата меняющейся живой конфигурации не доказана.

Ядро создаёт проекты schema4 с общей историей черновиков. Сохраняются аудируемое
управление членством и явные обновления 2→3→4 с проверенными backup.
Поиск исходников по пути/типу/слою выполняется до разбиения на страницы.
MCP предоставляет21 команду, включая сохранение, историю, восстановление
и правку кандидатов до1 MiB через неизменяемые версии и точные замены.
Базовый metadata API использует
ограниченные retained read sessions и evidence metadata_scan_v2. Локальный
stdio MCP доступен через optional extra mcp с SDK 1.30.0; базовый wheel
остаётся без обязательных сторонних зависимостей. Команды proposal-create/diff/check и MCP проверяют предложенную
правку одного модуля настоящим BSL-LS при отдельно установленном runtime. Это
эфемерная диагностика. Явная команда proposal-test выполняет зарегистрированный профиль YAxUnit на двух копиях сохранённой конфигурации; см. docs/product/TEST-PROFILES.md. Применение ещё недоступно. Java/JAR не включены
в wheel и имеют собственные лицензии. Runbooks установки, доступа,
миграции и метаданных находятся в docs/product внутри sdist.

Стандартная точка входа: rentgen (также python -m rentgen_core).
В dev8 добавлена команда snapshot-diff: сравнение двух сохранённых снимков
одного проекта по слою, пути и исходным байтам. Она не вызывает модель,
не читает живую конфигурацию и не изменяет состояние проекта.
Полная служба наблюдения и метрики качества этим не реализуются.
Профиль редактора companion 0.1.4 пока требует принятого core dev7;
совместимость с dev8 проходит отдельную проверку.
Захват требует явного выбора проекта и пути к scanner. Исходные файлы возвращаются
как точные bytes с проверенными идентификаторами снимка и хэшами.

Сборка использует явно указанный hatchling backend. Старый корневой setup.py
не является setuptools-метаданными и не должен запускаться. Разработчик сначала
устанавливает зафиксированный профиль сборки в отдельное окружение, затем:

```text
python -m build --no-isolation
```

Wheel содержит выбранные Python-модули, JSON-профили runtime и лицензию. Source distribution
также содержит исходники Go scanner; сам исполняемый scanner собирается отдельно:

```text
cd go
go build -buildvcs=false -trimpath -o bsl-scan.exe ./cmd/bsl-scan
```

Работа платформы 1С, редактирование метаданных и форм, обновление конфигураций,
постоянный мониторинг и перевод существующих HTTP/MCP обработчиков проходят
отдельную продуктовую приёмку.
