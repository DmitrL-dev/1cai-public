# Archi Export Counts - 2026-06-19

## Why

The legacy `/api/v1/archi/export` endpoint returned `elements_count=0` and `relationships_count=0`
after export. That looked like an empty or broken architecture export even when the generated ArchiMate file
contained real model content.

## Implemented

- Fixed async exporter execution: async `ArchiExporter.export_to_archimate` is now awaited instead of being run as a synchronous executor callable.
- Kept compatibility for synchronous legacy exporters by running them in the executor path.
- Migrated `ExportRequest.output_filename` validation from Pydantic v1 `@validator` to v2 `@field_validator`.
- Replaced the autogenerated/TODO docstring in `src/api/dependencies.py` with an explicit optional GraphService dependency description.
- Added XML counting for generated `.archimate` files:
  - `<element>` count becomes `elements_count`;
  - `<relationship>` count becomes `relationships_count`;
  - namespace-qualified ArchiMate XML is supported.
- Added API regression test with a generated ArchiMate file.

## Buyer Impact

Architecture export responses no longer say "0/0" for non-empty exports.
The legacy ArchiMate bridge remains optional, but when used it reports honest proof counts.
