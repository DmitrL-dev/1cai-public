# План нативной SCM-проверки

Основание: [дизайн](../specs/2026-09-27-native-scm-ci-design.md).
Исполнитель один; действующее поручение включает CI, проверку и публикацию в Git.

1. Добавить узкие отрицательные тесты provenance/owned paths/ACL/deadline,
   раннего запрета `-O`, отказа до изменения службы при недостаточных правах.
2. Перенести проверенный нативный read-only helper; сделать bootstrap и worker
   переносимыми, сохранив локальный owner launcher без изменения его pins.
3. Проверить прямой runtime и fixture локально без привилегированных изменений.
   Проверить byte identity, PID, отрицательные тесты и source preservation.
4. Добавить отдельный `native-scm` job с загрузкой kit того же run, сверкой SHA
   и commit, ограничением времени и сохранением evidence даже при ошибке.
5. Ревью diff, узкие тесты, commit/push, подробный draft PR. Дождаться реальных
   CI, проверить все критерии/cleanup и артефакты. Ошибки исправлять по evidence.
6. После успешных gates: merge, отдельная квалификация нового main, подробный
   анонс и обновление readiness. Пока native receipt не принят — SCM pending.

## Результат первого CI и исправление

Оба workflow первого head завершились: основной job прошёл (2455 Python,
67 Node и Go), нативные сценарии SCM выполнились, служба удалена. Очистка ACL
завершилась ошибкой, поэтому приёмка отклонена. Подробнее — в разделе
«Исправление по первому реальному CI» [дизайна](../specs/2026-09-27-native-scm-ci-design.md).

Добавлены защита временных деревьев от унаследованных прав, точное сравнение
ACE/P/AR с отдельным учётом AI, проверка исходных владельцев и очистка новых
поддеревьев. Новые тесты сначала показали отказ, затем прошли. Чтение владельца
сверено с настоящим Get-Acl на Windows. Свежий прямой runtime подтвердил отказ
непривилегированного запуска без изменения SCM/ACL и исходников.

Следующий gate — два workflow исправленного head с фактическими артефактами
`native-scm`, затем merge и отдельный CI нового main. До этого SCM не принят.
Прежний локальный owner launcher оставлен побайтово, но его запуск отложен:
там обнаружен такой же дефект очистки, нужен отдельно проверенный новый стенд.

## Второй CI: отказ до запуска службы и следующее исправление

Оба workflow head `182bdbfc2b38` завершились ошибкой проверки временных ACL.
Основной job прошёл 2468 Python-контрактов; native job службу не создавал.
Фактические ACL, ошибки и исправление описаны в разделе «Исправление по
второму реальному CI» дизайна. Первый и второй неуспешные наборы evidence
сохранены отдельно и не заменяются результатом следующего запуска.

Следующий head применяет полные DACL отдельно к файлам и каталогам и
восстанавливает права до записи config. Новые отрицательные тесты показали
пять отказов до исправления. Узкая проверка: 30 passed, один нативный тест
пропущен из-за отсутствия SeRestorePrivilege у локального токена; на CI этот
тест обязан пройти. Полная локальная регрессия и свежая проверка отказа без
привилегий отражаются в публичной квитанции перед commit/push.

## Третий CI: чтение метаданных для безопасного восстановления ACL

Оба workflow `7cf7de025788` завершились на одном нативном Python-тесте:
2473 passed, один failure, без пропусков. Служба не создавалась. Причина и
обоснование исправления описаны в разделе «Третий CI» дизайна.

Добавлен ограниченный блок SeBackupPrivilege с возвратом исходного состояния
токена и отдельным событием проверки. Новые тесты до исправления дали шесть
отказов. Проверка настоящего hardlink сохранена; закрытые файлы проверяются
в CI с обеими привилегиями. Свежая копия runtime и фактический отказ без прав
проверяются перед публикацией, результаты фиксируются в публичной квитанции.
