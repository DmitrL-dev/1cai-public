# Нативная проверка службы на временной Windows-машине CI

## Цель и границы

Проверить установленный Core через настоящий Windows Service Control Manager
под `NT AUTHORITY\LocalService`. Используется отдельная свежая VM GitHub Actions,
зависящая от успешной сборки `windows` того же workflow. Это доказательство для
зафиксированных байтов пакета и среды CI; типовая 1С, рабочая машина владельца
и production не входят в результат. Работа и ревью выполняются без субагентов.

GitHub документирует административные права Windows runner, но тест обязан
измерить фактический токен, доступ CreateService и SeRestorePrivilege до изменений:
https://docs.github.com/en/actions/reference/runners/github-hosted-runners#administrative-privileges

## Устройство

- Bootstrap принимает архив, SHA256, commit checkout и новую папку под RUNNER_TEMP.
  Проверяет manifest и provenance, создаёт прямой CPython из установленного
  Python 3.11.9, устанавливает только wheel Core офлайн и сверяет файлы с wheel.
  Venv launcher не подходит: PID оболочки может отличаться от PID службы.
- Runtime, искусственный source/data fixture и evidence — соседние папки одного
  нового каталога. Уникальное имя службы начинается с `Rentgen.CI.`. Внешние
  пути, reparse points, hardlinks, повторно использованные каталоги отвергаются.
- Worker загружает Core из установленного runtime. Нативный помощник читает
  QueryServiceStatusEx/QueryServiceConfig, путь процесса и SID его токена.
- Перед выдачей прав сохраняются DACL. Пробное восстановление неизменённого
  fixture обязательно. Затем временные деревья защищаются от наследования:
  Administrators/System получают F, LocalService — RX runtime/source/config и M data.
  Сохранённая временная DACL проверяется по SID, маскам и флагам каждого ACE;
  унаследованные права Users и CREATOR OWNER не могут расширить доступ службы.
- Жизненный цикл ограничен временем; отдельный резерв выделен очистке.
  Ошибка, пропущенное окно capture, тайм-аут или неполная очистка означают отказ.

## Критерии приёмки

1. Реальные RUNNING/STOPPED, ImagePath, PID, LocalService SID и параметры службы.
2. Первый сохранённый отчёт; повторный запуск без нового снимка/операции.
3. STOP принят во время наблюдаемой фазы capture, текущий цикл завершён один раз.
4. Прерывание только проверенного процесса: удерживаемый handle, image/SID и
   повторная сверка PID SCM. Дочерний scanner должен завершиться до восстановления.
5. После запуска сохраняется тот же operation_id и ровно один новый отчёт.
6. Чужой project в config отвергается с ожидаемым SCM-кодом без публикации.
7. Все исходные файлы остаются неизменными на каждой стадии проверки.
8. Служба отсутствует после удаления. Для каждого первоначального объекта
   полностью совпадают ACE (включая порядок, SID, маски и флаги), контрольные
   флаги P/AR и владелец. Windows может добавить AI при восстановлении через
   icacls: изменение этого флага учитывается отдельно в квитанции; равенство
   полных строк дескриптора не заявляется, если AI изменился.
9. Новые объекты не сохраняют ACE LocalService (LS / S-1-5-19). Если восстановленный
   CREATOR OWNER дал такие права на созданные службой объекты, очистка выбирает
   только новые поддеревья без первоначальных объектов внутри, проверяет границы,
   назначает владельцем Administrators и сбрасывает ACL к восстановленному родителю.
   Затем повторно проверяются все DACL, владельцы и неизменность списка объектов.

Неизвестный результат CreateService не разрешает автоматически удалять службу.
При неизвестном живом процессе ACL сохраняются для диагностики, приёмка падает.
Артефакт содержит ограниченные JSON, события и логи ACL; корпус не публикуется.
Нельзя подменять реальные результаты SCM результатами unit-тестов.

## Выбор размещения

Отдельный job даёт собственный лимит времени и чистый компьютер. Основной job
уже расходует существенную часть 60 минут на Python. Download artifact закреплён
SHA action, получает только артефакт текущего run. Итоговая квалификация проверяет
оба job, а не прежнее предположение об одном job и 24 шагах.

Скрипты и тесты находятся вне входов wheel/sdist. Версии компонентов не меняются,
пока не возникает изменение продуктового кода. Публичные релизы не перезаписываются.

## Исправление по первому реальному CI

Оба запуска первого head `8f49390f63c8bb64080caa82ce3d30852791e96e`
([push](https://github.com/DmitrL-dev/1cai-public/actions/runs/36322819712),
[PR](https://github.com/DmitrL-dev/1cai-public/actions/runs/36322904352)) завершились
ошибкой очистки. Основной job прошёл, реальные сценарии службы выполнились,
служба удалена. Этот результат не является принятой SCM-проверкой.

Обнаружены три связанные причины: сравнение всей SDDL-строки принимало AI за
изменение ACE; наследуемые права Users разрешали новые файлы в runtime, несмотря
на добавленный RX; CREATOR OWNER оставлял права LocalService на новых файлах.
Исправление проверяется новым запуском CI. Старые квитанции сохранены.

Семантика сверена с документацией Microsoft:
[строка дескриптора](https://learn.microsoft.com/en-us/windows/win32/secauthz/security-descriptor-string-format),
[icacls](https://learn.microsoft.com/en-us/windows-server/administration/windows-commands/icacls),
[чтение владельца](https://learn.microsoft.com/en-us/windows/win32/api/aclapi/nf-aclapi-getnamedsecurityinfow).

## Исправление по второму реальному CI — 28 сентября 2026

Оба workflow head `182bdbfc2b3822f552de9afdc544888bdcba846c`
([push 36326514201](https://github.com/DmitrL-dev/1cai-public/actions/runs/36326514201),
[PR 36326516502](https://github.com/DmitrL-dev/1cai-public/actions/runs/36326516502))
прошли основной job: 2468 Python-контрактов без ошибок и пропусков.
`native-scm` остановился на проверке временных ACL **до создания службы**.

В обоих сохранённых `runtime-temporary.acl` из 6050 записей 5609 файлов имели
пустой защищённый DACL `D:PAI`; 441 каталог — повторный ACE администратора.
Последовательность `/grant:r` с OI/CI, затем удаления наследования не обеспечила
явные права обычных файлов. OI/CI применяются к каталогам — это описано в
[документации icacls](https://learn.microsoft.com/en-us/windows-server/administration/windows-commands/icacls).
Дополнительно `PermissionError` при перезаписи config прерывал восстановление ACL.
Архивы обоих workflow сохранены и сверены с SHA-256 и размером GitHub API.

Исправление:

- Для каждой исходной записи создаётся полный защищённый DACL. У файлов ACE
  без флагов наследования; у каталогов — OI/CI. Администраторы и SYSTEM имеют
  Full Control, LocalService — Read/Execute, внутри `service_data` — Modify.
- Подготовленный UTF-16 ACL-файл проверяется по путям и записывается через
  `/restore`. Последующее `/save` и проверка инвентаря, флагов, SID и масок
  обязательны. Запрошенная и прочитанная политики входят в evidence с SHA-256.
- Восстановление начинается только после подтверждения отсутствия службы и
  scanner. Проверка структуры до восстановления не читает содержимое файлов,
  доступ к которым мог быть закрыт неудачной настройкой ACL. Проверки reparse
  points, hardlinks и границ каталогов сохранены.
- Config восстанавливается после попыток вернуть ACL обоих деревьев. Ошибка
  записи config фиксируется и не блокирует безопасное восстановление прав.
  При неизвестной или оставшейся службе config и ACL не изменяются.
- Добавлены проверки построения файловых ACL, отказа для двух реальных форм
  ошибочных DACL, недоступного содержимого и порядка очистки. Отдельный тест
  на настоящем Windows `icacls /restore` проверяет файлы, каталоги, намеренно
  пустой DACL одного временного файла и возврат исходных прав.

Локальный токен не имеет SeRestorePrivilege: нативный тест `/restore` здесь
пропускается явно. Он обязан пройти без пропуска на Windows CI. Это не является
приёмкой SCM; для неё нужны успешные сценарии службы, очистка и проверенные
артефакты двух workflow нового head, затем отдельного CI после merge.

## Третий CI: метаданные при пустом DACL

Оба workflow `7cf7de0257884665e778b47a345da27e51076a7b`
([push 36329862790](https://github.com/DmitrL-dev/1cai-public/actions/runs/36329862790),
[PR 36329864986](https://github.com/DmitrL-dev/1cai-public/actions/runs/36329864986))
завершились одинаково: 2473 Python-теста прошли, один упал, пропусков нет.
`native-scm` не запускался. Ошибка возникла в новом нативном тесте после
установки намеренно пустого DACL: `lstat().st_nlink` не дал число ссылок,
и строгая защита hardlink остановила проверку структуры.

Локальный опыт на собственных временных файлах подтвердил `st_nlink == 0`
как для обычного файла, так и для настоящего hardlink. Запрос Win32 с нулевым
доступом также вернул отказ. Поэтому ноль нельзя трактовать как одну ссылку.
В CPython 3.11.9 запрос метаданных использует FILE_READ_ATTRIBUTES и
FILE_FLAG_BACKUP_SEMANTICS: [исходный код CPython](https://github.com/python/cpython/blob/v3.11.9/Modules/posixmodule.c).

Исправление ограничено проверочным стендом:

- До мутаций обязательны elevated SCM create access, SeRestorePrivilege и
  SeBackupPrivilege. Отсутствующую привилегию стенд не добавляет.
- Только на время проверки метаданных перед восстановлением ACL включается
  существующая SeBackupPrivilege. Содержимое файлов в этом блоке не читается.
- AdjustTokenPrivileges проверяется по BOOL и коду ошибки: TRUE вместе с
  ERROR_NOT_ALL_ASSIGNED означает отказ. В `finally` восстанавливается
  PreviousState; уже включённая привилегия не отключается при выходе.
  [Контракт Microsoft](https://learn.microsoft.com/en-us/windows/win32/api/securitybaseapi/nf-securitybaseapi-adjusttokenprivileges).
- До и после блока сравниваются все имена и состояния привилегий. Для каждого
  из двух деревьев событие `cleanup_metadata_verified` фиксирует их равенство.
  Проверки границ, reparse points и единственной ссылки сохраняются.
- Нативный CI-тест проверяет закрытый обычный файл и отказ для закрытого файла
  с двумя ссылками, затем возвращает исходный DACL. Он обязателен без пропуска
  в CI. Локально отсутствие backup/restore privilege отражается явно.
- Отдельные тесты проверяют восстановление при исключении, уже включённую
  привилегию, ERROR_NOT_ALL_ASSIGNED и реальное поведение текущего токена.

Локальные тесты не заменяют нативную приёмку. Все три неуспешных head и их
артефакты сохранены; merge допускается после квалификации нового head и main.

## Четвёртый CI: диагностика окончательного восстановления

Оба workflow `3cf801e79d708e148a1c04a0696bfce5b37b6ade`
([push 36333723336](https://github.com/DmitrL-dev/1cai-public/actions/runs/36333723336),
[PR 36333725412](https://github.com/DmitrL-dev/1cai-public/actions/runs/36333725412))
дали **2478 passed, один failure, без errors/skipped**. Нативный тест прошёл
проверки закрытого обычного файла, отказа для закрытого hardlink и возврата
состояния привилегий. Затем окончательное сравнение baseline/restored DACL
завершилось `Original DACL was not restored exactly`. Служба не создавалась.

Сообщение не содержит фактических различий, поэтому причина несовпадения пока
не установлена. Текущий шаг — сбор данных, без изменения правил восстановления
или ослабления равенства ACE/P/AR. В JUnit failure добавлены реальные SDDL:
исходные, запрошенные, прочитанные после применения, восстановленные до удаления
alias и прочитанные после его удаления. Пути ограничены относительными именами
собственного временного дерева. Ошибка диагностического чтения не мешает
попытке удалить созданный тестом alias благодаря отдельному `finally`.

36 тестов стенда теперь входят в ранний Python guard вместе с прежними
runtime/owned-attempt проверками: **84 случая**. При ошибке шаг сохраняет JUnit
и завершается до полного набора. При успехе выполняется прежний полный набор
**2479 тестов**, затем остальные проверки и `native-scm`. Число уникальных
случаев, обязательный привилегированный тест и критерии приёмки не меняются.

Это диагностическое изменение проверочного стенда. Новый head не объявляется
исправлением последнего DACL-несовпадения до получения и анализа фактических
значений Windows. Все четыре неуспешных head и их артефакты сохранены.

## Пятый CI: сохранение исходной модели наследования

Диагностический head `a9ad0d3f0cb32fad8b0df13fd898899bd63c55ac` дал
одинаковые данные в [push 36336960810](https://github.com/DmitrL-dev/1cai-public/actions/runs/36336960810)
и [PR 36336965390](https://github.com/DmitrL-dev/1cai-public/actions/runs/36336965390):
84 теста, 83 passed, один failure, без errors/skipped. Ранний шаг занял 4–5 секунд.
Во всех четырёх исходных объектах к трём явным ACE добавились три унаследованные
копии. Снимки до и после удаления hardlink совпали; alias не был причиной.

Локальное воспроизведение показало два связанных эффекта. Включение наследования
через SetNamedSecurityInfoW добавляет родительские ACE. Кроме того, чтение через
GetNamedSecurityInfoW / icacls может представлять legacy DACL в преобразованной
модели: изменить P и ID в представлении, не меняя хранящийся DACL. Поэтому пара
«icacls /save → /restore» не обеспечивает требуемый точный возврат этого baseline.

Исходные и восстановленные DACL теперь читаются GetFileSecurityW и сохраняются
в прежнем ограниченном UTF-16 формате с проверкой путей. Для возврата каждого
исходного объекта используется SetFileSecurityW с DACL_SECURITY_INFORMATION=4.
Порядок ACE, SID, masks, inheritance flags и P/AR сравниваются без ослабления;
AI учитывается отдельно, как и раньше. Владельцы проверяются независимо.

SetFileSecurityW помечен Microsoft как устаревший. В проверочном стенде он выбран
осознанно ради документированного отсутствия распространения ACL на дочерние
объекты. Современная замена, меняющая модель наследования, не подходит для
точного восстановления legacy baseline. Операция ограничена собственным
проверенным деревом; owner/group/SACL не записываются; память освобождается в
finally, размер и время ограничены. В рабочие wheel/sdist этот код не входит.

Источники: [GetFileSecurityW](https://learn.microsoft.com/en-us/windows/win32/api/securitybaseapi/nf-securitybaseapi-getfilesecurityw),
[SetFileSecurityW](https://learn.microsoft.com/en-us/windows/win32/api/securitybaseapi/nf-securitybaseapi-setfilesecurityw),
[автоматическое наследование](https://learn.microsoft.com/en-us/windows/win32/secauthz/automatic-propagation-of-inheritable-aces).

Для временной защищённой политики и очистки новых поддеревьев icacls сохраняется.
Новые события original_dacls_read/original_dacls_applied фиксируют API, mask=4,
число объектов и SHA-256 снимка. Отказ при оставшемся service/scanner, проверки
hardlink/reparse, возврат привилегий, исходных владельцев и содержимого сохранены.

Добавлены семь случаев: три отказа до Win32-вызовов и четыре настоящих возврата
DACL для control `D:`, `AI`, `P`, `PAI` на файле и двух каталогах. Ранний набор
теперь содержит 91 случай, полный CI — 2486 Python / 67 Node / Go. Локальный
ранний результат: 90 passed и один обязательный для CI privileged skip.
Пять предыдущих head и их доказательства сохранены. Нативная SCM-приёмка
остаётся незавершённой до нового полного CI и проверки фактических артефактов.
