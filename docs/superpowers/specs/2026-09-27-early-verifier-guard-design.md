# Ранний отказ metadata migration verifier под Python -O

## Задача

Issue #25 зафиксировал timeout 10 секунд при проверке запрета оптимизированного
Python. Текущий `verify_metadata_migration.py` получает запрет косвенно из
`verify_edt_metadata_fixture`, после импортов нативного стека. Управляемый опыт
27.09.2026 подтвердил именно порядок импортов; исторический timeout не воспроизведён.

## Решение

Сразу после docstring, перед первым импортом, проверить `if not __debug__` и
выбросить тот же `RuntimeError("Verification requires assertions; do not use Python -O")`.
Нижележащий запрет в EDT verifier сохранить. Обычные импорты и функции не менять.
Тайм-аут теста 10 секунд оставить: исправление убирает работу до отказа, но не
объявляет гарантированное время старта процесса на произвольно занятом Windows.

## Проверки

- Новый тест запускает отдельный процесс с `-O` и `-OO`, устанавливает finder,
  который отклоняет попытку загрузить argparse, rentgen_core или EDT verifier,
  затем импортирует настоящий migration verifier из проверяемой копии.
- До исправления оба варианта должны отказать из-за импортов до запрета.
  После исправления должен возникнуть точный запрет оптимизации до этих импортов.
  Условия внутри оптимизированного процесса выполняются через `if`/исключения,
  без `assert`, который сам был бы удалён оптимизатором.
- Прежний отдельный тест `v.verify(None)` под `-O` сохраняется.
- Нормальный режим: структурные EDT-контракты, перенос языка test engine и
  отказ записи внутрь удерживаемого исходного дерева.

## Границы

BSL, метаданные конфигураций и запуск 1С не изменяются. Это исправление входа
в verifier, не доказательство точной причины прежнего медленного процесса.
Работу и ревью выполняет основной агент без субагентов. Отдельная ветка от
принятого main; кандидат dev13 остаётся неизменным до завершения его квалификации.
