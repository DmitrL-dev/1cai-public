# Нативная проверка Designer XML writer из Core dev10

## Цель

Проверить на установленном публичном Core dev10 цепочку: сохранённый preview
переименования `Catalog.Products.Attribute.Article` в `SKU`, preflight,
запись зарегистрированного Designer XML дерева, импорт именно записанных
байтов в новую файловую базу 1С, проверка Конфигуратором, CAS undo и полное
восстановление исходного inventory.

## Границы опыта

- Используется только принадлежащий проекту `edt-metadata-v1/created`.
- Источник, журнал и файловая база создаются в новом каталоге на одном томе.
- Preview составляется из сохранённых baseline/candidate fixture тем же
  продуктовым механизмом, что и в контрактных тестах. Это синтетический
  preview; выполнение EDT в этом опыте не заявляется.
- Read-only preflight в dev10 сохраняет intent, но возвращает
  `unavailable`: это его прежний контракт. Отдельный live writer проверяет
  сохранённый intent и выполняет поддержанную операцию.
- Продуктовый writer должен изменить зарегистрированный источник, а
  Конфигуратор должен загрузить **этот** каталог, не fixture candidate.
- Перед undo проверяется совпадение изменённого дерева с preview candidate;
  после undo проверяется побайтовое совпадение всего дерева с исходным.
- Бизнес-сценарий миграции данных выполняется существующим нативным
  YAxUnit verifier на идентичном сохранённом preview и связывается хэшами
  inventory. Он не подменяет проверку writer.

## Критерий приёмки

Машинный отчёт содержит ID preview/операции, хэши установленного Core,
платформы, YAxUnit, полные inventory до/после/после undo, результаты
`/LoadConfigFromFiles`, `/UpdateDBCfg`, `/CheckConfig`, дампа и бизнес-фаз.
Каждая стадия проверяет код выхода и останавливает следующую при ошибке.
Публикуемый отчёт исключает содержимое произвольных пользовательских данных.
Вывод не распространяется на произвольные конфигурации, расширения и
производственную базу.
