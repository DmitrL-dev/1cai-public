# Свежий EDT preview → live writer → 1С/YAxUnit на Core dev10

## Цель

На установленном публичном Core `0.1.0.dev10` получить новый сохранённый
preview `Catalog.Products.Attribute.Article → SKU` через работающий EDT 2026.1.3
и проверить непрерывную цепочку до записи исходников, нативной загрузки в 1С,
бизнес-данных и CAS undo.

## Дизайн

Используется существующий принадлежащий Рентгену тестовый профиль с живым
EDT/MCP runtime и опубликованным snapshot. Перед запуском verifier проверяет:
точный SHA256 публичного ZIP, совпадение файлов установленного Core с wheel,
права владельца, включённый EDT профиль, исходный inventory, актуальный head,
отсутствие незавершённого writer и полное совпадение fixture manifest. Старый
успешный EDT preview служит только ориентиром для идентичности плана; новый
preview создаётся через `metadata_runs.create_preview` с новым UUID. Продукт
сам резервирует отдельный workspace, запускает EDT, сохраняет request,
transcripts, baseline/candidate и закрывает процесс.

После проверки readback нового preview writer получает отдельный UUID и
сохранённый preflight intent. Он записывает ровно поддержанное переименование
в зарегистрированном Designer XML дереве. Verifier проверяет полный inventory
после записи, удерживает все файлы во время `/LoadConfigFromFiles`, затем
выполняет `/UpdateDBCfg`, `/CheckConfig`, round-trip и структурные проверки.
CAS undo выполняется после выхода из native pin; полный исходный inventory
сверяется побайтово. Отдельный YAxUnit прогон на тех же retained
original/baseline/candidate inventory проверяет значения и негативный UUID.

Публичный JSON содержит ID preview/операции, digest и полные inventories,
версии/хэши бинарных входов, коды native шагов и статусы бизнес-тестов.
Абсолютные пути к личному тестовому профилю остаются только в локальном
каталоге запуска. При ошибке до apply источник остаётся исходным; после apply
verifier пытается CAS undo в `finally`, а исходная ошибка и журналы сохраняются
для разбора. Неизвестный результат writer не маскируется повторным apply.

## Границы

Это собственный синтетический каталог и одна операция. EDT создаёт preview,
а live writer меняет выгруженные исходники; продукт не обновляет рабочую ИБ.
Нативная проверка и YAxUnit используют новые файловые базы. Вывод не
распространяется на произвольные клиентские конфигурации, `.cf/.cfe`,
расширения, формы/СКД как самостоятельные изменения, внешние конкурентные
записи или production deployment.
