# Исполняемые инструкции установки выбранного Core

## Основание

В опубликованном sdist dev14 инструкция называет исходники и wheel dev13.
Реальная сборка создаёт dev14, поэтому указанный путь установки не существует.
Номер версии вручную снова устареет; выбор первого wheel через glob может взять
чужой выпуск. Выбранный вариант — читать project.version из pyproject.toml
конкретных исходников и разрешать ровно соответствующее имя через LiteralPath.

## Решение

- CORE-INSTALLATION: номер версии не зашивается в текст и команды. Два сценария
  (Core и MCP) самодостаточны, создают свои окружения и определяют wheel из
  pyproject.toml. Отсутствующий wheel вызывает отказ до установки.
- MCP использует закреплённый профиль mcp-py311-windows.txt, уже используемый
  офлайн-комплектом; установка extra не обращается к resolver без lock.
- CORE-OFFLINE-KIT: выходная папка без номера релиза; версия исходников задаётся
  выбранным checkout. Исторические данные явно обозначаются как история.
- Эти два документа входят в sdist. Изменение требуется включить в новый
  квалифицированный выпуск; уже опубликованные теги и файлы остаются неизменными.

## Проверка

Сначала воспроизвести отказ старой команды на реальном wheel dev14. Затем
выполнить новые команды из самих Markdown-блоков в свежих папках с пробелами,
проверить installed version, pip check и CLI. MCP установить офлайн из принятого
wheelhouse с hash lock и запустить существующий клиент проверки 32 команд.
Отдельно проверить отсутствие нужного wheel при наличии другого: fallback
не допускается. Квитанции привязать к хэшам документов, pyproject и wheel.

Работа и ревью выполняются одним агентом согласно указанию без субагентов.
Полная готовность продукта и нативная SCM-приёмка этим не подтверждаются.
