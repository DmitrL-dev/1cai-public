# Проверка на установленной платформе 1С

10 сентября 2026, Windows x64, платформа **8.3.27.2342**. Найдены полный клиент
`1cv8.exe` и `ibcmd.exe`. Проверка ниже использовала полный клиент и отдельную
файловую базу, созданную для этого эксперимента. Рабочие базы не использовались.

Подтверждён базовый цикл:

1. `CREATEINFOBASE` создал базу и файл `1Cv8.1CD`.
2. `DESIGNER /DumpConfigToFiles` выгрузил нативный XML конфигурации.
3. В копии XML изменено только имя конфигурации с `Конфигурация` на `RentgenTest`.
4. `DESIGNER /LoadConfigFromFiles` загрузил изменённую копию.
5. `DESIGNER /UpdateDBCfg` успешно обновил конфигурацию базы данных.
6. `DESIGNER /CheckConfig` сообщил «Ошибок не обнаружено».
7. Повторная выгрузка подтвердила имя `RentgenTest` и сохранение UUID конфигурации.

Все семь операций/проверок успешны; команды клиента вернули код 0 и уложились
в таймаут 45 секунд на команду. Исходная выгрузка не изменена. Параметр соединения
`CREATEINFOBASE` в этом запуске использовал путь без пробелов и без вложенных
кавычек; переносимость цитирования произвольных путей ещё не подтверждена.

Это локальный smoke, а не результат GitHub CI и не полная приёмка продукта.
Автоматизирован ручной пакетный путь Конфигуратора; независимый от платформы
редактор конфигураций этим экспериментом не доказан. Не проверены формы,
бизнес-сценарии, обновления типовых решений с сохранением доработок, откат,
клиент-серверная база, другие версии платформы и `ibcmd`.

Для следующего этапа достаточно собственных синтетических объектов. Типовую
конфигурацию и две её версии нужно выбирать под конкретный сценарий обновления
с контрольными доработками и ожидаемым результатом, а не только ради запуска.
