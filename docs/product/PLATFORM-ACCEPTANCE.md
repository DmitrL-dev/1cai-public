# Проверка на установленной платформе 1С

10 сентября 2026, Windows x64, **8.3.27.2342**: выполнен воспроизводимый сценарий
с общим модулем и модулем управляемого приложения. Все базы и исходники созданы
самим тестом; типовые решения и рабочие базы не использовались.

## Что подтверждено

1. Создание файловой базы и выгрузка нативной основы XML.
2. Добавление собственного общего модуля `RentgenPlatformProbe`, загрузка,
   компиляция в серверном, внешнем и тонком клиентском контекстах, обновление базы.
3. Запуск приложения: вызов функции общего модуля вернул **42**.
4. Загрузка копии с ошибкой `Return 40 + ;`. Проверка 1С вернула **101**, указала
   тестовый модуль и строку 2. Ошибочная версия не обновляла конфигурацию базы.
5. Повторный запуск приложения после отказа по-прежнему вернул **42**.
6. Загрузка исправленного модуля, успешные компиляция и обновление, результат **43**.
7. Повторная выгрузка: UUID конфигурации и общего модуля сохранились; BSL общего
   модуля и модуля приложения совпал с ожидаемым после нормализации BOM/переводов строк.

Все 15 команд завершились в пределах 45 секунд каждая. Единственный ненулевой
код — ожидаемый отказ компилятора. Результаты исполнения читались из отдельных
новых файлов; старый файл запрещает запуск проверки. Исходная выгрузка сохранена.
Путь к тесту содержал пробелы и кириллицу.

[Краткое свидетельство локального запуска](evidence/native-platform-8.3.27.2342.json)
содержит хэши проверяющего скрипта и исполняемого файла, шаги и результаты.
Это свидетельство разработчика, не независимая аттестация.

## Повторить проверку

Из checkout этой ветки или распакованного sdist dev8:

```powershell
python scripts/verification/verify_native_platform.py `
  --platform 'C:\Program Files\1cv8\8.3.27.2342\bin\1cv8.exe' `
  --output 'C:\RentgenTests\Платформа 1' --timeout 45
```

Каталог `--output` должен быть новым. Скрипт сам создаёт базу и не принимает путь
к существующей базе. Нужен полный клиент и право его использования; скачивание
платформы и изменение лицензирования не выполняются. `acceptance.json` появляется
только после всех проверок; рядом остаются журналы, аргументы, исходники и база.
При таймауте или Ctrl+C завершается только созданное скриптом дерево процесса.
Повторный запуск требует нового каталога, старые результаты не удаляются.

Параметры строки соединения цитируются отдельно от командной строки 1С.
Обычный Python `list2cmdline` неверно экранирует вложенные кавычки для этого
парсера. Скрипт передаёт строку напрямую процессу, без shell; двойные кавычки
внутри аргумента удваиваются, имена команд и ключи остаются без кавычек.

## Границы

Это локальная проверка установленной платформы. GitHub CI проверяет обработку
ошибок самого скрипта; без установленной 1С он не выполняет этот сценарий.
Базовый предыдущий smoke изменения имени пустой конфигурации также прошёл.

Пакетный режим использует движок Конфигуратора. Полная замена Конфигуратора,
операции редактирования объектов через API Рентгена, формы, бизнес-сценарии,
обновления поставщика с сохранением доработок, резервное копирование и откат,
клиент-серверная база, другие версии и `ibcmd` ещё не приняты.

Отдельная проба COM на этом компьютере завершилась `TYPE_E_LIBNOTREGISTERED`
при `Connect`, хотя `V83.COMConnector` указывал на `comcntr.dll` версии 8.3.27.2342.
Регистрация системы не менялась; COM не входит в успешную проверку выше.

Для следующего этапа достаточно собственных синтетических объектов. Типовую
конфигурацию и две её версии нужно выбирать под конкретный сценарий обновления
с контрольными доработками и ожидаемым результатом, а не только ради запуска.

Основание для команд: официальные разделы 1С о
[строке соединения](https://kb.1ci.com/1C_Enterprise_Platform/Guides/Administrator_Guides/1C_Enterprise_8.3.27_Administrator_Guide/Appendix_7._Startup_command-line_options_of_1C_Enterprise/7.7._Infobase_connection_string/7.7.1._General_information/?language=en),
[создании базы](https://kb.1ci.com/1C_Enterprise_Platform/Guides/Administrator_Guides/1C_Enterprise_8.3.24_Administrator_Guide/Appendix_7._The_parameters_of_the_command_line_to_launch_1C_Enterprise/7.2._Selecting_run_mode/7.2.3._Launch_in_the_infobase_creation_mode/?language=en)
и [выгрузке/загрузке XML](https://kb.1ci.com/1C_Enterprise_Platform/Guides/Administrator_Guides/1C_Enterprise_8.3.27_Administrator_Guide/Appendix_7._Startup_command-line_options_of_1C_Enterprise/7.4._Running_Designer_in_batch_mode/7.4.4._Configurations_and_extensions/?language=tr).
Совместимость конкретного синтаксиса запуска дополнительно подтверждена самим
нативным сценарием, включая отрицательную проверку компилятора.
