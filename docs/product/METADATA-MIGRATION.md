# Проверка сохранности данных при изменении метаданных

10 сентября 2026 на 1С 8.3.27.2342 и YAxUnit 25.12 выполнен полный проверочный
сценарий собственной фикстуры. В одной новой файловой ИБ созданы три записи
Products с Unicode-строкой, пустой строкой и строкой из 32 знаков. Полные исходные
идентификаторы ссылок сохранены в тестовых данных и сравниваются после обновлений.

| Этап | Проверенный результат |
| --- | --- |
| Создание записей с Article | 3 записи записаны, значения и ссылки прочитаны |
| Новый сеанс 1С | Данные сохранились вне сеанса и вне транзакции теста |
| Загрузка baseline после импорта EDT | Значения, число записей и ссылки сохранились |
| Обновление на candidate с SKU | Значения читаются через SKU; ссылки сохранились; Article отсутствует |
| Возврат исходной схемы с Article | Значения и ссылки сохранились; SKU отсутствует |
| Candidate с намеренно изменённым UUID реквизита | Загрузка, обновление и компиляция успешны; тест значения падает |

Отрицательный пример дал одну ошибку утверждения, а не технический сбой тестового
движка: вместо ожидаемой 32-символьной строки прочитана пустая. Это показывает,
почему CheckConfig недостаточно для подтверждения сохранности данных. Каждый
сеанс проверял строго выбранный серверный тест; JUnit и файл exit code согласованы.

## Точность входов и границы доказательства

Испытаны точные original/baseline/candidate из сохранённого preview. Их файлы
удерживались по размеру и SHA256. Изменений языка или других служебных правок в
базовую конфигурацию итоговый сценарий не добавляет. После каждого положительного
обновления сделана обратная выгрузка; проверены UUID справочника, реквизита и формы,
ID поля и привязка `Объект.Article` / `Объект.SKU`.

Для запуска YAxUnit его заимствованный объект языка `Русский` переименован в
`Russian` внутри тестового расширения с сохранением UUID и LanguageCode `ru`.
Именно так язык назван в исходной фикстуре. Расширение сначала выгружается из
загруженной конфигурации без UpdateDBCfg, затем адаптируется и дополняется
собственными модулями. BSL этих модулей и их UUID проверены обратной выгрузкой
до исполнения тестов. Framework CFE закреплён SHA256; сторонний код не включён
в MIT-исходники Рентгена.

Проверка покрывает три набора значений одного строкового реквизита в конкретном
справочнике и конкретные выгрузки. Она не доказывает сохранность произвольной
типовой конфигурации, всех типов данных, обработчиков и бизнес-процессов.
Нормализация EDT проверена на этом корпусе; общая матрица её допустимости ещё
не завершена. Возврат схемы в тестовой ИБ не является реализованным протоколом
apply/undo Рентгена. Автоматического изменения статусов прежнего preview нет.

## Воспроизведение

Исходники репозитория или sdist содержат проверяющий скрипт и собственные фикстуры.
Нужны Windows, Python без `-O`, установленная 1С и внешний YAxUnit 25.12 CFE из
[закреплённого профиля](../../packaging/test-profiles/yaxunit-25.12/inputs.json).
Аргумент input-run указывает на каталог операции с `input`, `baseline-xml` и
`candidate-xml`; принимается только исходная фикстура edt-metadata-v1, не произвольная ИБ.

```powershell
$env:PYTHONPATH = (Get-Location).Path
python scripts/verification/verify_metadata_migration.py --input-run <каталог-операции> --platform <путь-к-1cv8.exe> --platform-sha256 <SHA256> --ibcmd <путь-к-ibcmd.exe> --ibcmd-sha256 <SHA256> --cfe <путь-к-YAxUnit-25.12.cfe> --output <новый-каталог>
```

Существующий output не перезаписывается. Скрипт создаёт только собственную ИБ,
владеет деревом процессов, ограничивает время и место на диске. Последний шаг
намеренно теряет значение в собственной тестовой ИБ; положительные результаты
предыдущих этапов сохранены отдельно. Оставшаяся ИБ предназначена для исследования
отрицательного примера, а не для дальнейшей работы.

`acceptance.json` содержит инвентари входов, хэши платформы, движка, тестовых
модулей и отчётов; `reports.json` — отдельные результаты фаз; `steps.json` —
нативные команды. Нулевой код скрипта означает, что положительные тесты прошли,
а отрицательный завершился ожидаемой ошибкой утверждения. Скрипт не повторяет
операцию с неизвестным исходом и не восстанавливает прерванный запуск автоматически.

[Машинная сводка принятого запуска](evidence/metadata-migration-v1.json).
Следующий продуктовый этап — привязать такие проверки к политике применения
candidate и реализовать журнал применения/отмены с защитой от чужих изменений.
