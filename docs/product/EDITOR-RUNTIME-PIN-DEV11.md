# VS Code: совпадение снимков установленного дерева при проверке dev11

После публикации [Companion 0.1.11](https://github.com/DmitrL-dev/1cai-public/releases/tag/companion-v0.1.11)
и [Core dev11](https://github.com/DmitrL-dev/1cai-public/releases/tag/core-v0.1.0-dev11)
повторён ограниченный сценарий редактор → установленный Core → 1С/YAxUnit
на новом собственном синтетическом проекте. Для этого повтора **до первого**
и **после второго** процесса редактора сняты манифесты дерева локальной
установки VS Code. Это дополнительное доказательство к
[первой проверке опубликованной пары](EDITOR-TESTS.md#опубликованные-companion-0111-и-core-dev11--24-сентября-2026),
а не изменение выпущенных файлов.

## Что именно закреплено

Исполняемый `Code.exe` имеет версию `1.138.0` и SHA256
`081417b5e8032c703cf9e25e4886ab10c417ad1b8b87cfd1244c67d15331a8a6`.
Локальный обход установки отвергал reparse entries, считал SHA256 каждого файла,
сохранял относительный путь и размер, а также список каталогов. Перед запуском
и после обоих процессов получились **побайтно одинаковые** манифесты: 2473
файла, 636 каталогов, 1 110 103 413 байт файлов. SHA256 каждого полного
манифеста (489660 байт) —
`b712c1b7ad0dff1596f525d07e8713a8c1856c37825c139c5864d101abf35013`.
Полные манифесты сохранены локально; в Git опубликован ограниченный итог без
абсолютных путей хоста. SHA256 локального скрипта обхода —
`59132f4159a1fb4252519654a009350f4e3df64c892b1bc15d60cf10e2b6db86`.

## Повторный нативный сценарий

Входами оставались публично скачанный VSIX с SHA256
`916e1311a5bd8ea43c05e7220c547239bb056a963b85ab7746a13ff8e67f83d5`
и установленный Core из принятого ZIP с SHA256
`9351d2b8790a358f66931a3067e8ba1823b61b7ca6b97989bb430f8fd124441a`.
Временная копия существующего host harness меняла только ожидаемую версию
Companion `0.1.8 → 0.1.11`; её исходный и использованный хэши приведены в
[квитанции](evidence/editor-runtime-pin-dev11-20260924.json).

Первый процесс VS Code выбрал сохранённую ревизию **1** при актуальной **2**.
Baseline дал один ожидаемый failure, candidate — один passed на отдельных
собственных файловых базах 1С 8.3.27.2342/YAxUnit 25.12. Второй процесс
отключил тестовый профиль и прочитал тот же завершённый отчёт, не создав нового
запуска. Исходный модуль и head проекта сохранились, модель не вызывалась.
Локальные исходные acceptance JSON имеют SHA256
`45cde7a003dc2ef34d553322d1842d888cd9b3898a247ec08e1760c224c45c4d`
и `1a15da2ddcacfb5fa492d80369c068d7124496cef3da46941e2bdbb13244c9a0`.
[Публичная ограниченная квитанция](evidence/editor-runtime-pin-dev11-20260924.json)
имеет SHA256 `69427c7aabd86319333b26c39813a6a3673a6f43f8e8f158c011c0ce5f711dbb`.

## Предел доказательства

Совпадение двух снимков показывает, что на границах прогона состав, размеры и
SHA256 файлов установки совпали. Временное изменение с последующим возвратом
между снимками этим способом не исключено. Манифест не включает системные
библиотеки Windows, состояние ОС, отдельные каталоги user-data и расширений, окружение
процесса или внешнюю аттестацию. Поэтому прежнее поле отчёта
`runtime_dependencies: not_fully_pinned` остаётся корректным: полный runtime
редактора этим опытом не квалифицирован. Также не проверены типовые
конфигурации, рабочая ИБ, live apply из редактора или production deployment.
