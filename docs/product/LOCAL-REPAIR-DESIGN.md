# Управляемая правка сохранённого модуля

2026-09-10. Следующий вертикальный сценарий ежедневной разработки; полная
продуктовая цель и остальные функции стратегии v3 сохраняются.

Рентген формирует вызовы ядра; модель предлагает только точные замены текста
и краткое объяснение. Это устраняет служебные ошибки UUID/SourceRef/MCP и
зависимость этого сценария от XML-шаблонов Cline. Форк Cline и новый универсальный
агент отклонены для этого шага: они расширяют объём изменений без проверки
основной гипотезы — способен ли выбранный локальный движок исправить модуль.

Вход: доверенный профиль установленного core dev7, выбранный SourceRef и
инструкция пользователя. Создание нового черновика, чтение ревизии 1 и анализ
идут через официальный MCP SDK. Один запрос Ollama получает полный код модуля
в LF без BOM, инструкцию и диагностики. `format` задаёт JSON Schema:
`{edits: [{old_text, new_text}], summary}`. Сервер модели только loopback;
HTTP-прокси и перенаправления выключены. Результат проходит строгий разбор,
ограничения UTF-8 и проверку уникальных непересекающихся замен ядра. Адаптер
возвращает исходный LF/CRLF; BOM сохраняет ядро. Поддерживается также один цельный
Markdown-блок json вокруг объекта, без пояснений снаружи; строгий разбор и
проверки содержимого выполняются после снятия этой оболочки.

Лимиты первой версии: полный модуль до 32 КиБ без усечения, инструкция до
4 КиБ, до 16 замен по 8 КиБ каждое поле, ответ JSON до 24 КиБ; один запрос
модели, общий срок 120 секунд, до 4096 выходных токенов, окно 32768.
Большие модули пока отклоняются явно, а не передаются частично. Это ограничение
первой реализации, не критерий полной продуктовой готовности.

До каждой записи журнал фиксирует operation_id. Нет повторных модельных
запросов или автоматического повторения мутаций. При конфликте/отмене/потере
ответа сохраняются идентификаторы для чтения квитанции. Новая ревизия проверяется
повторным чтением, хешем и анализом. Отчёт связывает диагностику с конкретным
кандидатом; `clean` означает только полный успешный BSL-анализ. Тесты платформы
не запускались, применение недоступно. Слова модели не считаются доказательством.

Реализация: `integrations/open-editor/repair_model.py` отвечает за модель и
контракт текста; `repair_workflow.py` — за последовательность MCP и проверку
результатов; `run_repair.py` — за доверенный профиль, SDK и журнал запуска.
CLI — первая поставляемая точка входа; команда companion добавляется после
подтверждения реального сценария. Исходная конфигурация не записывается.

Проверки: настоящий локальный HTTP-приёмник для структуры/лимитов/ошибок;
контрактные отказы на повреждённую диагностику и конфликт без повторной записи;
один синтетический сценарий с реальной локальной моделью, установленным SDK,
BSL Language Server, независимым чтением истории и проверкой смысла исправления.
Положительный результат этого примера не доказывает качество произвольных задач.
