# Ежедневная AI-разработка: связка работает, задача не принята

10 сентября 2026. Companion 0.1.5 разработки теперь поддерживает управляемую
правку и нативную проверку в одном профиле core dev8. Адаптер проверяет точное
совпадение версии ядра с профилем, MCP 1.30.0 и выбранного Python. Dev7 остаётся
поддержан; неизвестная версия или несовпадение установки отклоняются.

В отдельном окружении установлены dev8 и зависимости MCP из локальных wheels
с проверкой хэшей. Настоящий VSCodium загрузил собранный VSIX. Команда правки
создала ревизию 1, получила диагностику BSL, сделала один запрос к локальной
Qwen3.5:9b, сохранила ревизию 2 и повторно выполнила BSL-проверку.

Задача: устранить пустой обработчик исключения при записи документа, сохранив
передачу ошибки вызывающему коду. Модель вставила `Сообщить(...)` и продолжила
проглатывать исключение. До правки BSL сообщил `MissingCodeTryCatchEx`, после —
`DeprecatedMessage`. Расширение показало `diagnostics_present`; чистая проверка
или правильность задачи не заявлены. По журналу был **один** запрос: 498 входных
и 159 выходных токенов; модель не запрашивалась повторно.

В новом процессе редактора найден этот же черновик. Его выбранная ревизия
прошла настоящую компиляцию 1С 8.3.27.2342 на исходном снимке, включая проверку
исходника и кандидата. Отчёт прочитан по UUID. SourceRef, proposal content ID
и ревизия сохранены; исходный модуль, head и журнал модельного запроса не
изменились. Таким образом, компилируемый код может оставаться неправильным
по задаче. Функциональные тесты конфигурации не запускались.

Исходники проверок:

- `scripts/verification/prepare_daily_platform.py` создаёт новый синтетический
  проект из `first-roundtrip` проверки native platform. Принимает явные пути
  `--python`, `--scanner`, `--fixture`, `--diagnostics-root`, `--platform`, `--output`.
- `scripts/verification/companion_host/daily.cjs` запускает один запрос через
  настоящую команду редактора. Критерий успеха включает конкретную проверку
  сохранения передачи исключения; нулевого количества диагностик недостаточно.
- `scripts/verification/companion_host/daily_followup.cjs` исследует сохранённую
  неудачную попытку и компиляцию без нового запроса к модели. Не объявляет задачу
  исправленной. Входной профиль задаётся `RENTGEN_EDITOR_PROFILE`.

В первой неудачной попытке счётчик в отчёте host остался начальным нулём из-за
раннего assertion. Фактический один запрос подтверждён журналом и последующей
проверкой. Verifier исправлен: неизвестное значение — `null`, сбор сведений о
запросе предшествует проверке успешности. Исходная неудачная попытка сохранена.

Проверено 165 Python-тестов и 31 Node-тест. VSIX этой проверки: SHA256
`4831ebee86c32a9e9a151070111a0f01b9fe9262dcae859d33740af198645bf0`, 133099 байт.
Это новая сборка разработки; опубликованные выпуски не менялись. Диалоги
пользователя покрыты контрактными тестами, в host использованы аргументы команд.
