# Установленный Core dev11: автономный Git-аудит schema 3

24 сентября 2026 года установленный публичный Core `0.1.0.dev11` прошёл
ограниченный локальный сценарий `Rentgen.GitAudit` schema 3 в консольном режиме.
До запуска уже существовал опубликованный snapshot одного собственного
синтетического BSL-проекта. После нового чистого Git-коммита отдельный
publisher **не** запускался: schema 3 сама выполнила capture закреплённым
Go scanner, затем анализ настоящим BSL-LS и создала owner report.

## Привязка к поставке

Использована ранее проверенная установка [Core dev11](https://github.com/DmitrL-dev/1cai-public/releases/tag/core-v0.1.0-dev11):

wheel SHA256 `74cfe4a4f00369e13ef87c084ab1b62a016ac0661217fba015d5bccc831877b6`,
`bsl-scan.exe` SHA256 `8d81c1eda05d9c358385396861eb1df611d83489582f7293ad461c45017817c4`.
Все 10 установленных файлов `rentgen_diagnostics` ранее побайтно сверены
с wheel. Внешний исполняемый BSL-LS 1.0.5 JAR имел SHA256
`de97f571e6474c5c151cf859294f589ee01152de3b4826b43e1a80b69ee2602a`,
входной Temurin JDK ZIP 21.0.12.1+1 —
`f9d6e191ab098c0d416e7d588a24420a8621cd2f4720dab2459b8b7b2d2d8b4e`.
Это **уже использованный** локальный runtime, а не приёмка свежей распаковки;
отдельный [issue #23](https://github.com/DmitrL-dev/1cai-public/issues/23)
фиксирует отказ первого цикла на новом runtime.

findings и остановился **до вызова службы**. После исправления verifier
прочитал head через `LocalRuntime.head()` и выполнил оба приведённых цикла.
Этот первый сбой harness не является отказом продукта и не учитывается как
проверочный цикл. SHA256 использованного скрипта —
`ae04e776c6bcdb9f08e5191cf5b194dac927a288c4298769450ba0deb6157266`.
Локальная исходная JSON-квитанция имеет SHA256
`954b1d8dc2467fec6268bf54ebd6d4928853e7cb333b710bedec304f18e8d820`.
[Публичная ограниченная квитанция](evidence/service-git-schema3-native-dev11-20260924.json)
содержит те же проверенные связи без путей хоста и SID: 2094 байта,
SHA256 `ccd97a988b128cf8d1bc2e1b81e17e7e91c90dd7b169cfa27f8647b462632a78`.

## Предел доказательства

Это один новый commit после уже существовавшего snapshot, один синтетический
BSL-модуль, один Windows-хост, console mode. Сценарий подтверждает
автономное создание snapshot и нативный анализ на этом пути; он не проверяет
первую установку runtime, непрерывную службу Windows SCM, service account,
конкурентную запись, реальную конфигурацию `.cf/.cfe`, рабочую ИБ,
доставку уведомлений, HTTPS/DNS или production deployment.
