# Диагностика из открытого агента: незавершённая приёмка

2026-09-09. Проверен один ограниченный запуск VSCodium 1.135.06055,
Cline 4.1.17 legacy, companion 0.1.1 и установленного core 0.1.0.dev5.
Локальная qwen3.5:4b Q4_K_M работала через Ollama с окном 32768;
весь runtime модели занимал 7106172928 байт GPU RTX 4060/8GB.
Это проверка искусственного модуля, не оценка работы на конфигурации заказчика.

## Задача и фактический результат

Модуль `ЗаписьДокументов.bsl`, 488 байт UTF-8 BOM/CRLF, содержит процедуру
`СохранитьДокумент`, которая вызывает `ДокументОбъект.Записать()` и скрывает
исключение в пустом обработчике. Агент должен прочитать сохранённый черновик,
выполнить анализ до изменения, вернуть ошибку вызывающему коду и повторить анализ.
Подсказка не содержит готовой правки. Сигнатура и единственный вызов записи
должны сохраниться; подавление диагностики не считается исправлением.

Получено:

- Cline и companion действительно активировались с установленным dev5.
- Агент прочитал снимок, создал ревизию 1 и получил русский текст через
  `rentgen_draft_read(encoding="utf-8")`.
- Настоящий BSL Language Server 1.0.5/Temurin 21.0.12.1 вернул
  `MissingCodeTryCatchEx`, Error, строка 9. Runtime проверен по закреплённым
  файлам, покрытие `exact_one`, диагностика полная.
- Два запроса `rentgen_draft_edit` содержали некорректный JSON. Cline отверг
  их до вызова MCP. В предложенном тексте также отсутствовал корректный
  обработчик исключения. Проверка исправленного кандидата не состоялась.
- Попытка остановлена на девятом модельном запросе, 139,8 секунды. Нулевой
  exit code редактора не засчитан как успех: независимый verifier вернул
  `accepted=false`, `failure=request-limit`, exit code 1.
- Новый процесс CLI подтвердил единственную ревизию 1, исходные байты и
  неизменный head. Живой модуль также не изменился. Повторной модельной попытки
  после этого не было; модель выгружена из GPU.

Тесты 1С не запускались по решению пользователя. Применение недоступно.
Диагностика имеет статус доказательства `ephemeral_unattested`: она не является
сохранённым доверенным запуском или разрешением на применение.
**Полный цикл диагностика → исправление → повторная проверка не принят.**

## Исправления продукта

В dev5 добавлено текстовое чтение черновиков через MCP. Раньше был только
base64, неудобный для чтения русских модулей моделью. Новый режим сохраняет
BOM/переводы строк, полные и порционные хеши, текущие проверки прав и точную
ревизию. Лимиты и курсор измеряются байтами; граница порции не разрезает
символ. Прежний base64-ответ по умолчанию сохранён. Реальный установленный
MCP SDK проверил оба режима, включая кириллицу и символ вне BMP.
Поддержка текста вне BMP не расширяет BMP-only профиль анализатора.

Добавлен установщик BSL runtime из локальных файлов. Он сверяет все 490 файлов
JDK и JAR с манифестом установленного ядра, сохраняет лицензии, проверяет
существующий каталог вместо перезаписи, не скачивает и не выполняет Java.
Профиль редактора принимает отдельный каталог диагностики и передаёт
`LOCALAPPDATA` только MCP-процессу. Это потребовалось из-за виртуализации AppData
процессом MSIX: проверка конечного пути ядром правильно отклоняла подменённый
Windows путь. Проверки закрепления runtime не ослаблены.

Установщик завершает удержание каталогов перед Windows rename, затем проверяет
конечный runtime заново. Это локальная установка доверенным пользователем;
изоляция от конкурентного злоумышленника с тем же SID не заявлена.

## Автосогласования Cline

В первой попытке общий `actions.useMcp=true` позволил незапланированный
`rentgen_project_list`, несмотря на список шести отдельных автосогласований.
В установленном официальном legacy bundle подтверждена проверка
`shouldAutoApproveTool(...) || tool.autoApprove`.

Генератор тестового сценария исправлен: общий флаг остаётся false, список
шести инструментов сохраняется. Исправленная настройка ещё не прошла новый
модельный запуск. Пользовательский генератор и прежде оставлял все
автосогласования выключенными. Список в UI не является серверной политикой
доступа; это уточнение внесено и в прежний отчёт приёмки редактора.

Следующий шаг — ограниченный набор инструментов и проекта на стороне MCP,
проверенный настоящим SDK, и измерение объёма контекста агента. Это должно
сократить лишние возможности и контекст, но само по себе не доказывает качество
модели. Повторять дорогой сценарий без изменения причины не следует.

## Воспроизведение и записи

`scripts/verification/prepare_editor_diagnostic.py` создаёт новый искусственный
проект и профиль. После его `install.ps1` используется
`run_open_editor_host.py --profile PROFILE --prompt-file PROFILE/diagnostic-prompt.txt`.
Нельзя считать вывод модели проверкой: `verify_editor_diagnostic.py` отдельно
связывает сообщения MCP с квитанциями CLI и хешами; для завершённого сценария
требует два реальных анализа и третий независимый анализ сохранённого кандидата.
Этот положительный путь пока не подтверждён реальным модельным запуском.
Проверка допустимой формы правки специфична для данной процедуры и не доказывает
произвольную бизнес-логику BSL.

Фактический профиль: `output/editor-diagnostic-acceptance-20260909/profile`.
Записи в `C:/1cAI/output/product-readiness-2026-09-08`:
`editor-diagnostic-attempt-20260909.json` и
`editor-diagnostic-observations-20260909.json`.
Они сохраняют неудачу, единственный результат анализатора и независимые
квитанции; не заменяют приёмку всего продукта.
