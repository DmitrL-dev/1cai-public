# Профиль тестирования сохранённого предложения

Решение: неизменяемый проектный профиль с адресом SHA256. Администратор
регистрирует явные локальные пути и хэши полного клиента 1С, ibcmd и закреплённого
YAxUnit 25.12, а также собственные серверные тестовые модули и непустой список
ожидаемых методов. Ядро копирует CFE и байты модулей в состояние проекта.
Изменение тестов означает новый профиль. Тестовый код не входит в предложение
агента и не подменяется изменениями исходников. Отключение профиля запрещает новые
запуски, но сохраняет возможность читать прежние отчёты.

Выполнение требует project:read, source:edit, analysis:run. Профиль создаёт только
project:admin. Первые команды доступны локальному CLI; MCP не принимает пути
исполняемых файлов и регистрацию тестового кода. Регистрация означает доверие
администратора к выполнению BSL профиля и конфигурации на этом компьютере.

Запуск фиксирует SourceRef, content ID предложения, профиль и UUID операции до
создания процессов. Baseline и candidate материализуются из сохранённого снимка;
для каждой стороны создаётся отдельная новая файловая база. Обратная выгрузка
должна подтвердить модуль до исполнения. YAxUnit запускается с закреплённым
набором тестов; JUnit, отдельный exitCode и фактически перечисленные тесты
должны согласоваться. Пустой отчёт, неизвестный набор, пропуски и технический
сбой не обозначаются как passed. Рабочие исходники, head и рабочая ИБ не меняются.

Результат хранится атомарно в test-runs. Его можно прочитать без открытия
профиля, EXE или снимка. Повтор операции с теми же входами возвращает только
завершённый отчёт; неполная/неуспешная попытка автоматически не повторяется.
Права проверяются до входов, во время исполнения и перед выдачей. Отмена
останавливает собственное дерево процессов. Полной изоляции ОС и подписи
результата этот механизм не обеспечивает.

Поддержка первого адаптера: один слой Designer XML, YAxUnit 25.12, собственные
серверные общие модули тестов, Windows. Расширения проекта, EDT, клиентские и
параметризованные тесты требуют отдельного расширения матрицы. Профиль и запуск
ограничены по числу модулей/тестов, размеру входов и времени.

## Регистрация и запуск

В JSON регистрации передаются `schema: 1`, человекочитаемое `name`, объекты
`platform`, `ibcmd`, `engine` с абсолютными `path` и `sha256`, массив `modules`.
Каждый модуль содержит `name`, абсолютный `path` к UTF-8 BSL и массив `tests`
с точными именами методов. Тесты регистрируются самим BSL через
`ИсполняемыеСценарии`; список `tests` задаёт ожидаемый результат, а не генерирует
сценарии. Пример одного элемента:

```json
{
  "name": "ЮТРентгенПроверка",
  "path": "C:\\RentgenTests\\ОшибкаЗаписи.bsl",
  "tests": ["ОшибкаЗаписиПередается"]
}
```

Используйте хэши своей проверенной установки 1С. Для первого адаптера хэш CFE
должен совпадать с закреплённым YAxUnit 25.12 из
`packaging/test-profiles/yaxunit-25.12/inputs.json`. Исходный модуль примера
расположен рядом. Вызовы для уже зарегистрированного проекта:

```powershell
$common = @('--registry', 'C:\RentgenState\registry.sqlite3', '--project', $projectId)
rentgen test-profile-register @common --profile-json C:\RentgenTests\profile.json
rentgen test-profile-list @common
$operationId = [guid]::NewGuid().ToString()
rentgen proposal-test @common --snapshot $snapshotId --proposal-json $proposalFile --test-profile $profileId --operation-id $operationId
rentgen proposal-test-result @common --operation-id $operationId
rentgen test-profile-disable @common --profile-id $profileId
```

Сохраните UUID до запуска. При прерывании сначала прочитайте результат по UUID;
`incomplete` не означает, что процесс завершён. Для сознательно нового запуска
используйте новый UUID. Возврат CLI 0 означает получение отчёта, а не успешные
тесты: смотрите `tests.baseline.status`, `tests.candidate.status`, счётчики и случаи.
`tests.status` относится к candidate. Ошибки компиляции дают `not_run`, пропуски —
`incomplete`. Автоматического применения изменений нет.

## Проверено на установленном пакете

`scripts/verification/verify_test_profile_delivery.py` проверил ядро из отдельного
venv на 1С 8.3.27.2342: исходная реализация дала один failure, исправленная — один
passed. Использовались две новые базы и один неизменный профиль. После capture
живой исходник намеренно изменён; исполнены именно сохранённые байты. Head и
живой исходник сохранились. Повтор завершённой операции после отключения профиля
вернул прежний отчёт, не изменив ни одного файла запуска; новый UUID отклонён.
Чтение результата выполнено отдельным процессом CLI. Unit-тесты дополнительно
проверяют отзыв доступа, отключение во время исполнения и фиксацию входных файлов.

[Доказательства приёмки](evidence/test-profile-installed.json) содержат хэши,
счётчики и область проверки. Для воспроизведения используйте `--help` скрипта;
его `--source` — каталог `bad-source` самостоятельного платформенного стенда,
`--python` — Python с установленным dev8, `--scanner` — собранный bsl-scan.exe.
Каталог `--output` должен отсутствовать. Базы и журналы сохраняются для разбора;
[лимиты исполнителя и очистка служебных данных](NATIVE-RESOURCES.md) сохраняют
базы и отчёты. Общая политика сроков хранения результатов пока не реализована.

Статус: локальный CLI и [companion 0.1.8 разработки](EDITOR-TESTS.md) подтверждены
на синтетическом сценарии. Типовые конфигурации, полное бизнес-покрытие и длительное
автономное хранение результатов ещё предстоят. Отдельная база не ограничивает сетевой доступ BSL.
