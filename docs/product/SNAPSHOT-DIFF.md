# Изменения файлов между снимками

2026-09-10. Реализовано в публичных исходниках core 0.1.0.dev8. В опубликованном
комплекте core 0.1.0.dev7 этой команды нет; установите отдельно собранный dev8.

Срез для будущего observer: сравнить два явных снимка одного проекта и выдать
добавленные, удалённые и изменённые файлы, точные SourceRef и общие количества.
Основа сравнения — слой, точный путь и SHA256 исходных байтов. Переименование
даёт удаление и добавление; семантическая идентичность, порядок расширений,
качество кода и бизнес-метрики не выводятся из изменения файла.

Оба снимка читаются через существующие ограниченные SnapshotReadSession:
действующие права, проверенные retained bytes и проверка целостности при выходе.
Текущий исходный каталог и LLM не нужны. Курсор привязан к упорядоченной паре
снимков, проекту и размеру страницы; последующий head не меняет сравнение.
Размер страницы 1–100, избыточный JSON отклоняется с просьбой уменьшить страницу.

CLI: `snapshot-diff --registry PATH --project UUID --before HASH --after HASH`
с необязательными `--limit` и `--cursor`. Это сравнение уже опубликованных
снимков, без слежения, запуска сканера, диагностики и записи состояния.

Сравнение проверено на настоящих публикациях с Go scanner и SQLite: точные
байты, сохранённые ссылки, переименование как удаление/добавление, страницы,
более поздний head, отсутствие текущего файла, повреждение retained manifest,
отзыв прав перед чтением и во время сериализации ответа. Это основание для
последующего observer, а не готовая служба постоянного наблюдения.

Пример после двух публикаций:

```powershell
rentgen snapshot-diff --registry C:\RentgenState\registry.sqlite3 --project PROJECT_UUID --before BEFORE_SHA256 --after AFTER_SHA256 --limit 100
```

`counts` относится ко всему сравнению, `changes` — к текущей странице. Каждая
строка содержит `kind` и записи `before`/`after` с точными SourceRef; отсутствующая
сторона равна `null`. `next_cursor=null` означает последнюю страницу. В следующем
вызове передайте тот же проект, снимки и лимит, добавив `--cursor NEXT_CURSOR`.
Повторное чтение страницы снова проверяет права и сохранённые байты.

Предел каждой сессии: 20 000 исходных записей, 2,5 ГиБ проверяемых байтов,
30 секунд; сравнение держит две сессии одновременно. Превышение даёт явный отказ,
а не частичный отчёт. Сравнение не является дешёвым опросом изменения head:
будущий observer должен сначала проверить ID снимка и не повторять сравнение
при неизменившемся ID. Для больших отчётов каждая страница повторяет проверку
снимков; это ограничение текущего интерфейса.
