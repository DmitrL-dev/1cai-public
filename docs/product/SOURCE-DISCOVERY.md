# Поиск исходников по всему снимку

Реализовано в development checkout, 2026-09-09. Редактор теперь получает модули
из всего снимка и ищет их по пути. Большое число XML-файлов перед BSL больше не
создаёт пустые страницы модулей. Это поиск точного исходника в ежедневном сценарии;
диагностика, тесты, применение и остальные критерии продуктовой готовности остаются
отдельными требованиями. Прежние сборки dev2 этих фильтров не содержат.

Существующий source-list расширен необязательными `query`, `kind` и
`layer`. Фильтрация работает по полному проверенному manifest до pagination;
живые файлы и содержимое модулей для поиска не читаются. Отдельный индекс сейчас
создал бы вторую границу актуальности. Загрузка всех страниц в браузер добавила
бы задержки и лишние запросы, оставив агентам другой интерфейс.

- `query`: подстрока полного относительного пути, Unicode casefold, без regex,
  нормализации путей и изменения возвращаемого написания. По умолчанию пустая;
  максимум 256 символов/1024 UTF-8 байта, управляющие/форматные символы и суррогаты
  запрещены. Регистр поиска не меняет identity исходника.
- `kind`: `all` по умолчанию или `module` для `.bsl`/`.os` без учёта регистра.
- `layer`: отсутствует для всех слоёв или точный существующий ID слоя; неизвестный
  явно указанный слой даёт ошибку. Слои не сливаются: одинаковые пути сохраняют
  разные SourceRef и исходные хеши.
- Порядок остаётся ordinal слоя + точный путь manifest. Страницы ограничены
  1..200 элементами. Курсор связывает фильтры, проект, снимок и размер страницы;
  смена фильтра требует начала нового поиска. Старый курсор без фильтров сохраняет
  прежний контракт. Нельзя продолжить курсор по другому набору результатов.
- CLI `source-list`, MCP `rentgen_source_list` и HTTP `/sources` используют одно
  ядро и текущие правила авторизации/лимитов. Параметры проверяются до открытия
  графа и удержания generation там, где transport поддерживает preflight.
- Редактор всегда запрашивает `kind=module`. Форма поиска по пути отправляется
  явно, а не на каждое нажатие клавиши. Изменение фильтра сбрасывает страницу;
  уже открытый локальный черновик сохраняется. Смена проекта/снимка сбрасывает
  поисковый контекст через существующие ключи. Полный точный SourceRef остаётся
  единственным входом для открытия модуля.

Проверка: более 200 XML до искомого BSL; кириллица/регистр, одинаковые пути в
слоях, пустая выдача, страницы без пропусков/дубликатов, неверный курсор/фильтр,
отзыв прав и S1 после S2. Целевые CLI/MCP/HTTP проверки используют общий контракт;
браузер должен найти модуль за пределами первой общей страницы, открыть его и
сохранить проверяемый черновик через настоящий API. Тесты платформы 1С отложены
пользователем; поиск manifest от них не зависит.

## Использование

В редакторе введите часть пути в «Поиск модуля по пути» и нажмите «Найти модуль».
«Сбросить поиск» возвращает список всех модулей; открытый черновик сохраняется.
Поиск по содержимому и символам здесь не заявлен. Фильтр слоя доступен через
CLI/MCP/HTTP; интерфейс явно показывает слой каждого результата.

```powershell
rentgen source-list --registry C:\Rentgen\registry.sqlite3 --project PROJECT_UUID --snapshot SNAPSHOT_SHA256 --kind module --query Продажи --layer base --limit 50
```

В MCP передайте `query`, `kind`, `layer` инструменту `rentgen_source_list` вместе
с `project_id` и `snapshot_id`. HTTP использует те же названия query-параметров
в `/api/v1/projects/{project}/snapshots/{snapshot}/sources`. Следующую страницу
запрашивайте с прежними фильтрами и размером страницы, передав `next_cursor` как
`cursor`. Чтобы сменить фильтр, начните без курсора.

## Приёмка

Новый публичный стенд создаётся командой
`scripts/verification/project_portal_acceptance.py setup-discovery`: в проекте A
205 XML-файлов предшествуют модулям. После `grant-editor --run UUID`, запуска API
и Vite используйте фазу `source-discovery` в `prepare_project_portal_browser.py`.
Полный вывод исполняемого Playwright-сценария сохраняйте только в приватный каталог
стенда; экспорт результата выполняет команда `result`.

На реальном API проверены пустая выдача, четыре отдельных слоя, открытие найденного
модуля, сохранение BOM/CRLF и SourceRef после смены поиска, отсутствие запросов
при наборе текста, отсутствие горизонтального переполнения при ширине 390 px.
Отдельные реальные CLI-процессы прошли две страницы четырёх слоёв; официальный
MCP SDK нашёл BSL после 205 XML. Это синтетические проекты с настоящими JWT,
SQLite, Windows SID и Go, без полного production lifespan или запуска 1С.
