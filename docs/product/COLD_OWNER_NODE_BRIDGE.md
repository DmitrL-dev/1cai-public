# Локальный Node-мост для холодного запуска

## Что сделано

Добавлен проверяемый участок обмена служебными сообщениями перед запуском расширения. Он готовит один запрос `BOOTSTRAP`, собирает ответ из фрагментов и принимает только `REFUSAL` — сообщение об отказе. Успешный запуск настоящего редактора через этот мост пока не реализован.

Для обычного пользователя порядок работы с опубликованной версией остаётся прежним. Эта страница описывает следующий шаг разработки. Она не предлагает включать экспериментальный транспорт или обходить проверку владельца.

## Один запрос: по шагам

1. Владелец локального тестового контракта передаёт ожидаемые идентификаторы запроса, поколение соединения, лимиты и часы. Эти значения сами по себе не подтверждают личность процесса.
2. Первый `bootstrap` сохраняет общий promise до вызова внешних часов. Повторный вызов получает тот же promise.
3. Экземпляр расходует один объект lease и готовит один исходящий кадр. Другой экземпляр не может повторно использовать этот объект lease.
4. `outbound` возвращает максимум одну копию запроса. Автоматической повторной отправки нет.
5. `receive` собирает один ответ из ограниченных фрагментов. Проверяются длина, UTF-8, состав полей, отсутствие повторных JSON-ключей и соответствие исходному запросу.
6. Корректный `REFUSAL` завершает promise ошибкой. Инициализатор расширения не запускается. Внутренние буферы удерживаются до разрешённого локального закрытия.

## Какие ограничения проверяются

| Ограничение | Поведение |
| --- | --- |
| Тип сообщения | Допускаются запрос `BOOTSTRAP` и ответ `REFUSAL`; `RESULT` и данные успешной привязки отклоняются |
| Длина кадра | Четыре байта длины перед JSON; максимум тела 65 536 байт |
| Размер фрагмента | Не больше заданного лимита; верхняя граница 16 384 байта |
| Поля JSON | Один плоский объект; запрещены лишние поля, повторные ключи, вложенные значения и неверные корреляции |
| Объём и число вызовов | Отдельные лимиты суммарных байтов, удерживаемого хранения и вызовов `receive`; один слот запроса |
| Сроки | Сохраняются абсолютные границы соединения, ответа, отмены и закрытия; изменение исходного объекта их не продлевает |
| Часы | Принимаются монотонные значения `bigint`; движение назад и ошибка часов приводят к отказу |
| Отмена | Сначала прекращается локальная работа; возможен максимум один локальный запрос отмены |
| Закрытие | Только точный объект lease; повторное успешное закрытие не повторяет освобождение буферов |
| Ошибки | Вторичная ошибка отмены или закрытия не подменяет первую ошибку запроса |

## Что подтверждают тесты

Восемь новых групп проверяют отказ по умолчанию, фрагментированный ответ и общий promise, неверные поля и корреляции, лимиты, отмену и сроки, повторный вход и сохранение первой ошибки. Вместе с прежними проверками активации и bootstrap локально прошли 38 тестов без пропусков.

Две дополнительные проверки воспроизводят ошибки повторного входа: закрытие должно отозвать запрос до вызова внешних часов, а отменённый до отправки объект lease нельзя использовать повторно через новый экземпляр моста. До исправления оба случая завершались ошибкой; после исправления прошёл весь локальный набор из 38 тестов.

Тестовые объекты lease, байты и часы созданы самим тестом. Результат подтверждает этот участок кода. Он не является доказательством настоящего IPC, личности процесса редактора, завершения Win32 IO или возможности загрузить модель.

## Следующие шаги

- Связать прикладной кадр Python с той же удерживаемой IO-операцией и её буферами.
- Подтвердить владельца настоящего процесса редактора через удерживаемую цепочку передачи, а затем подключить единственный транспорт.
- Отдельно проверить завершение native IO, бюджет очистки и запуск установленного расширения.

Мост не содержит socket, pipe, запуска процесса или вызова модели. `execute` отвечает `OWNER_TRANSPORT_NOT_ADMITTED`. По умолчанию endpoint недоступен. Поля `ready`, `peer_bound`, `kernel_authority`, `native_completion`, `Root_lease_settled` и разрешения на модель остаются false; loading/native grants отсутствуют.

## Связь с проверочным контрактом Python

В [контракте Python-соединения](COLD_OWNER_CONNECTION.md) описан следующий
проверочный срез Source54: готовый `BOOTSTRAP` из буфера той же операции и один `REFUSAL`.
Отказ не завершает native IO. Исходные сроки сохраняются; storage удерживается
до успешного завершения и закрытия той же операции. Шесть узких Python-тестов
прошли отдельно; они не расширяют результаты 38 Node-тестов и не подтверждают
новый транспорт.

В Python-контракте после независимого ревью исправлены две дополнительные
проблемы до отправки и при освобождении диагностических ссылок. Полный узкий
набор теперь содержит восемь прошедших Python-тестов; подробности приведены в
[описании двух исправлений](COLD_OWNER_CONNECTION.md). Эти результаты сохраняют
границу `REFUSAL`, не разрешая настоящий транспорт или запуск модели.
