# Локальная графическая рабочая область

Статус: **новый экспериментальный срез из исходников, ещё не опубликованный GUI-релиз**.
Визуальный интерфейс работает в браузере, анализ ZIP использует существующий Rust input core
и Python authorization/parser. Принятый Linux binary Core dev17 подходит для этого среза.
Весь продукт, Windows/macOS GUI, живые базы и командные операции этим не квалифицируются.

## Первый рабочий сценарий

1. Запустить локальный GUI для явно выбранного проекта.
2. Открыть выданную ссылку в браузере на том же компьютере.
3. Выбрать или перетащить ZIP-выгрузку Designer XML.
4. Дождаться проверки ZIP и чтения структуры. Можно отменить передачу или анализ.
5. Исследовать объекты и модули, найти запись по имени/пути, посмотреть свойства,
   UTF-8 исходник и SHA-256. Модули около объекта определяются только по пути его папки,
   это не семантический граф зависимостей.

Приложение читает только загруженные байты. Оно не изменяет исходный архив,
живую базу, исходники проекта, registry, membership, head, snapshots или drafts.
Новый выбранный ZIP полностью принимается до анализа. Если он не проходит проверку,
предыдущий успешный результат остаётся доступным.

## Запуск из checkout

Нужны Python 3.11+, GNU/Linux x86_64 и проверенный Rust input core из
[экспериментального дополнения dev17](https://github.com/DmitrL-dev/1cai-public/releases/tag/core-v0.1.0-dev17).
Требования Linux runtime совпадают с [Rust input core](RUST-INPUT-CORE.md).
Никакие npm/framework/server dependencies не добавлены. Файлы интерфейса входят в package.

Сначала один раз явно создайте изолированные identity, registry и проект по инструкции
[переносимого ядра](PORTABLE-CORE.md). Не используйте чужую identity или production state
для ознакомительного запуска.

```sh
python -m rentgen_core.gui \
  --registry /absolute/registry.sqlite3 \
  --identity-profile /absolute/private/identity.json \
  --project <project-uuid> \
  --input-core /absolute/rentgen-input-core \
  --input-core-sha256 <verified-binary-sha256> \
  --open-browser
```

После установки новой сборки аналогичная команда называется `rentgen-gui`.
Это не означает, что GUI уже есть в опубликованном wheel dev17.
Port по умолчанию выбирается OS. При необходимости `--port 8765` задаёт фиксированный порт.
Host всегда `127.0.0.1`; произвольный listen address не принимается.

Ссылка запуска содержит временный случайный ключ сеанса в fragment.
Не пересылайте ссылку и не включайте её в журналы или скриншоты.
Интерфейс убирает ключ из адресной строки и хранит его только в памяти вкладки.
После обновления/закрытия вкладки нужно снова открыть исходную ссылку запуска.
Перезапуск процесса делает старую ссылку недействительной.
Остановка: Ctrl+C в терминале. Приложение отменяет активную операцию, дожидается
завершения дочернего процесса и удаляет собственные временные файлы.
После аварийного kill могут остаться временные файлы в закрытой OS temp-папке;
автоматическое удаление неизвестных каталогов не выполняется.

## Границы результата

- Только ZIP Stored/Deflate без пароля, ZIP64, multipart и небезопасных путей.
- Designer XML расположен прямо в корне ZIP; внешняя обёртка не угадывается.
- До 16 МиБ архив, 4096 записей, 32 МиБ распакованных данных, 4 МиБ на файл.
- До 200 объектов или модулей на странице результата. Текстовый поиск
  метаданных проверяет весь принятый ZIP по имени, синониму, каноническому типу
  (`Catalog`, `Document` и т. п.) и относительному пути. Число совпадений и усечение
  показаны явно. Фильтр типа применяется к показанным результатам; поиск модулей
  проверяет имена и пути всех принятых модулей. Остальные результаты доступны кнопками предыдущей и следующей страницы.
- Просмотр исходника ограничен 256 КиБ и UTF-8. Бинарные/неподдерживаемые кодировки
  не декодируются с потерей данных. Исходник показывается без выполнения кода.
- `metadata = bounded_root_properties_only`, `bsl = inventory_only`, UUID unverified,
  live source not verified, published snapshot false.
- Диагностика, callgraph, сравнение, изменения и командные процессы недоступны.
  UI обозначает их как будущие этапы и не генерирует фиктивные результаты.
- Frontend не требует Windows. Backend этого маршрута пока Linux-only;
  запуск `gui` на Windows/macOS явно отклоняется до обращения к проекту.

## HTTP boundary

Это локальный transport для одного OS account, не authentication service для сети.
Hostile code того же account, root и подмена trusted startup configuration вне границы.

- Новый 256-bit token на процесс, без cookie, localStorage или persistent credentials.
- API требует token header; exact Host, Origin для POST/PUT, Fetch Metadata checks.
  CORS не разрешён. CSP запрещает внешние assets/network, frames, objects и base URL.
- Registry/profile/project/helper/hash берутся только из доверенной команды запуска.
  Браузер не выбирает OS paths или права. Filename используется только как подпись.
- Проверки текущих project:read + analysis:run выполняются вокруг Rust IO и после
  сериализации успешного результата/ошибки, перед HTTP disclosure.
- Source endpoint принимает путь только как selector ранее возвращённого inventory.
  Он повторно открывает собственный upload через Rust, проверяет archive SHA и raw SHA,
  ограничивает размер и отдаёт только полностью проверенные UTF-8 bytes.
- Нет extraction ZIP, shell-команд из UI, телеметрии или отправки исходников наружу.
- Двухэтапный upload даёт ID до передачи bytes, что позволяет явную отмену.
  Резервирование истекает через 30 секунд; body deadline 30 секунд;
  максимум 8 активных HTTP handlers, 75 секунд на request и один анализ одновременно.
- Отмена cooperative на границах существующего Rust протокола. Кратковременная задержка
  возможна до завершения текущего bounded IO. Если завершение уже победило отмену,
  возвращается готовый результат. Успех не выдаётся до подтверждённого reap Rust child.

## Проверки

```sh
RENTGEN_INPUT_CORE_TEST_BINARY=/absolute/rentgen-input-core \
  python -m pytest -q tests/unit/test_local_gui.py tests/unit/test_local_gui_search.py tests/unit/test_rust_input_workflow.py
node --test tests/gui/*.test.mjs
```

Набор проверяет настоящий loopback HTTP, Rust ZIP import/source, отказ чужим Host/Origin/token,
file path и размер, сохранность project state, отмену с reap настоящего child, cleanup,
усечение source, authorization после сериализации, потерянный upload и повторный импорт.
Это целевая приёмка. Она не заменяет browser end-to-end, полный существующий Windows suite
или native-приёмку Windows/macOS.

Для визуальной проверки можно собрать **явно подписанный UI-only файл** из синтетического
JSON результата и соответствующих синтетических файлов:

```sh
python scripts/verification/build_gui_visual_fixture.py \
  --analysis-json /path/synthetic-analysis.json \
  --synthetic-source-directory /path/synthetic-export \
  --output /path/Rentgen-visual-review.html
```

Файл не обращается к backend. Он проверяет внешний вид/навигацию, а не импорт.
Не передавайте этому инструменту данные заказчиков. Label в statusbar отличает этот
просмотр от рабочего runtime. Если browser environment запрещает localhost, нельзя обходить
запрет сменой порта или публикацией backend; native browser QA остаётся отдельным gate.

Дизайн учитывает [WCAG 2.2](https://www.w3.org/TR/WCAG22/): focus-visible, клавиатуру,
адаптивный reflow и reduced motion. Это не заявление о сертификации полного соответствия.
Защита запросов следует семантике [Fetch Metadata](https://developer.mozilla.org/en-US/docs/Web/HTTP/Guides/Fetch_metadata).

### Настоящая браузерная приёмка Linux

Отдельный обязательный для квалификации GUI workflow `Linux GUI browser acceptance`
собирает Rust helper из того же checkout и запускает одиннадцать Playwright-проверок настоящей
страницы через `127.0.0.1`. Настройка required check в branch protection выполняется
отдельно; наличие workflow само по себе не изменяет правила слияния.

```sh
cargo +1.92.0 build --locked --release --manifest-path rust/input-core/Cargo.toml -j 2
npm ci --prefix tests/gui/browser --ignore-scripts
(cd tests/gui/browser && npx --no-install playwright install chromium)
RENTGEN_INPUT_CORE_TEST_BINARY="$PWD/rust/input-core/target/release/rentgen-input-core" \
  npm --prefix tests/gui/browser test
```

Playwright зафиксирован в отдельном test-only `package-lock.json`; runtime Python package
по-прежнему не требует npm. Нужен обычный непривилегированный Linux account с поддержкой
Chromium sandbox и системными библиотеками браузера. Команды не устанавливают системные
пакеты и не меняют sandbox/sysctl/права. Если среда запрещает loopback или sandbox,
проверка завершается ошибкой: это **не пройденная браузерная приёмка**. Не используйте
`--no-sandbox`, внешний backend или расширение listen address как обход.

Каждый тест создаёт собственные синтетические ZIP, identity, registry и проект,
запускает неизменённый HTTP server/Rust helper и после завершения проверяет неизменность
входных файлов и project state. Покрыты импорт, объекты, модули, UTF-8 исходник и SHA-256,
повторный импорт, ошибочный ZIP с сохранением предыдущего результата, клавиатурный путь,
Escape/возврат фокуса, поиск, tablist, узкое окно 390 px и настоящий browser zoom 200%.
Для детерминированной отмены задерживается только исходящий upload в браузере после
настоящего резервирования job; `/api/cancel` обслуживает настоящий backend. Отмена уже
запущенного Rust child и reap проверяются дополнительным существующим HTTP/Rust suite.

200% устанавливается через официальный `chrome.tabs.setZoom` в одноразовом test profile.
Минимальное собственное test-only расширение не имеет permissions, host permissions,
content scripts или сетевых запросов. Проверяются `getZoom() == 2`, удвоение DPR и
уменьшение CSS viewport вдвое. CSS zoom и deviceScaleFactor не подменяют этот gate.
Недоступность расширения не приводит к skip. Профиль удаляется после теста.
Для 200% сохраняются два native viewport PNG: начало рабочей области и исходник,
полностью прокрученный в видимую область. CDP захватывает текущую поверхность без
full-page изменения viewport/clip; размеры PNG сверяются с CSS viewport × DPR.
Временное уведомление скрывается до захвата. Receipt сохраняет измерения и границы
исходника; наличие файла само по себе не заменяет визуальный просмотр человеком.
Все запросы страницы, кроме точного origin запущенного loopback server, запрещены тестом;
правила Host/Origin/token/CSP приложения не изменяются.

CI сохраняет JUnit, синтетические скриншоты и receipt с commit checkout и хешем helper.
Успешный receipt создаётся только после одиннадцати выполненных тестов без skips/errors.
Трассы запросов, профиль, identity, registry и ссылка с token не публикуются. На PR явно checkout-ится точный head SHA; receipt проверяет его совпадение с ожидаемым
HEAD и отдельно записывает workflow SHA. Зелёный запуск не доказывает другой HEAD. Это Linux Chromium gate, не Windows/macOS GUI-приёмка,
не полная WCAG-сертификация и не GUI-релиз.


### Потерянный ответ об импорте

Если связь оборвалась после получения ID импорта, интерфейс делает не более трёх
дополнительных чтений состояния **того же ID**: до 3 секунд на чтение и 250 мс
между попытками. Повторная загрузка ZIP или новый запуск анализа автоматически
не выполняются. Подтверждённый результат заменяет предыдущий вместе с его SHA-256.
Подтверждённая ошибка или отмена оставляет предыдущий успешный результат.

Если результат подтвердить не удалось, интерфейс явно показывает, что исход
импорта неизвестен, и скрывает прежний инвентарь: backend уже мог заменить архив.
«Проверить результат» запускает только такой же ограниченный read-only запрос по
известному ID. Можно явно выбрать другой ZIP. Поздние ответы отмены и проверки
предыдущей операции не изменяют новую рабочую область. Если новый импорт не принят
(например, `BUSY` или потерян ответ резервирования), известный прежний ID и кнопка
проверки сохраняются. Ошибка или отмена замены также не теряет эту возможность.

Четыре дополнительные browser-проверки теряют настоящий ответ `ready` после реального
успеха backend, проверяют ограничение попыток/ручное восстановление без повторной
загрузки, поздний ответ отмены после нового импорта и сохранение известного ID после
потери ответа нового резервирования/реального `BUSY`. Ответ успеха backend не
подменяется синтетическим JSON; используются те же собственные тестовые ZIP.


### Поиск метаданных по всему принятому архиву

Непустой запрос запускается после 350 мс без ввода. Один запрос — не более 256 байт
UTF-8, один результат — не более 200 объектов. Поиск повторно читает собственную
неизменяемую копию ZIP через Rust; общие метрики архива не подменяются количеством
совпадений. Пустой запрос в UI возвращает первоначальные первые 200 объектов.
Unicode сравнивается серверным `casefold`, тип задаётся каноническим именем.
Диагностика BSL и семантические связи не добавлены. Отдельный режим точного фрагмента кода описан ниже.

Одновременно допускается только один search worker. Смена запроса/вида/архива
отменяет устаревшую работу, а следующий запрос сериализован с отменой. Backend
не принимает следующий worker, пока предыдущий не завершён и его Rust child не
собран. Протокол Rust сохраняет свой 60-секундный общий deadline; UI ожидание
ограничено 65 секундами, запросы состояния — 5 секундами. Поиск можно сбросить или
повторить явно. Если потерян ответ старта, отмена без ID ограничена тем же текущим
job и точным SHA архива. Фоновый worker остаётся ограниченным даже при потере связи.

Каждый поиск/ответ связан с текущим job и SHA-256 архива. Результаты дополнительно
проверяются после JSON-сериализации, до HTTP-выдачи. Права project:read + analysis:run,
Host/Origin/session key/CSP сохраняются. Смена архива не удаляет файл во время его
чтения поиском. Предпросмотр объекта после первоначальных 200 разрешён только по
последнему успешному server-owned набору результатов: тот же архив и raw SHA
проверяются повторно через Rust. Браузер не выбирает OS paths и не передаёт trusted
hash для выдачи исходника. Старые результаты/allowlist инвалидируются при замене.

Дополнительные тесты используют собственный ZIP с 201 объектом и 204 модулями:
Unicode/синоним/тип/путь/пустой запрос, ограничения, исходник 201-го объекта,
отмена с reap настоящего child, отзыв прав перед выдачей и параллельная замена.
Две browser-проверки проверяют 201-й результат и поздние ответы после смены запроса,
вида и импорта. Их наличие не означает, что новый HEAD уже прошёл CI.

### Поиск путей модулей во всём архиве

В режиме «Имя или путь» раздела «Модули» запрос проверяет относительные пути (включая имена файлов)
всех принятых `.bsl`, `.os` и `.bsp` до ограничения результата в 200 строк.
Сравнение Unicode без учёта регистра использует `casefold`. Содержимое модулей
для этого поиска не читается и не индексируется; это не полнотекстовый поиск BSL.
Число совпадений, общий счётчик модулей и усечение показаны отдельно. Пустой
несвязанный запрос возвращает первоначальный инвентарь.

Кнопка «Найти модули в папке по всему ZIP» у объекта запускает поиск под точным
префиксом его пути XML без расширения плюс `/`. Например, `Catalogs/Item.xml`
даёт `Catalogs/Item/`, но не `Catalogs/ItemNeighbor/`. Это только совпадение папки,
не доказательство семантической принадлежности. Внутри области можно уточнить
запрос; «Сбросить поиск» снимает ограничение папки.

`/api/search-start` принимает дополнительно `kind: metadata|modules` (по умолчанию
`metadata`) и `object_path: null|string`. Путь объекта допустим только для модулей
и разрешается сервером по текущему собственному metadata-hit; произвольные
префиксы и хеши клиента не принимаются. Ответы содержат `kind`, `object_path`
и вычисленный `prefix`; UI проверяет их вместе с job, SHA, search ID и запросом.
Сохраняется один ограниченный metadata-anchor текущей области, не накопительный
кеш. Открывать поздний модуль можно только из последнего актуального ограниченного
набора module-hits, с повторной проверкой SHA ZIP и raw SHA через Rust.

Используется тот же единственный worker, отмена/сбор child, блокировка замены архива
и повторная проверка прав перед выдачей. CLI/MCP `analyze_export(query=...)` сохраняет
прежнее поведение. Лимит просмотра 256 КиБ и строгий UTF-8 не меняются.
Две проверки обнаружения модулей входят в обязательный browser gate:
поздние модули и проверяемый исходник, уточнение области, отсутствие коллизии папок,
а также поздние ответы при смене запроса, отмене, вида и архива. Новый HEAD требует
собственного CI; наличие тестов не означает успешный запуск браузера.

### Страницы инвентаря и поиска

«Предыдущая страница» и «Следующая страница» доступны для объектов, модулей,
текстового поиска и поиска модулей в папке объекта. Порядок стабилен: байты UTF-8
относительного пути. Страница содержит максимум 200 строк; UI показывает диапазон
и полное число совпадений. Фильтр типа по-прежнему ограничен текущей страницей.
Пустой запрос начинает с первоначального инвентаря, но переходы вперёд и назад
повторно читают неизменяемый ZIP; весь архив в браузер не выгружается.

`/api/search-start` принимает `offset`, по умолчанию 0: только целое число
(не boolean), кратное 200, от 0 до 4000. Максимум следует из предела 4096 записей
архива. Offset не является токеном доступа и не может задать путь или хеш.
Некорректный offset отклоняется до запуска worker; ненулевой offset за пределами
совпадений отклоняется после ограниченного подсчёта. Для нулевого результата
разрешена только страница offset=0. Объекты/модули фильтруются до смещения.

Ответы старта и состояния содержат offset вместе с query/kind/object_path/prefix
и job/SHA. Результат содержит `page`: offset, limit, total, returned, has_previous,
has_next. UI проверяет привязку, размер и согласованность диапазона до показа.
Смена запроса, вида, папки или импорта сбрасывает страницу. Во время загрузки
переходы отключены; отмена и запоздалые ответы сохраняют защиту поколений.

Каждый переход использует существующий единственный search worker с ограниченным
временем и сбором Rust child. Исторические страницы не накапливаются: для исходника
доступны первоначальный инвентарь текущего job, текущая актуальная страница и один
ранее проверенный anchor папки. Следующий принятый backend-поиск/переход страницы или импорт отзывает предыдущие
дополнительные page-hits. Локальный сброс поля или смена вида сами по себе
не отзывают уже завершённую страницу сервера: они подавляют устаревший UI через
поколения запросов. Это сохраняет прежнюю границу «последний актуальный backend
результат», без нового endpoint отзыва.
Проверки прав после сериализации, SHA архива/raw SHA, лимит 256 КиБ и строгий UTF-8
сохранены. CLI/MCP `analyze_export` не получает новую семантику пагинации.

Тесты используют собственные архивы с более чем 400 объектами и модулями:
200/200/1, обратный переход, Unicode-запрос, точная папка, границы/подмена offset,
устаревшие исходники и ответы, отмена, импорт и отзыв прав. Browser gate требует
все 17 сценариев без пропуска, включая навигацию клавиатурой, 390px и настоящий
200% zoom. Успешность нового HEAD подтверждает только его отдельный запуск CI.

### Точный фрагмент кода: первое совпадение в файле

В разделе «Модули» режим «Фрагмент кода» ищет буквальный однострочный текст
с учётом регистра. Запрос непустой, до 256 байт UTF-8; пробелы и табуляция значимы,
CR/LF и прочие C0-символы недопустимы. Нет регулярных выражений, индекса,
семантического поиска символов/вызовов или утверждения о выполнении кода.

Одна строка результата означает один подходящий файл, не одно вхождение. Показаны
только первое совпадение, номер строки от 1 и фрагмент до 512 Unicode-символов
(максимум 2048 байт UTF-8). Остальные вхождения внутри файла не перечисляются.
Это сохраняет максимум 4096 file-hits и страницы по 200 без накопления всех
совпадений. Порядок — байты UTF-8 пути, смещение — прежние 0..4000 с шагом 200.
Есть общая область архива и точная папка ранее разрешённого metadata-объекта.

Поиск читает только принятые `.bsl`, `.os`, `.bsp` через RustInputSession; Python
не открывает ZIP самостоятельно. На файл действует тот же предел 256 КиБ, строгий
`utf-8-sig` и политика C0, что у просмотра исходника. BOM не сдвигает строки;
CRLF, CR и LF считаются переводами строки. Колонки/Unicode-casefold не заявлены.
Перед принятием раннего совпадения проверяется весь файл на недопустимые символы.

Слишком большие, не-UTF8 и содержащие запрещённые C0 файлы пропускаются с отдельными
счётчиками. UI всегда показывает количество проверенных файлов и полное/частичное
покрытие именно выбранной области модулей, включая нулевой результат. При частичном
покрытии отсутствие совпадений в проверенных файлах не доказывает их отсутствие
в пропущенных. XML и иные расширения не входят в область поиска исходного кода.

Бюджет одного поиска: не более 4096 записей принятого manifest, не более 32 МиБ
прочитанных исходников суммарно и 256 КиБ на файл. Python-сканер удерживает текущий
файл и максимум 200 результатов, а не все исходники/вхождения. Python проверяет
права, отмену и бюджет между блоками до 32768 символов (literal overlap до 255),
Rust transport — между чтениями до 32768 байт. Ограниченный источник/фрагмент
выводится через textContent; полный просмотр не превращается в сотни тысяч DOM-строк.

10 секунд CPU относятся только к Python worker thread (`thread_time`), без CPU
Rust child. 45 секунд wall — кооперативный бюджет, не OS quota и не жёсткое
прерывание: незавершённый Rust exchange может добавить до 10 секунд при открытии
или до 5 при чтении, плюс существующий bounded reap. Python decode/строковые
примитивы ограничены размером одного файла. Прежние 60 секунд Rust session,
96 МиБ transport и подтверждённый сбор child сохраняются. При превышении бюджета
возвращается `SOURCE_SEARCH_BUDGET_EXCEEDED` без успешного частичного списка и
без сообщения «ничего не найдено»: полный поиск не завершён. Это отличается от
успешно завершённого сканирования с явно учтёнными пропущенными файлами.

Локальное измерение на собственных 127 файлах по 256 КиБ (33,292,288 байт) дало
4.528 секунды wall и 4.121 секунды worker-thread CPU с полным покрытием. Это одно
измерение в cloud, не гарантия скорости и не измерение CPU дочернего процесса.

Протокол использует `kind: source` с прежними job/SHA/query/object_path/prefix/offset.
`modules` содержит file-hits с `first_match`, `source_coverage` — счётчики и complete,
`scan` — bytes_read/wall_ms/thread_cpu_ms. Перед выдачей повторяются права и привязка.
Для открытия действуют только первоначальный инвентарь, текущая актуальная страница
и один anchor; full-file ZIP/raw SHA проверяются заново. Прочие режимы и CLI/MCP
не меняются. Новый exact HEAD требует собственного CI:17 обязательных browser
сценариев, включая source/path-mode гонки, поздний source preview, HTML-подобный
literal, частичное покрытие, пагинацию, узкое окно и настоящий 200% zoom.
