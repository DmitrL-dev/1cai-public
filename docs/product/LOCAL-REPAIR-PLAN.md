# Реализация управляемой правки

Исполнение последовательно в текущем worktree, без субагентов. Дизайн:
[LOCAL-REPAIR-DESIGN.md](LOCAL-REPAIR-DESIGN.md). Автономная работа разрешена
пользователем; отдельный цикл согласований реализации не требуется.

- [x] Модель: тест `parse_edit_response` на уникальную замену, BOM/CRLF,
  лишние поля, повторяющиеся ключи JSON, слишком длинный ответ и no-op.
  Реализовать строгий парсер и `OllamaEditor.propose(raw, instruction, diagnostics)`;
  проверить один HTTP-запрос с `format`, отсутствие tools/ID и запрет redirect.
- [x] MCP: `repair(call, source_ref, instruction, model, record)` создаёт IDs,
  журналирует намерение записи, читает точную ревизию, проверяет настоящий
  baseline, вызывает модель один раз, сохраняет expected_revision=1, сверяет
  новую ревизию/хеш и анализ. Тесты: невалидный baseline не вызывает модель;
  конфликт/неясный результат не повторяет запись; неполная диагностика не clean.
- [x] CLI: `run_repair.py --profile PATH --source-ref PATH --instruction PATH
  --output NEW_DIRECTORY --model qwen3.5:4b`. Только установленный dev7 и SDK
  1.30.0; профиль формирует собственные аргументы MCP с ограничением проекта.
  Журнал fsync до мутации, самостоятельная директория запуска, без перезаписи.
- [x] Реальный сценарий: отдельный искусственный модуль подавления исключения,
  одна генерация, BSL до/после, независимый CLI читает историю/квитанции/кандидат
  и сверяет неизменные source/head. При отрицательном результате сохранить причину.
  Выполнены два разных режима по одному запросу каждый; обе приёмки отрицательные.
- [x] Документация использования и ограничений, целевые тесты, отдельный commit.
  UI companion остаётся следующим шагом, полная готовность не объявляется.
