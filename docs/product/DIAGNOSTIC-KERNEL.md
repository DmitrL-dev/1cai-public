# Rust diagnostic kernel: ограниченный эксперимент

В исходниках появился отдельный [`rust/diagnostic-core`](../../rust/diagnostic-core/README.md).
Он проверяет типизированные факты, поддерживает или опровергает ограниченные
гипотезы, выбирает следующую проверку и пересматривает вывод при отзыве evidence.
Это компонент для синтетических наблюдений. Он не читает выгрузку или базу сам,
не подключён к пользовательскому CLI/MCP и не выполняет предложенную проверку.
В опубликованные пакеты Core dev17 / Companion 0.1.18 этот более поздний
source-эксперимент не входит.

В том же crate добавлен отдельный [source-fact профиль](SOURCE-FACTS.md): его
экспериментальный Linux CLI принимает только три наблюдения из выбранных bytes,
не наследует синтетическую квалификацию ниже и ещё проходит свою приёмку.

## Реализованная граница

Пять совместимых, не взаимоисключающих выводов относятся к трём классам:
контекст/экспорт метода общего модуля, тип/наличие члена непосредственного
получателя и ограниченное рассогласование исходников с runtime. Формы и
динамические вызовы в этом профиле недоступны. Причины уровня «старая сессия»
или «расширение не применилось» kernel не устанавливает.

Чтение, права проекта, реальное происхождение фактов и исполнение checks остаются
обязанностью будущего host adapter. Все результаты помечены
`experimental_synthetic_not_authenticated`: входные строки `same_attested` и
`access: usable` сами по себе ничего не удостоверяют. Имя исключения, строки
кода, значения данных, пути, команды и произвольные labels в протокол не входят.
Модель, обучение и внешний AI API не используются.

Контракт ограничивает вход 64 KiB, глубину JSON 16, факты и supersession edges
до 128, гипотезы до двух на выбранный класс, каталог шестью checks, наблюдения
тремя, стоимость девятью условными единицами и применение правил 256.
Стоимость отражает раскрытые типизированные факты, а не измеренную задержку 1С.
Неизвестное, конфликт, неподдержанный контекст и потеря witness не превращаются
в догадку. Операции live write/undo и Windows retained reader не изменены.

Подробный wire contract: [PROTOCOL.md](../../rust/diagnostic-core/PROTOCOL.md).
Продолжение архитектуры и native-adapter gates: [план](NARROW-DIAGNOSTICS-PLAN.md).

## Что измерено для синтетического профиля

До исполнения зафиксированы исходники, критерии и независимые собственные
синтетические cases. По замечаниям source review исправлены формы JSON и
generic evaluator; первоначальные снимки сохранены, пороги и скрытые сценарии
не менялись. После этого выполнен один compile/development run и один полный
frozen evaluation run.

- 32 Rust contract tests и 2 stdio tests прошли.
- 249 вызовов kernel покрыли все 182 запланированные единицы оценки.
- Неверных диагнозов, необоснованных опровержений, утечек canary, неразрешённых
  наблюдений и нарушений точного протокола не обнаружено в этом наборе.
- В каждом split из 24 случаев: 12/12 случаев с хотя бы одним доказанным
  ограниченным выводом и 12/12 отрицательных контролей без диагноза.
- В каждом восьмисценарном сравнении: 13 запросов adaptive против 15 fixed-order;
  3 выигрыша, 1 проигрыш и 4 равенства. Стоимость и раскрытие **равны: 21 единица**.
  Результат означает меньше запросов в этих сценариях, не меньше данных или
  ускорение на настоящей платформе.
- Held-out recall отдельных допустимых выводов: **14/15**. Остановка после
  первого доказанного вывода не устанавливает все одновременно истинные причины.

Тесты удерживают семейства историй evidence и сопоставлений, а не незнакомые
исходники 1С. Числа не являются production accuracy или статистически доказанным
обобщением. После публикации wire vectors служат только повторяемой регрессии.

Независимый аудит заново вывел результаты по сохранённым входам/выходам и
подтвердил прохождение зафиксированных критериев. Найдены три пробела будущего
evaluator: проверка совместимости реально раскрытого значения, consent у
paired-prefix и явное применение порогов/полноты расписания. Отдельная проверка
всех 83 таких наблюдений установила, что этот запуск они не затронули.
[Машиночитаемый результат и hashes](DIAGNOSTIC-KERNEL-QUALIFICATION.json)
разделяют исходный эксперимент и [публичную регрессию](../../rust/diagnostic-core/tests/observed-wire/README.md).

## Известные ограничения

Отдельный случай с двумя конфликтующими предпосылками имеет допустимую
двухшаговую цепочку исправления evidence, но одношаговая эвристика не начинает
её: **0/1**, avoidable abstention. Это недостаток покрытия, а не принципиальная
невозможность получить ответ. Другой случай требует четырёх наблюдений при
лимите три и останавливается по бюджету; эти причины не объединяются.

Полноценное извлечение source facts, native receiver capture, signatures 1С,
проверка реальной identity/ACL, наблюдение за сессией и пользовательская
диагностика ещё не приняты. Ускорение, macOS и готовность всего продукта
не заявлены. Опубликованные Core dev17 / Companion 0.1.18 имеют отдельные
принятые bytes и release records; этот crate их не заменяет.

## Повторяемая проверка исходников

Из полного checkout с Rust 1.92.0:

```sh
cargo +1.92.0 test --locked -j 1 --manifest-path rust/diagnostic-core/Cargo.toml -- --test-threads=1
```

Отдельный CI проверяет этот синтетический компонент на Linux и Windows.
Он не меняет существующие Product checks и не превращает известный Windows-
ориентированный полный Linux suite в зелёный.
