## Как читать и обновлять реестр

Колонка «Статус S» фиксирует исходную сверку, а не текущий результат незавершённой ветки. `incomplete` — есть часть реализации или приёмки; `missing` — нет квалифицированной пользовательской реализации; `weak` — есть связанные code/tests/старые records, но недостаточно прямых доказательств; `dependencies` — отдельный prerequisite gate; `contradicted` — фактический результат противоречит желаемому; `proven` — доказана только явно указанная область.

На S: 71 `incomplete`, 9 `missing`, 39 `weak`, 1 `dependencies`, 2 `contradicted`, 5 `proven`. Два `contradicted` ID описывают разные критерии одной старой отрицательной AI-попытки, а не два новых опыта. Пять положительных записей — четыре component gates и одна историческая native-фикстура; **ни одна не закрывает полный финальный релиз**.

Чтобы изменить состояние требования, рядом с ID фиксируют новый source SHA, OS/runtime/fixture, точную команду, executed/skipped/error counts, установленный артефакт и receipt; результат должен покрывать весь критерий. После изменения SHA перепроверяют нужные gates. Синтетический test подтверждает свой контракт, а не подставляет native/model/human acceptance.

Архивные планы/specs сохраняют даты и исходные checked/unchecked. Старый unchecked не означает отсутствие современного кода; старый checked не доказывает новую поставку. Их действующие инварианты остаются в строках ниже; шаги «создать RED», «bump dev14», «publish dev15» не становятся новыми командами. История dev19 — в [датированной сверке](RELEASE-PLAN-20261015.md).

## Оставшиеся внешние условия

- Лицензированный exact-build 1С/EDT host и owned test bases для нового native, debugger, data/rollback и object/runtime matrix. Сейчас недоступны.
- Квалификация закреплённого editor host связывает точные Core/VSIX/BSL bytes с activation/restart/recovery/Problems; keyboard/accessibility и native 1С остаются отдельными gates.
- Реальный выбранный model endpoint и независимый frozen holdout с разрешёнными fixtures/лицензиями для сравнения policies и новой daily AI-задачи.
- Настоящие заявленные Windows/Linux/macOS/arch/filesystem топологии; обычные hosted Windows SCM/Git checks не являются native 1С business workflow.
- Независимый новый пользователь для первого результата и времени; automated offline install этого не заменяет.

Разработка идёт готовыми пользовательскими блоками: функция, tests и инструкции вместе; проверочные remote commits допустимы ради CI. Независимый готовый PR по умолчанию squash, зависимая цепочка или явное указание человека — обычный merge. Версии/tag не создаются для каждого PR. Служебные qualification/publication records появляются после фактических bytes/публикации и объединяются с post-release docs; прежние принятые records, теги и assets неизменны.
