# Профиль среды EDT

Статус: в ветке разработки после core-v0.1.0-dev8. Команды регистрируют среду;
они ещё не предоставляют редактирование метаданных или квалификацию runtime.

Администратор проекта выбирает локальный EDT и Java. Регистрация фиксирует SHA256
файлов EDT `plugins`, `configuration/config.ini`, `bundles.info`, а также JDK
`bin`, `lib`, `conf`, `release`. Идентификатор профиля — SHA256 всего определения,
включая пути и имя. Изменение определения создаёт новый профиль. Ссылки и reparse
points запрещены; число файлов, глубина и объём ограничены. Дистрибутивы остаются
внешними зависимостями и в MIT-поставку не копируются.

Поддерживаемая экспериментальная пара: EDT core `27.0.2.v202609041212`
и EDT-MCP `2.16.1`. Наличие этих имён в инвентаре не удостоверяет происхождение
бинарников: администратор отвечает за выбранную поставку. Проверка настоящего
запуска — отдельный этап; список честно возвращает `qualification: not_run`.

Пример JSON регистрации (пути и хэш нужно заменить на значения своей установки):

```json
{
  "schema": 1,
  "name": "Локальный EDT 2026.1.3",
  "runtime_root": "C:\\Tools\\edt\\eclipse",
  "java": {
    "path": "C:\\Tools\\jdk17\\bin\\java.exe",
    "sha256": "SHA256 файла java.exe, 64 строчных шестнадцатеричных символа"
  }
}
```

```powershell
rentgen edt-profile-register --registry C:\Rentgen\registry.sqlite3 --project <project-id> --profile-json C:\Rentgen\edt.json
rentgen edt-profile-list --registry C:\Rentgen\registry.sqlite3 --project <project-id>
rentgen edt-profile-disable --registry C:\Rentgen\registry.sqlite3 --project <project-id> --profile-id <profile-id>
```

Регистрация и отключение требуют `project:admin`; список и использование —
`project:read`, `source:edit`, `analysis:run`. Проверка прав предшествует чтению
внешнего JSON через CLI. API не принимает URL, токен, дополнительные аргументы
Java или произвольное имя инструмента MCP.

Перед использованием сверяются состав, размеры и SHA256; зарегистрированные
файлы удерживаются без разрешения записи на время операции. Отключение профиля
или отзыв прав не позволяют вернуть успешный результат. Исполнитель также должен
перепроверять доступ между действиями и завершать своё дерево процессов при отказе.
Эти механизмы не являются песочницей ОС. Полная изоляция, рабочие файлы Eclipse,
ретенция и восстановление операций описаны в [плане адаптера](EDT-ADAPTER-PLAN.md).

Реестр ограничен 64 записями, включая незавершённые `pending-*`. Повторная
регистрация существующего определения идемпотентна и не включает отключённый
профиль. Автоматического удаления или повторного включения пока нет.

## Проверка 10 сентября 2026

На отдельном установленном EDT зарегистрированы 1262 файла среды и 179 файлов
JDK. С удержанием этих входов создан новый workspace, запущен принадлежащий
проверке процесс Java, выполнены MCP initialize и `list_projects`; затем дерево
процессов закрыто. Регистрация заняла 36,86 с, вся проверка — 59,92 с. Сервер
подтвердил `edt-mcp-server` 2.16.1 и протокол 2025-11-25. Использовался локальный
одноразовый Bearer-токен, исходники ядра из рабочей ветки и MCP Python SDK 1.30.0.
AI-модели не вызывались. [Сводка результата](evidence/edt-profile-startup-v1.json).

Этот запуск проверяет совместимость удержания файлов с настоящим EDT. Он не
проверяет готовность модели проекта, изменение метаданных или установленный
пакет нового ядра и не меняет `qualification` в реестре.
