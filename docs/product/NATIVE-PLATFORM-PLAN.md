# Воспроизводимая проверка нативной конфигурации

Следующий этап после smoke пустой базы: подтверждать загрузку собственных
метаданных и реальную проверку BSL установленным полным клиентом 1С.
Это проверочная инфраструктура для прямого редактирования; сама операция
редактирования метаданных в продукте и полная замена Конфигуратора ещё впереди.

Выбран новый каталог и новая файловая база на каждый запуск. Использование
переданной рабочей базы исключено интерфейсом сценария. Нативную основу XML
выгружает установленная платформа; исходники типовых решений не нужны.
В основу добавляется собственный общий модуль с заданным UUID и простой функцией.
Так проверяется совместимость фактической платформы без копирования чужой
конфигурации. GUI-автоматизация и бинарные контейнеры не требуются.

План:

1. Создать базу и выгрузить нативную основу.
2. Добавить собственный общий модуль, загрузить, проверить серверный BSL,
   обновить базу и выгрузить результат.
3. Загрузить копию с заведомой синтаксической ошибкой; требовать отказа проверки
   с указанием тестового модуля. Не обновлять базу ошибочной версией.
4. Загрузить исправленную копию с изменённой функцией, проверить, обновить,
   выгрузить; сравнить UUID и точный BSL с нормализацией BOM/переводов строк.
5. Сохранить аргументы, коды возврата, логи, хэши и границы приёмки. Все процессы
   ограничены по времени; при таймауте завершается только созданное дерево процесса.

Выполнено: все этапы на 8.3.27.2342, включая запуск приложения через собственный
модуль `OnStart`. Возвращаемые значения: 42 до ошибки, 42 после отказа без
обновления базы, 43 после исправления. Повторяемый скрипт и доказательства —
[PLATFORM-ACCEPTANCE.md](PLATFORM-ACCEPTANCE.md).

Успех требует положительной и отрицательной проверок. Отсутствие лицензии,
таймаут и непрочитанный лог не считаются успешным результатом. Формы, выполнение
бизнес-логики, обновления поставщика и откат остаются отдельными обязательными
проверками. Сценарий запускается явно на Windows с установленной платформой;
обычный GitHub runner не объявляет платформенную приёмку без 1С.
