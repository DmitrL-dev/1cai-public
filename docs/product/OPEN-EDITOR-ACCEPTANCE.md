# Приёмка подключения открытого агента

2026-09-09. Windows x64, VS Code 1.127.0, Cline 4.1.17 из официального VSIX,
установленный core0.1.0.dev3/MCP1.30.0/CPython3.11.9. Модель Ollama qwen3.5:9b
на localhost. Cline не модифицировался; использован публичный API расширения
`startNewTask` внутри настоящего Extension Development Host.

Проверка выполнена в новом профиле и искусственном проекте с одним BSL-модулем
50байт, UTF-8 BOM + CRLF. Перед запуском снимок снят поставленным Go scanner.
В тестовом профиле был задан список отдельных автосогласований MCP;
пользовательский генератор оставляет все автоматические согласования
выключенными. Позднее установлено: общий `actions.useMcp=true` в Cline 4.1.17
разрешает и остальные инструменты, поскольку проверка использует OR.
Поэтому прежний список не доказывает ограничения доступа. Фактически
наблюдались четыре вызова ниже. Shell/browser/edit-files агенту автоматически
не разрешались. Подробности: [проверка диагностики](EDITOR-DIAGNOSTIC-ATTEMPT.md).

Фактически выполнены четыре вызова `rentgen_project_head`, `rentgen_source_list`,
`rentgen_draft_start`, `rentgen_draft_edit`. Агент получил SourceRef от ядра,
сохранил исходную версию и заменил `BeforeEditor` на `AfterEditor` во второй.
Независимый новый CLI-процесс прочёл обе версии и обе operation receipts;
ответы совпали с ответами MCP из сохранённой истории настоящего Cline.
Кандидат49байт, SHA256:
`df29aaf0804f4b409d3dba08e957bc76bc98935aee29291265f288c79c379399`.
Живой источник50байт и head остались неизменными; BOM, CRLF и конечный перевод
строки сохранены. Завершение модели само по себе не использовалось как pass.

Пять локальных модельных запросов заняли231секунду. Это существенное ограничение
текущего профиля: полезная правка очень мала, большой системный контекст Cline
и описания инструментов занимают значительную часть окна модели. Следующий
этап должен проверить скорость/стоимость контекста и работу на настоящих
задачах. Превосходство над другими редакторами не подтверждено.

Адресные проверки генератора:11 passed (существующий каталог, неверный проект,
изменённый VSIX, явный локальный провайдер, буквальные пути с пробелами/кавычками,
неоднозначный editor CLI, checkout вместо установки, неподдерживаемый MCP/Python,
необязательный scanner). Ещё одна Windows-проверка воспроизвела таймаут настоящего
процесса с дочерним worker и подтвердила завершение обоих с кодом runner124.
Дополнительно настоящий CLI отверг неизвестный проект,
каталог профиля не появился. Black/Ruff и проверка diff прошли.

Исправления, найденные фактическим запуском: CLI лежит в каталоге версии новой
поставки VS Code; PowerShell должен дождаться installer process; Cline4.1.17
читает MCP из editor globalStorage, хотя модели хранит в CLINE_DATA_DIR.
Первый модельный запуск со старым предположением о пути MCP дал ошибку подключения
и не засчитывался. Исправление проверено новым профилем и успешной цепочкой выше.

Полная машинная запись хранится вне исходников:
`C:/1cAI/output/product-readiness-2026-09-08/open-editor-acceptance.json`.
Рабочие логи — в `output/editor-cline-acceptance-20260909/profile3`, включая
`host-acceptance.json`, `cli-draft.json`, историю Cline и hash её сообщения.
Тестовые процессы редактора/MCP завершились. Секреты и платные модельные
запросы в этом сценарии не использовались.

VSCodium позднее проверен отдельно: [результат с моделью4B](LOCAL-AGENT-PERFORMANCE.md).
Не принято этим этапом:
полная поставка/UX подключения, реальная сложная доработка, диагностика из
агента, тесты1С и применение, структурные изменения, обновление и observer.
Spectorn scan не состоялся из-за истёкшего сертификата; protection UNKNOWN.
