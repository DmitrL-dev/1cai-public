# Жизненный цикл одного соединения с владельцем редактора

**Статус: внутренний контракт и проверки на искусственном транспорте.**
Реальный Windows IPC ещё не подключён. Этот срез нужен разработчикам следующего
этапа [подключения владельца редактора](COLD_OWNER_BOOTSTRAP.md).

## Зачем нужен этот компонент

Запрос может успеть заполнить выходные данные, а затем прерваться. Запрос отмены
также может вернуться раньше завершения операции. Если сразу освободить буфер,
незавершённый ввод-вывод может продолжить обращаться к уже освобождённой памяти.

Компонент `scripts/verification/cold_owner_connection.py` сохраняет связанные
ресурсы до наблюдения завершения. Неизвестный результат закрытия оставляет
ресурс удержанным: повторная попытка не должна случайно закрыть другой ресурс.

## Какие записи удерживаются

| Запись | Что связывает |
|---|---|
| `_EditorEntry` | Уже удержанный редактор, его группу, generation и сведения о роли |
| `_EndpointContract` | Один экземпляр соединения, сведения о роли, ABI, правах и передаче ресурсов |
| `_OperationLease` | Политику размеров и сроков, устойчивое хранилище и владельца завершения |

Сессия выдаёт внутренние объекты-маркеры для этих записей. Проверяется идентичность
объектов одной сессии. JSON, PID, nonce, числовой handle или словарь с `accepted:true`
не заменяют запись. Имена с подчёркиванием — соглашение внутреннего API Python;
они не являются границей безопасности. Будущий Root backend должен хранить эти
объекты внутри доверенного процесса.

## Порядок операции

1. Проверить все три записи, их generation, связи, размеры и сроки.
2. Зарегистрировать операцию и удержать выходное хранилище, `OVERLAPPED`, буфер
   и слоты закрытия **до вызова транспорта**.
3. Выполнить запрос вне короткой блокировки владельца. Отдельная блокировка
   сериализует действия с вводом-выводом и используется без ожидания.
4. При отзыве оставить ресурсы удержанными. Отмена означает запрос на отмену.
5. Принять завершение только для того же объекта операции и того же набора ресурсов.
6. Закрывать собственные слоты по одному. Освободить общий буфер после закрытия всех слотов.

| Состояние | Значение |
|---|---|
| `REGISTERED` | Ресурсы уже удержаны; транспорт ещё не вызван |
| `IN_FLIGHT` | Вызов транспорта начат |
| `COMPLETION_PENDING` | Вызов вернулся или прервался; завершение ещё нужно наблюдать |
| `OBSERVED_COMPLETION` | Наблюдено завершение этой операции; идёт освобождение ресурсов |
| `CLOSED` | Все слоты закрыты и общий буфер освобождён |

Перед попыткой закрытия слот получает состояние `closing_unknown`. Исключение
или неизвестный результат сохраняет это состояние и хранилище; повторное закрытие
такого слота запрещено. Явный `False` от проверочного транспорта означает известный
отказ до закрытия и допускает повторную попытку того же слота.

Новый вызов отмены допускается только до `cancel_until_ns`. Новый опрос
завершения и закрытие каждого следующего слота допускаются до `closure_until_ns`.
Истёкший срок отзывает операцию и сохраняет незавершённые ресурсы. Вызов,
начатый в пределах срока, может сообщить свой результат; новый бюджет не выдаётся.
Само истечение срока не означает завершения или освобождения буфера.

Первоначальная ошибка отправки сохраняется и повторно выбрасывается без замены
ошибкой отмены или очистки. Позднее завершение позволяет очистку; отозванная
сессия при этом остаётся отозванной.

## Проверка разработчиком

```powershell
python -m pytest tests/unit/test_cold_owner_connection.py -q
```

Два сценария проверяют отказ до отправки при отсутствующих или поддельных записях
и цепочку «заполнение выхода → прерывание → отмена → позднее завершение →
неизвестное закрытие». Транспорт перехвачен; значения размеров и сроков в тестах
являются искусственными. Второй сценарий также проверяет отказ повторной
отправки после начавшейся очистки или полного закрытия и запрет новых действий
при истечении срока, используя детерминированные часы без ожидания.

## Следующий этап

Публичный вход `dispatch_registered_operation` пока возвращает
`OWNER_TRANSPORT_NOT_ADMITTED`. Проверочный транспорт подключается только через
внутренний вход тестов. Компонент не открывает Windows pipe, не запускает редактор,
Core, SDK или модель и не выдаёт READY, разрешение загрузки модели либо Native.

Для настоящего транспорта нужны удержанная идентичность extension host,
подтверждённые роли, точные Windows ABI и права endpoint, доверенная передача
ресурсов, измеренная политика памяти и сроков и реальный сборщик завершений.
Положительные проверки этого среза не заполняют эти сведения. Ранний отказ
launcher `DAILY_ROOT_EDITOR_OWNER_REQUIRED` остаётся действующим.
