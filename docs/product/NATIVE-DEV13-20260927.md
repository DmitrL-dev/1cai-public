Штатная установка нового runtime и обычный service CLI дали exit 0 и настоящий
`bsl/MagicNumber` с git_source_verified. 27 проверок подтвердили привязки
project/snapshot/commit/report, исходные UTF-8/CRLF и пустоту diagnostic-runs после
cleanup. Отдельный runtime с одним изменённым байтом JAR дал exit 2 и локальный

успешных owner reports и сохранность исходника.
[Квитанция](evidence/runtime-directory-stamps-sddl-installed-20260927.json).

## CLI apply и Undo на 1С

На установленном локальном wheel `b7b26fcd446e1841bcbc7ef1cb3f4797dd4fc992dfbe212c4555d07bb948b6cd` и 1С 8.3.27.2342
выполнены два proposal precheck: корректный BSL принят, ошибочный дал диагностику.
CLI применил правку к собственной копии синтетического модуля. В новой собственной
файловой базе 1С загрузка, CheckConfig, обновление и исполнение вернули **43**.
После Undo все шесть исходных файлов восстановлены по SHA256, повторное исполнение
вернуло **42**. Сохранены UUID модуля и конфигурации и head проекта; все 11 native
шагов завершились кодом 0 без timeout. Модель не вызывалась.
Полный dump не объявляется побайтно одинаковым из-за служебных данных платформы.
[Квитанция](https://github.com/DmitrL-dev/1cai-public/blob/main/docs/product/evidence/proposal-live-native-dev13-20260927.json)
фиксирует локальный кандидат; равенство его wheel с принятым CI wheel проверено.
Отдельный редакторский сценарий описан в заметках Companion и
[общем протоколе](https://github.com/DmitrL-dev/1cai-public/blob/main/docs/product/NATIVE-DEV13-20260927.md).

## Выбранная ревизия из редактора

Companion 0.1.13 с SHA256 `cefb0b365951ad3dd072794c414211bce0425177d75b101bb62e99f164f98d03` проверен в двух отдельных
процессах VS Code. Первый выбрал ревизию 1 при текущей 2: YAxUnit baseline failed
и candidate passed на отдельных базах. Второй после отключения профиля прочитал
тот же отчёт без нового тестового запуска. Исходник и head сохранены.
[Квитанция](evidence/tests-editor-dev13-20260927.json).
Все файлы отдельной копии VS Code 1.139.1 совпали в снимках до/после; системные библиотеки,
user-data, промежуточные изменения и внешняя аттестация этим не покрываются.
Прямой CLI подтвердил TEST_PROFILE_DISABLED для новой операции и побайтную
сохранность файлов завершённой операции при повторе. Обновления редактора и
расширений отключены только в собственном проверочном профиле. Предыдущий опыт
функционально прошёл, но снимки установки зафиксировали замену VS Code 1.138.0
на 1.139.1. Это расхождение сохранено в квитанции и стало причиной повтора
на отдельной копии; первый опыт не выдан за неизменный runtime.

Первоначальная подготовка редакторского профиля с модулем на съёмном E: была
отклонена CAPTURE_PLATFORM_UNSUPPORTED. Приёмочный профиль использует побайтно
ту же копию модуля на фиксированном C:, новый проект и сохранённые входные хэши.
Это следование контракту retained inputs; отклонённый опыт сохранён отдельно.
