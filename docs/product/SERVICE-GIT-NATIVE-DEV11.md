# Установленный Core dev11: GitAuditWorker с настоящим BSL-LS

24 сентября 2026 года установленный публичный Core `0.1.0.dev11` прошёл
**ограниченную локальную** проверку GitAuditWorker schema 2 в консольном режиме.
Использованы собственные синтетические Git-проекты с одним BSL-модулем,
предварительно опубликованный snapshot, настоящий BSL Language Server и
закреплённый JDK. Положительный путь с уже стабилизировавшимся runtime прошёл;
первый цикл на свежераспакованном runtime обнаружил отдельный отказ. Поэтому
нативная приёмка GitAuditWorker **сразу после установки** ещё не завершена.

## Привязка к опубликованным файлам

- Core [dev11](https://github.com/DmitrL-dev/1cai-public/releases/tag/core-v0.1.0-dev11):
  принятый ZIP SHA256 `9351d2b8790a358f66931a3067e8ba1823b61b7ca6b97989bb430f8fd124441a`.
  Использована та же установленная среда, что и в
  [проверке Source Observer](SERVICE-CONSOLE-NATIVE-DEV11.md), где 92 файла
  установленного `rentgen_core`/`rentgen_graph` сверены с wheel из ZIP.
  Для этого прогона дополнительно побайтно сверены все 10 файлов
  установленного `rentgen_diagnostics` с тем же wheel (SHA256 wheel
  `74cfe4a4f00369e13ef87c084ab1b62a016ac0661217fba015d5bccc831877b6`).
- `bsl-scan.exe` из этого ZIP: SHA256
  `8d81c1eda05d9c358385396861eb1df611d83489582f7293ad461c45017817c4`.
- Внешние файлы скачаны из выпусков [BSL-LS 1.0.5](https://github.com/1c-syntax/bsl-language-server/releases/tag/v1.0.5)
  и [Temurin 21.0.12.1+1](https://github.com/adoptium/temurin21-binaries/releases/tag/jdk-21.0.12.1%2B1).
  SHA256 исполняемого JAR —
  `de97f571e6474c5c151cf859294f589ee01152de3b4826b43e1a80b69ee2602a`,
  входного JDK ZIP —
  `f9d6e191ab098c0d416e7d588a24420a8621cd2f4720dab2459b8b7b2d2d8b4e`.
  Успешный нативный анализ сообщил `runtime_verified=true` после проверки
  закреплённых файлов. Эти бинарники не включены в выпуск Core.

## Наблюдаемые циклы

| Сценарий | Результат |
| --- | --- |
| Новый проект, ранее использованный runtime | Первый цикл `analyzed`, один owner report с `git_source_verified`, 0 BSL findings. Второй цикл `unchanged`; исходный модуль и Git working tree неизменны. Ещё один новый проект повторил положительный чистый цикл. |
| Новый commit с пустым `Исключение` на том же проекте | После нового snapshot нативный BSL-LS вернул два finding: `bsl/MissingCodeTryCatchEx` и `bsl/MissingParameterDescription`. GitAuditWorker опубликовал `analyzed` для commit `c3cd9202f609b111f1ff76dfb1407c72a23f3897`; SHA256 исходного модуля `02e73e08f94f30f0d5b20f05ea2bcb3d53fc9a206af753efd76753ebda3d7164`, snapshot `a947b022a8b90e6376765544e5032d3aea20ce147518c4f3c23062a7872d1f8e`. Исходник и рабочее дерево остались неизменны. |
| Два только что распакованных runtime | Первый цикл каждого завершился fail-closed: наружный `SERVICE_WORKER_FAILED`, журнал `GIT_ANALYZER_INCOMPLETE`, outbox `fatal`, без успешного owner report. Диагностическая обёртка настоящего адаптера установила внутренний `BSL_INPUT_CHANGED`, `runtime_verified=false`, `diagnostics_complete=false`. Повторный запуск без замены бинарников дал `analyzed`. |
| Ещё один новый runtime с паузой 5 секунд после распаковки | Первый цикл снова завершился `BSL_INPUT_CHANGED`; простую фиксированную паузу нельзя считать решением. |

Ещё один новый runtime с паузой 30 секунд также дал `BSL_INPUT_CHANGED` на
первом цикле. Позднее прямой вызов native-адаптера на свежей копии JDK, после
новой установки из этой копии и после новой распаковки официального ZIP
завершался `completed` с `runtime_verified=true` и двумя findings. Отдельная
серия из трёх независимых установок дала 3/3 таких первых анализов; её
[скрипт и локальная квитанция привязаны SHA256 в issue #23](https://github.com/DmitrL-dev/1cai-public/issues/23#issuecomment-5815030379).
Эти позднейшие контроли выполняли **адаптер напрямую**, а не полный цикл
GitAuditWorker, и не входят в ограниченную JSON-квитанцию ниже. Они показывают,
что отказ непостоянен, но не квалифицируют холодный путь и не объясняют
изменение метаданных каталогов.

Отдельная [повторная проверка 25 сентября](SERVICE-GIT-COLD-RECHECK-DEV11.md)
уже вызвала **полный** GitAuditWorker на двух новых runtime и профилях:
первые циклы schema 3 и schema 2 дали `analyzed`, повторные не дали второго
`analyzed`. Это тот же Windows-хост и ранее зарегистрированный синтетический
проект. [Новая ограниченная квитанция](evidence/service-git-cold-recheck-dev11-20260925.json)
не входит в первоначальную квитанцию этой страницы. Положительные циклы не
объясняют старые `BSL_INPUT_CHANGED` и не закрывают issue #23.

[Следующая серия на новых регистрациях проектов](SERVICE-GIT-NEW-PROJECT-DEV11.md)
обнаружила ещё один первый отказ **публичного полного worker**: наружный
`SERVICE_WORKER_FAILED`, журнал `GIT_ANALYZER_INCOMPLETE`, outbox `fatal` без
owner report. Повтор на том же runtime дал `analyzed`. Шесть независимых
проектов с диагностическим hook и два через обычный CLI дали положительные
первые циклы; [квитанция](evidence/service-git-new-project-dev11-20260925.json)
разделяет эти группы. Внутренний `reason` нового отказа не был записан, поэтому
его связь с прежним `BSL_INPUT_CHANGED` остаётся гипотезой.

На одном свежем runtime диагностическая обёртка `RuntimePins.verify` сравнила
два снимка инвентаря: у каталогов JDK `conf`, `lib`, `jmods` совпали файловые
идентификаторы, но изменились `write`/`change` timestamp. Причина изменения
метаданных **не установлена**. Это наблюдение не доказывает отсутствие
внешнего писателя и не разрешает ослабить retained-handle и SHA256 проверки.
Исходный модуль отрицательных циклов имел SHA256
`b057c96c16816b8fe835b62b6a6cde9ab8556653b3021676880bde3ccc59f5b9`;
оба неуспешных проекта сохранили чистый Git working tree и не создали owner
report. Подробный разбор и критерии исправления — в
[issue #23](https://github.com/DmitrL-dev/1cai-public/issues/23).

[Машинная ограниченная квитанция](evidence/service-git-native-dev11-20260924.json)
связывает релиз, внешние входные хэши, положительные и отрицательные циклы.
Её размер — 2969 байт, SHA256
`8f43614b0f6b7178721bd5483290c938e068102163fc49d92e5afa6e5e560637`.
Локальные скрипты и полный runtime сохранены вне Git; в квитанции указаны их
SHA256. Она не содержит SID и абсолютных путей хоста. Отдельная внешняя
аттестация не проводилась.

## Предел доказательства

Это проверка **консольного** GitAuditWorker на одном Windows-хосте и одном
синтетическом BSL-модуле с двумя версиями. Windows SCM, служебная учётная
запись, долгий runtime, отдельный внешний писатель, типовые `.cf/.cfe`,
формы/СКД, рабочая ИБ, HTTPS/DNS, доставка уведомлений и production deployment
не проверялись. `fatal` от свежего runtime не превратился в ложный успешный
отчёт, но сейчас не восстанавливается автоматически в том же цикле.
