# HTTP API истории черновиков

Реализовано в development checkout, 2026-09-09. Маршруты обязательны для
приложения; ошибка импорта останавливает его запуск. Нужны проверенный bearer
token, членство в выбранном проекте и schema4. Роль admin в JWT сама по себе
не предоставляет доступ. Actor берётся из проверенного subject и настроенного
auth realm; SID HTTP-службы не используется.

Префикс всех маршрутов: `/api/v1/projects/{project_id}`.

| Метод и путь | Вход | Право |
|---|---|---|
| `POST /snapshots/{snapshot_id}/drafts/{draft_id}` | JSON: `operation_id`, `expected_revision`, `title`, `proposal` | `project:read` + `source:edit` |
| `GET /drafts` | `limit`, `after_draft_id`, `status=active\|archived` | `project:read` |
| `GET /drafts/{draft_id}` | Необязательная `revision` | `project:read` |
| `GET /drafts/{draft_id}/history` | `limit`, `before_revision` | `project:read` |
| `GET /draft-operations/{operation_id}` | — | `project:read` |
| `POST /drafts/{draft_id}/archive` | JSON: `operation_id`, `expected_revision` | `project:read` + `source:edit` |
| `POST /drafts/{draft_id}/restore` | То же | `project:read` + `source:edit` |

Все ID операций и черновиков — canonical UUID. В первой записи ожидается
revision 0; дальше — номер версии, на основе которой редактировал пользователь.
`proposal` — полный объект, полученный через preview. Сервер проверяет его
содержимое и полный SourceRef, затем повторно сверяет сохранённый снимок.
Обычное сохранение не переносит черновик на новый снимок.

Параметры project в пути, query и `X-Rentgen-Project` должны совпадать. Для save
это относится и к snapshot. Остальные маршруты не выбирают снимок: query/header
snapshot отвергаются, а исходный снимок берётся из сохранённой версии. Неизвестные
и повторные query-параметры, лишние поля JSON, duplicate keys, NaN, невалидный
UTF-8 и вложенность больше 32 отвергаются.

## Ответ и восстановление неизвестного результата

Ответ имеет вид `{"result": ..., "request_id": "..."}`. Save/archive/restore
возвращают квитанцию с actor, operation ID, draft ID, revision, статусом,
заголовком, content ID и SourceRef. Get возвращает `{"receipt": ..., "proposal": ...}`.
Списки возвращают `items` и `next_after` либо `next_before`; они не содержат
исходных текстов. Размер страницы: по умолчанию 20, максимум 25.

Сохраняйте operation ID до отправки POST. Если соединение потеряно либо сервер
вернул `DRAFT_OUTCOME_UNKNOWN`, читайте `/draft-operations/{operation_id}`.
Полученная квитанция подтверждает конкретную историческую запись, которая может
уже не быть текущей версией. `null` означает отсутствие квитанции в момент чтения,
а не доказанную остановку ещё выполняющегося запроса. Нельзя автоматически
генерировать новый operation ID и повторять неопределённое сохранение.

Точный повтор с исходным actor, ID и запросом возвращает исходную квитанцию.
Другой запрос с этим ID — `OPERATION_CONFLICT`. При `DRAFT_CONFLICT` сохраните
локальный текст и предложите пользователю сопоставить его с новой версией.
Отзыв права записи после commit может скрыть ответ POST; оставшийся читатель
всё ещё может получить квитанцию отдельным GET. При полном отзыве доступа
квитанция и исходный текст не возвращаются.

## Границы выполнения

Права проверяются перед чтением тела, перед файловым чтением в worker, внутри
транзакции сохранения и после сериализации, непосредственно перед отправкой
ответа. Отзыв прав и ASGI send не атомарны; внешние middleware могут буферизовать
ответ. Все ответы имеют `Cache-Control: no-store`.

Тело ограничено 1.5 MiB и 10 секундами получения, ответ — 2 MiB. Оригинал и
кандидат имеют отдельные ограничения по 1 MiB. На процесс разрешена одна
операция с черновиками; save также занимает общий слот чтения снимка. Чтение
истории не открывает исходники или граф и не запускает анализатор. Передача
ответа ограничена 15 секундами. Отмена запроса не бросает worker с незавершённой
операцией: слот удерживается до его завершения и окончания/сбоя отправки.

| Статус | Значение |
|---|---|
| 400 | Неверный DTO, UUID или параметры |
| 401 / 403 | Нет проверенного token / недостаточно прав |
| 404 | Нет черновика или указанной версии |
| 408 / 413 | Тайм-аут получения тела / превышен лимит |
| 409 | Конфликт версии/операции, архив, несовместимый SourceRef или требуется schema4 |
| 429 | Занят слот; `Retry-After: 1` |
| 503 | Состояние недоступно либо исход операции неизвестен |

HTTP-проверки используют настоящую проверку JWT, проектные права, SQLite и
Go-снимки. Проверены конфликты, изоляция проектов, отзыв прав до чтения снимка и
после commit, лимиты, медленное тело и отмена запроса. В тесте отмены срок
передачи сокращён до 0.1 секунды; production-значение остаётся 15 секунд.
Общий механизм отправки также проверяется на disconnect, timeout и cancellation
существующими тестами preview/check. Повторный запуск Java для этого изменения
не требуется; реальные тесты 1С отложены пользователем.

Квитанция сохранения не подтверждает статическую проверку, тесты, approval или
применение. [Браузерный редактор](DRAFT-EDITOR.md) поддерживает сохранение,
историю и восстановление неопределённого результата; новый дистрибутив ещё не собран.
