# Рынок инструментов 1С и направление Рентгена

Срез подготовлен 12 сентября 2026 года. Это карта публичных продуктов и
репозиториев, а не утверждение о полном рынке: коммерческие функции, цены и
доступность меняются, поэтому перед покупкой нужна проверка у поставщика.

## Что уже есть

| Решение | Основная сила | Где Рентген не должен дублировать |
| --- | --- | --- |
| [1С:EDT](https://edt.1c.ru/) | Официальная IDE, Git, работа с несколькими конфигурациями, проверка «на лету», плагины | Это базовая среда и источник совместимости; Рентген добавляет контроль изменений, доказательства и автономный аудит поверх неё |
| [1С:Напарник](https://code.1c.ai/) | Официальный агент в EDT: поиск по проекту, правка кода и метаданных, Git, режимы планирования/исполнения | Сильная предметная интеграция, но зависимость от вендора и закрытой инфраструктуры; Рентген остаётся MIT, model-agnostic и self-hosted |
| [Confaster](https://confaster.ru/blog/cursor-1s/) | Работа рядом с классическим Конфигуратором, подсказки, ревью, AI-Merge, провайдеры и COM/MCP по описанию поставщика | Удобство интерактивного окна; Рентген делает воспроизводимый headless-контур с журналом, preflight, round-trip и CI |
| [BSL Language Server](https://github.com/1c-syntax/bsl-language-server) | Открытые диагностики BSL и LSP; активные релизы | Использовать как подключаемый анализатор и источник правил, не переписывать его |
| [SonarQube 1C BSL plugin](https://github.com/1c-syntax/sonar-bsl-plugin-community) | Quality-gate и история диагностик в SonarQube | Подключить через adapter; Рентген хранит provenance входа и связывает findings с snapshot/Git |
| [Vanessa-ADD](https://github.com/vanessa-opensource/add) | Открытая BDD/TDD-автоматизация и документация тестов 1С | Интегрировать как test provider; не создавать несовместимый второй язык сценариев |
| [1C_EDT_MCP_PUBLIC](https://github.com/fedukhin-sys/1C_EDT_MCP_PUBLIC) | Открытый MCP-плагин EDT с широким набором операций для проектов, метаданных, форм, отладки и тестов | Совместимость через MCP и строгий permission boundary; не конкурировать количеством инструментов |
| [bsl-ai-toolkit](https://github.com/vgtitov/bsl-ai-toolkit) | Agent-agnostic skills/MCP, byte-perfect metadata и эксплуатационные сценарии | Взять идеи контрактов и интегрироваться; наша ниша — независимая evidence-плоскость и полный lifecycle |
| [1c-copilot-mcp](https://github.com/EugeneVl/1c-copilot-mcp) | MCP-мост к 1С:Напарнику и специализированным знаниям | Оставить провайдером модели/знаний; Рентген не привязывает ядро к одному облачному сервису |

Публичный обзор для 1С также выделяет классические соседние инструменты:
Инструменты разработчика, Vanessa Automation, SonarQube BSL и плагины EDT.
Они закрывают отдельные этапы разработки, но не дают общего доказательного
цикла «изменение → проверка → сохранение доработок → отчёт владельцу».

## Вывод для позиционирования

Рентген следует выводить как **полностью открытый control plane проверяемой
разработки 1С**, а не как ещё один чат или IDE:

1. **MIT и self-hosted по умолчанию.** Локальная модель, Ollama/vLLM и любой
   совместимый upstream; сетевой маршрут можно пропускать через Spectorn.
2. **Evidence-first.** Каждая операция получает immutable input, exact
   snapshot/commit, права, хэши, журналы, platform/BSL/test receipts и
   понятный исход passed/diagnostics/failed/incomplete. Текст модели не
   является доказательством.
3. **Headless metadata и обновления.** Главный незакрытый рыноком участок —
   безопасно менять metadata/forms/СКД без ручного Конфигуратора, сохранять
   доработки при обновлении и уметь остановиться при неоднозначности.
4. **Непрерывный аудит.** Git watcher и scheduler анализируют только новый
   clean commit, связывают findings с кодом и snapshot, показывают новые,
   исправленные и повторно открытые нарушения, а владельцу дают отчёт с
   источником каждой метрики.
5. **Интеграция вместо изоляции.** BSL LS, SonarQube, Vanessa, YAxUnit,
   1C:EDT MCP и локальные/облачные модели подключаются адаптерами. Открытые
   проекты получают контрибьюции обратно, а не закрытый форк.

## Приоритеты

| Приоритет | Результат | Критерий выхода |
| --- | --- | --- |
| P0 | Metadata apply/undo на рабочей копии | Трёхфазный журнал intent → write → re-read, stale/revoke/conflict/recovery, round-trip на реальной 1С, без blind retry |
| P0 | Git watcher + поставляемые adapters BSL/других анализаторов | Новый commit анализируется один раз, результат привязан к exact tree, сбой повторяется безопасно, history переживает restart |
| P0 | Spectorn route | Зафиксирован весь маршрут upstream, policy при недоступности и отсутствие обхода защиты; secret не попадает в логи |
| P1 | Обновление конфигурации | Three-way merge базовой/текущей/новой конфигураций, конфликт на уровне object/UUID/BSL, тестовая база и откат |
| P1 | Владелец продукта | Версионируемый отчёт по quality, тестам, изменениям, рискам и источникам; бизнес-метрики только из подтверждённых runtime-данных |
| P2 | Совместимость и экосистема | Матрица 8.3.x/EDT/типовых конфигураций, .cf/.cfe и EDT XML, расширения, forms/СКД, MCP/editor UI |

## Что обещаем пользователю сейчас

Текущая ветка уже содержит открытое ядро snapshots/drafts/MCP, durable
observer findings, bounded Git watcher и read-only metadata qualification.
Живое metadata apply/undo, автоматический scheduler, поставляемый
репозиторный analyzer, обновление типовых конфигураций и Spectorn route пока
не объявляются готовыми. Это разделение должно оставаться видимым на стартовой
странице и в каждом release note.
