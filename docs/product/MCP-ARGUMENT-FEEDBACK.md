# Обратная связь для агента и повторная попытка

2026-09-09. Core `0.1.0.dev7` уточняет ошибки схемы MCP без изменения
принимаемых аргументов, прав или schema 4. Некорректные запросы по-прежнему
отклоняются до обращения к проектному состоянию.

## Что выявил реальный запуск

На установленном dev6 выполнена одна новая попытка Cline 4.1.17 legacy /
VSCodium 1.135.06055 / qwen3.5:4b. Профиль разрешал шесть инструментов на стороне
MCP и в отдельных автосогласованиях Cline; общий `useMcp` оставался false.
Модель работала с окном 32768, полностью в GPU (7106172928 байт).

Начальный запрос использовал 16722 входных токена. За 107,6 секунды было
начато девять модельных запросов, затем сработал прежний лимит. Агент дважды
добавлял лишний `manifest_hash` в `source_list`, затем не передал обязательный
`title` при создании черновика. Сервер возвращал общую ошибку без указания поля.
После повторных попыток модель создала и прочитала ревизию 1. Правка и анализ
BSL не состоялись. Других модельных запусков в этом этапе не выполнялось.

Новый процесс CLI подтвердил неизменные head, живой исходник и кандидат
ревизии 1. Независимый verifier возвращает `accepted=false`, `request-limit`
и exit code 1. Исходная задача исправления подавленной ошибки записи остаётся
непринятой. Тесты 1С отложены пользователем; применение недоступно.

## Что исправлено

`INVALID_ARGUMENT` теперь содержит ограниченные `details`:

- JSON Pointer к проверяемому полю (пустая строка обозначает корень);
- нарушенное правило и ожидаемый тип, диапазон, длину или формат;
- недостающие поля, лишние известные поля и разрешённые поля объекта.

Лишний `manifest_hash` назван явно, отсутствие `title` больше не приходится
угадывать. В ответе нет значений аргументов и исходного кода. Произвольные имена
полей тоже не отражаются: возвращается их количество. Показываются только
имена, уже объявленные в опубликованных схемах. Объём ответа не растёт вместе
с длиной неизвестных имён. Ограничение проекта и инструментов dev6 сохраняется.

Исправлен также проверочный скрипт: Cline добавляет `Error:\n` перед ошибочным
MCP-ответом. Verifier разбирает этот формат как ошибку; неподдерживаемый ответ
остаётся ошибкой с хешем. Префикс ошибки не превращает JSON с `result` в успех.
Незавершённая модельная задача не запускает дополнительный анализатор.

78 unit-проверок прошли (63 валидатора/черновиков/scope/verifier и 15 профиля).
Настоящий SDK подтвердил точные подсказки и приём исправленного запроса, а также
прежний отказ некорректных селекторов. Четыре проверки поставки прошли; отдельная
сборка дала те же артефакты. ZIP проверен установкой без сети. Установленный
клиент дополнительно подтвердил отсутствие значения-маркера в сообщении ошибки.

Профиль `output/editor-feedback-profile-20260909` создан для dev7/companion 0.1.3.
Установленный SDK подключился по его фактическим command/args/env: девять
инструментов, подсказка по ошибке, корректный head и отказ запрещённого capture.
Автосогласования выключены. Этот новый профиль пока не запускался в редакторе
с моделью; утверждение об успешном исправлении BSL на dev7 не делается.

## Проверка транспорта без запуска модели

В истории текущей попытки ответы assistant являются текстом с `<use_mcp_tool>`
и `<arguments>`. Это фактически использованный XML-режим. У установленного
официального legacy bundle обнаружен переключатель `nativeToolCallEnabled`:
он передаётся сборщику системного промпта/инструментов. Его OllamaHandler умеет
передавать `tools` в `/api/chat` и принимать `message.tool_calls`. Модель в
локальном `/api/show` заявляет capability `tools`. Это основание проверить
существующий нативный режим, но не доказательство его работоспособности с MCP.

В новом искусственном профиле `output/editor-native-transport-probe-20260909`
установлены тот же официальный Cline и companion 0.1.3 с core dev7. Скрипт
`scripts/verification/probe_open_editor_transport.py` временно включает флаг
и направляет провайдер только на собственный loopback-приёмник. Приёмник
сохраняет первый запрос, не пересылает его и не создаёт ответ assistant.
Редактор завершается по маркеру захвата; исходные настройки восстанавливаются.
Предел тела — 1 МиБ, предел запуска редактора — 60 секунд. Старые результаты
не перезаписываются. `transport-captured` не проходит verifier модельной задачи.

Получен ровно один `/api/chat`: **72318 байт**, **64861 символ** в system,
`num_ctx=32768`, **нет поля `tools`**, присутствуют XML-шаблоны инструментов.
Лог Cline сообщает выбор `generic`. Генерация модели не выполнялась; это
проверка транспорта, а не успешная правка. Новый dev7/companion также реально
активировался в VSCodium, но сценарий ремонта BSL остаётся непринятым.

Причина найдена в установленном `legacy/dist/extension.js`: `getNativeTools`
требует одновременно флаг и `use_native_tools:1` у выбранного шаблона.
Проверка провайдера `Ax` не включает Ollama; шаблон `generic` не содержит
нужной метки. Проверка семейства `uP` также не включает Qwen3.5. Поэтому
переход только на OpenAI-совместимый провайдер не устраняет ограничение
по этому коду. Второй транспортный или модельный прогон не запускался.
Сама Ollama документирует [OpenAI-совместимый API](https://docs.ollama.com/api/openai-compatibility),
но наличие endpoint не меняет выбор шаблона внутри Cline.

Следующий кандидат — адаптер, который
сам формирует служебные ID и запросы ядра, а от модели принимает проверяемую
правку. Локальная Ollama поддерживает JSON Schema через `format`, но ответ всё
равно требует независимой проверки. Это пока проектное направление, не
реализованный контракт. Источники: [structured outputs](https://docs.ollama.com/capabilities/structured-outputs),
[параметры chat API](https://docs.ollama.com/api/chat).

Локальный `output/editor-cline-research/ollama.ts` относится к новому движку;
он не доказывает поведение используемого legacy. Выводы выше проверены по
фактически установленному `legacy/dist/extension.js` официального Cline 4.1.17
и сохранённой истории текущего запуска.
