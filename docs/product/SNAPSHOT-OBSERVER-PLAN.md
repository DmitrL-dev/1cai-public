# Основа непрерывного аудита: сравнение сохранённых снимков

Цель: определить точный набор изменений между двумя снимками проекта без LLM
и чтения живой конфигурации. Это первый этап observer из ROADMAP; служба захвата,
планировщик и отчёты качества остаются отдельными обязательными этапами.

## Решение

Использовать уже реализованные SnapshotReadSession и публичный CLI. Альтернативы
— сравнение живых каталогов или независимый индекс observer — расходятся с
зафиксированными источниками и добавляют собственное состояние согласованности.
Сравнение сохранённых снимков даёт воспроизводимые ссылки и единые проверки прав.

Идентичность файла: слой и точный путь. Изменение: разные размер или SHA256.
Переименование: удаление и добавление. Изменения метаданных объектов, порядка
слоёв, качества и бизнес-показателей не выводятся из этих счётчиков.
Оба снимка должны принадлежать одному проекту и principal; используются
ограниченные сессии с проверкой целостности при выходе. Лимит ответа — 1 МиБ;
страница — 1–100 изменений. Курсор привязан к паре снимков, проекту и лимиту.
