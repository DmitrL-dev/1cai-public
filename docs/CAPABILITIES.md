# Возможности, ограничения и проверенные сценарии

**Основной опубликованный профиль — Windows x64 / CPython 3.11.**
Отдельное Linux x86_64 дополнение остаётся экспериментальным. Linux/macOS
добавляются поэтапно; наличие исходников не означает поддержку
всех операций. [Матрица платформ](product/PLATFORM-SUPPORT.md) и
[план развития](../ROADMAP.md) описывают эту границу.

[Главная](../README.md) · [Как пользоваться](USER_GUIDE.md) · [Каталог документации](README.md)

Этот обзор сохраняет технические подробности, которые нужны при выборе
интеграции или сценария применения. Наличие API, успешный искусственный опыт
и готовность всей ежедневной работы оцениваются отдельно.

### Контекст модели в Companion 0.1.18

В Companion 0.1.18 доступен выбор 8192, 16384 или 32768 токенов при создании
нового профиля; по умолчанию используется 32768. Управляемый адаптер сверяет
значение с профилем и проверяет размер полного сериализованного запроса
до HTTP. Он не обрезает текст при превышении лимита.

Проверка размера в байтах консервативна и не является точным токенизатором.
Она не доказывает достаточность RAM/VRAM или вместимость произвольного
шаблона модели. Меньшие контексты требуют своей native-проверки;
исторические результаты её не заменяют. Подробности и таблица лимитов — в
[профиле редактора](../integrations/open-editor/README.md#размер-контекста-локальной-модели--companion-0117).

## Применение правок

Применение требует отдельной операции с проверкой прав, ожидаемого состояния
и входов. Отчёт BSL, компиляция или тестовый результат сами по себе не
разрешают запись. Операции ниже имеют разные границы.

| Маршрут | Поддержанный объём | Запись и восстановление |
| :--- | :--- | :--- |
| [Workspace](product/METADATA-WORKSPACE.md) | Отдельная принадлежащая рабочая копия | CLI create/apply/undo/status/recover, inventory, backup и повторное чтение |
| [Designer XML live writer](product/METADATA-LIVE-APPLY.md) | Один базовый Designer XML слой; `rename_catalog_attribute` | Атомарный журнал, CAS undo и явное recovery |
| [BSL proposal live writer](product/PROPOSAL-LIVE-APPLY.md) | Один существующий BSL-файл в одном базовом Designer XML слое | Запечатанный журнал, CAS undo и явное recovery |
| [Native EDT adapter](product/EDT-EXECUTION.md) | Выбранный preview поддержанного сценария | Повторяет preview и публикует в новую принадлежащую копию; CAS undo |

**CAS** означает проверку ожидаемого состояния перед записью или возвратом.
Если файл уже изменён посторонним действием, операция может отказать.
`undo` возвращает поддержанное изменение при выполнении своих условий;
`recover` помогает разобрать и завершить восстановление после прерывания.
Это не универсальный откат любой конфигурации или информационной базы.

Для direct BSL writer исходное дерево и состояние проекта должны находиться
на одном томе файловой системы: публикация подготовленного файла использует
атомарную замену. Между томами операция отказывает до создания live-журнала.

Для остальных операций метаданных нужны собственные способы подготовки,
платформенные проверки и сценарии возврата. Применение в файлы выгрузки
не означает автоматически обновлённую информационную базу 1С.

Связанные контракты: [preview](product/METADATA-PREVIEW.md),
[подготовка apply](product/METADATA-APPLY.md),
[read-only qualification gate](product/METADATA-APPLY-GATE.md),
[миграция метаданных](product/METADATA-MIGRATION.md).

## Обновление и сопоставление метаданных

Для трёх сохранённых версий — исходной base, своей current и новой upstream —
доступен [three-way plan](product/THREE-WAY-UPDATES.md). Он различает сохранение
доработки, принятие upstream и конфликт по хэшу. Для однозначных решений
по путям собирает ограниченный candidate в памяти с digest; исходное
дерево при этом не меняется.

- [Designer XML по типу и UUID](product/METADATA-THREE-WAY.md): отдельный
  candidate для раздельных прямых `Properties`, с сохранением QName/namespace-фрагментов.
- [Семантические scopes](product/METADATA-THREE-WAY-SEMANTICS.md): BSL, формы
  и СКД считаются атомарными областями; статусы supported/conflict/unsupported явные.
- [EDT identity inventory](product/EDT-INVENTORY-IDENTITY.md#local-cli):
  read-only CLI для компактных `.mdo` и реальных `MetaDataObject/*.xml`,
  UUID, владельцев форм/команд и явно выбранного опубликованного EDT-снимка.
- [EDT identity three-way](product/EDT-IDENTITY-THREE-WAY.md):
  `edt-inventory-plan` сравнивает три сохранённых inventory по UUID/owner/layer.
- [EDT attribute three-way](product/EDT-ATTRIBUTE-THREE-WAY.md):
  read-only evidence вложенных реквизитов Catalog, их непосредственного
  владельца и хэшей; перенос между типами объектов отклоняется.
- [ibcmd fixture executor](product/EDT-FIXTURE-EXECUTOR.md):
  ограниченный create/import/export цикл с квитанциями и удержанием входов,
  без live apply.

Покрытие EDT частичное. Наличие plan/candidate и синтетического corpus не
подтверждает полноценное обновление типовых `.cf/.cfe` с сохранением всех
доработок. [Матрица совместимости](product/CONFIGURATION-COMPATIBILITY.md)
разделяет эти уровни доказательств.

## Наблюдение, отчёты и уведомления

| Компонент | Что делает | Граница |
| :--- | :--- | :--- |
| [Snapshot diff](product/SNAPSHOT-DIFF.md) | Сравнивает два сохранённых снимка | Не применяет изменения |
| [Observer](product/OBSERVER.md) | Захватывает изменённую выгрузку и сохраняет отчёты | Без запросов к LLM; отдельный локальный lifecycle |
| [Git watcher](product/GIT-WATCHER.md) | Сохраняет Git-находки с предусловиями и их lifecycle | Использует bounded adapter и [BSL-LS analyzer](product/GIT-BSL-ANALYZER.md); полная SCM/1С-приёмка отдельная |
| [Owner report](product/OWNER-REPORT.md) | Связывает quality findings и подтверждённые runtime-метрики | Без подтверждённого runtime adapter бизнес-значения остаются `not_available` |
| [Owner report store](product/OWNER-REPORT-STORE.md) | Сохраняет неизменяемые квитанции, читает их через CLI/MCP | Точный проект и snapshot, ограниченные списки; путь хранилища задаёт доверенный слой |
| [HTTPS delivery](product/NOTIFICATION-DELIVERY.md) | Явно отправляет durable outbox на разрешённый адрес | Ограниченный размер, allowlist; подтверждение после HTTP 2xx |
| [Notification receiver](product/NOTIFICATION-RECEIVER.md) | Проверяет bearer/idempotency и сохраняет digest receipt | В dev10 проверен локальный TLS/ASGI с Uvicorn/httptools; публичный HTTPS/DNS и downstream не приняты |

Observer может построить owner report из сохранённых findings выбранного
snapshot без повторного запуска Git/LLM. Ручной `record_findings` должен
явно передать `snapshot_id`; лимит `max_findings` выбирается явно.
`owner-report-build` собирает и сохраняет отчёт без промежуточного JSON.
Подробности — в [Git/snapshot evidence](product/GIT-SNAPSHOT-EVIDENCE.md).

[Generic runtime adapter](product/RUNTIME-METRICS.md) и
[экспорт регистра 1С/ERP](product/RUNTIME-SOURCE.md) читают retained evidence
с проверками доступа и происхождения. Они не придумывают бизнес-показатели
по исходному коду и не заменяют подтверждённый поставщик метрик.

В Core dev17 Git watcher schema 3 добавляет ограниченный автономный
маршрут: trusted scanner сначала создаёт принадлежащий snapshot, затем
находки связываются с точным commit и owner receipt. Отказ при отзыве прав,
гонках и неподтверждённом происхождении описан в контракте; полноценное
развёртывание Git-службы и 1С этим не объявляется принятым.
Контракты [service host](product/SERVICE-HOST.md),
[установки службы](product/SERVICE-INSTALLER.md) и
[снимка процессов](product/STOCK-PROCESS-INVENTORY-QUALIFICATION.md)
остаются отдельными от первого пользовательского запуска.

## Нативные опыты и состояние публикации

Core dev17 / Companion 0.1.18 опубликованы 5 октября 2026. Принятые компоненты,
CI и отдельная проверка всех десяти публичных файлов описаны в
[состоянии поставки](product/READINESS.md). Новая реальная editor/native 1С/AI-приёмка
не заявлена; следующие результаты остаются историческими.

Core dev15 исправляет выбор точного wheel из выбранных исходников.
Отсутствие этого wheel останавливает установку; другая версия из `dist`
не подставляется. MCP устанавливается по закреплённому профилю зависимостей.
Выпуск и совместимость редактора связаны с
[PR #39](https://github.com/DmitrL-dev/1cai-public/pull/39).

Пять Core CI опубликованного dev15 подтвердили каждый **2488 Python- и
69 Node-тестов**, Go и native Source Observer под LocalService.
Отдельная офлайн-установка принята; все семь публичных файлов двух выпусков
скачаны без авторизации и побайтно сверены.
Источники: [READINESS](product/READINESS.md),
[квитанция публикации](product/evidence/release-dev15-publication-20260928.json),
[Core notes](../releases/core/0.1.0.dev15/RELEASE_NOTES.md),
[Companion notes](../releases/companion/0.1.15/RELEASE_NOTES.md).

[Квалификация dev15](product/DEV15-RELEASE-QUALIFICATION-20260928.md) связывает
поставку с нативным тестом и восстановлением отчёта на 1С 8.3.27.2342.
Исторические [BSL apply/Undo](product/NATIVE-DEV13-20260927.md),
[переименование с сохранением данных](product/METADATA-LIVE-NATIVE-DEV13-20260927.md)
и [EDT](product/EDT-LIVE-NATIVE-DEV13-20260927.md) сохраняют версию dev13
фактического запуска. Они не переименовываются в приёмку текущих исходников.

Отдельный [business roundtrip](product/NATIVE-BUSINESS-ROUNDTRIP-20260913.md)
проверил запись/чтение, Article → SKU, повторное открытие и удаление
в синтетическом каталоге. Это host-only опыт, а не поставленная CLI-команда.

Логическое архивирование native-run доступно через admin-only CLI/MCP:
сохраняются audit, evidence и UUID. Освобождается логический retained-слот,
но дисковое содержимое не удаляется. Начиная с dev11 исправлена запись
полных Windows file ID; прежний dev10 сохранял эту ошибку.
[Примечания dev11](../releases/core/0.1.0.dev11/RELEASE_NOTES.md).

## Что ещё предстоит принять

- Переносимый CLI/MCP и адаптеры хранения/процессов с отдельной приёмкой на каждой ОС.
- Понятный первый запуск и воспроизводимые измерения времени/памяти до оптимизаций.
- Репрезентативную ежедневную AI-разработку 1С, её качество и предсказуемые затраты.
- Полную матрицу работы с объектами без GUI Конфигуратора.
- Обновление типовых конфигураций с сохранением доработок и бизнес-тестами.
- Полный набор источников непрерывного аудита и отчётов владельца.
- Защищённый модельный маршрут через Spectorn: к управляемой правке он пока не подключён.
