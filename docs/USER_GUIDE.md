# Как пользоваться Рентгеном

Руководство относится к текущему Windows-профилю Core/Companion.
[Платформы](product/PLATFORM-SUPPORT.md) и [версии](product/READINESS.md)
проверяются отдельно. Действия в редакторе не являются обязательными для
первого снимка через CLI.

[Главная](../README.md) · [Первое знакомство](START_HERE.md) · [Первый запуск](../GETTING_STARTED.md) · [Все инструкции](README.md)

Рентген работает с сохранёнными исходниками проекта и отдельными предложениями
изменений. Начните с чтения, затем подготовьте черновик, проверьте выбранную
версию и примите решение о следующем действии.

**Быстрые переходы:** [модули](#найти-и-прочитать-модуль) ·
[AI-правка](#подготовить-правку-с-моделью) ·
[ручная доработка](#исправить-сохранённый-черновик) ·
[проверки](#проверить-выбранную-версию) ·
[возврат после прерывания](#вернуться-после-прерывания) ·
[применение](#решить-применять-ли-изменение).

Если ещё нет проекта и профиля редактора, сначала выполните
[первый запуск](../GETTING_STARTED.md). Для выбора сценария и объяснения
подготовки есть [путеводитель](START_HERE.md).

## Шесть слов, которые понадобятся

| Термин | Простое объяснение |
| :--- | :--- |
| Выгрузка | Папка с файлами конфигурации 1С, подготовленная для работы с исходниками |
| Проект | Зарегистрированная выгрузка со своим ID, состоянием и правами доступа |
| Снимок | Сохранённая версия файлов проекта, к которой можно вернуться при чтении и сравнении |
| Черновик | Отдельное предложение изменения модуля, связанное с исходным снимком |
| Ревизия | Номер сохранённой версии черновика: например, первая версия и следующая правка |
| Квитанция | Сохранённый результат конкретной операции; помогает узнать её исход после прерывания |

**Core** — локальное ядро, которое хранит состояние и проверяет права.
**Companion** — расширение редактора с деревьями модулей и черновиков.
**MCP** — интерфейс, через который редакторский AI-агент обращается к ядру.
Для первого просмотра разбираться в протоколе MCP не требуется.

**VSCodium** — редактор исходного кода. **Cline** — расширение с AI-агентом,
которому можно поручить работу через разрешённые инструменты MCP.
**Ollama** запускает заранее загруженную языковую модель на вашем компьютере.
**BSL** — язык кода 1С; BSL Language Server анализирует такой код и выдаёт замечания.

## Где находятся ваши файлы

![Три места хранения: выгрузка с исходными файлами, состояние Рентгена со снимками и историей, профиль редактора с настройками и рабочими копиями](assets/where-files-live.svg)

1. **Папка выгрузки** содержит исходные файлы конфигурации.
2. **Папка состояния** содержит снимки и историю проекта; реестр указывает,
   где находятся зарегистрированные проекты.
3. **Профиль редактора** содержит настройки интеграции, рабочие копии для
   редактирования и журналы запусков.

Выберите для них отдельные папки. Обычное сохранение рабочей копии не означает
ни сохранения новой ревизии в ядре, ни применения к исходникам. Снимки и история
не заменяют резервные копии исходной информационной базы 1С.

## Что вы увидите в редакторе

| Место | Что там находится | Ваше действие |
| :--- | :--- | :--- |
| **«Рентген: модули»** | Файлы выбранного снимка | Найти путь и открыть код для чтения |
| **«Рентген: черновики»** | Сохранённые предложения изменений | Нажать на предложение и посмотреть сравнение |
| **История под строкой черновика** | Предыдущие сохранённые ревизии | Выбрать конкретную версию для чтения или проверки |
| **Рабочая копия черновика** | Отдельный редактируемый файл | Сохранить текст, затем отдельно сохранить новую ревизию в ядре |

Точные названия команд приведены ниже. Пустой список черновиков после первого
запуска допустим: предложения ещё не созданы. Доступность проверок зависит
от инструментов и параметров подготовленного профиля.

## Найти и прочитать модуль

Сначала выполните [первый запуск](../GETTING_STARTED.md) и откройте подготовленный
профиль через `launch.ps1`.

1. В проводнике редактора найдите **«Рентген: модули»**.
2. Нажмите кнопку поиска и введите часть пути: например, имя общего модуля.
3. Откройте найденный модуль. Вы увидите текст сохранённого снимка.
4. Если изменились файлы выгрузки, сначала создайте новый снимок, затем обновите
   дерево модулей. Кнопка обновления выбирает последний опубликованный снимок.

Поиск в этой панели работает **по пути файла**. Для анализа связей между
модулями доступны команды ядра `graph-resolve` и `impact`:
[пример CLI](product/CORE-INSTALLATION.md#первый-проект).

Короткий ID снимка виден в панели и вкладке. Уже открытые документы остаются
на своей версии после переключения снимка; откройте модуль заново, чтобы
прочитать выбранную новую версию. Подробности — в
[инструкции Companion](../integrations/vscode-rentgen/README.md).

## Подготовить правку с моделью

Для управляемой локальной правки нужны Ollama с заранее загруженной моделью
и закреплённый runtime BSL. Их установку задаёт
[профиль редактора](../integrations/open-editor/README.md#подготовка).

1. Выберите модуль и команду **«Рентген: правка с локальной моделью»** у его строки.
2. Укажите имя установленной модели и сформулируйте одно конкретное изменение.
   Хорошее задание объясняет ожидаемое поведение и условия, при которых оно нужно.
3. Дождитесь результата: адаптер создаёт черновик, проверяет исходную версию BSL,
   делает один запрос модели, сохраняет предложение и проверяет его BSL.
4. Откройте сравнение и прочитайте изменённые строки. Проверьте, соответствует
   ли предложение задаче и правилам вашего проекта.

Результат может быть ошибочным или не пройти содержательную проверку. Принят
один искусственный сценарий на Qwen3.5:9b; это не доказательство качества
произвольной разработки 1С. Размер модуля, запроса и время попытки ограничены;
точные пределы и параметры контекста — в [управляемой правке](product/LOCAL-REPAIR.md)
и [профиле редактора](../integrations/open-editor/README.md#размер-контекста-локальной-модели--companion-0117).

Другой маршрут — попросить Cline использовать инструменты MCP и сохранить
предложение в черновик. В свежем профиле автоматические согласования выключены:
проверяйте запрашиваемые действия в интерфейсе Cline. Доступ к другим проектам
и набор инструментов задаются при запуске и проверяются ядром.
Полные правила — в [инструкции интеграции](../integrations/open-editor/README.md).

Первый ручной черновик без модели создаётся через команды ядра
`proposal-create` и `draft-save`; требования и пример сохранения приведены в
[истории черновиков и CLI](product/DRAFT-HISTORY.md#сохранение-и-повторное-открытие).
Рабочая копия в редакторе предназначена для последующей доработки
уже сохранённого черновика.

## Исправить сохранённый черновик

1. В **«Рентген: черновики»** нажмите на черновик, чтобы открыть сравнение с его
   исходным снимком. Раскройте строку, чтобы посмотреть предыдущие версии.
2. Выберите **«Рентген: редактировать версию черновика»** у нужной версии.
   Откроется отдельная рабочая копия модуля.
3. Внесите изменение. Обычный **Ctrl+S** сохраняет файл рабочей копии.
4. Нажмите **Ctrl+Shift+P**, чтобы открыть палитру команд редактора —
   поле поиска действий. Найдите полное название
   **«Рентген: сохранить версию черновика»** и выполните команду.
   Только эта команда добавляет новую ревизию в историю ядра.
5. Обновите дерево черновиков, откройте новую ревизию и проверьте сравнение.

Если другой автор уже сохранил новую версию, ядро отклонит публикацию
с конфликтом. Ваш текст останется в рабочей копии. Откройте актуальный
черновик, сравните изменения и начните новую сессию редактирования.

После изменения нужны проверки **новой ревизии**. Отчёт о предыдущей версии
не подтверждает изменённый текст. Контракты сохранения и восстановления — в
[ручном редактировании](product/MANUAL-DRAFT-EDIT.md).

## Проверить выбранную версию

Сначала сохраните правку в ядро. Затем выберите черновик или конкретную
ревизию в его истории и запустите настроенную проверку из контекстного меню.

| Проверка | Что она даёт | Что подготовить |
| :--- | :--- | :--- |
| **«Рентген: проверить версию BSL»** | Замечания BSL Language Server для одного сохранённого модуля | Закреплённые Java и BSL-LS |
| **«Рентген: проверить версию в 1С»** | Раздельные результаты проверки исходной и предложенной версии платформой | Установленную 1С; одну выгрузку Designer XML без расширений |
| **«Рентген: выполнить тесты версии»** | Результаты доверенного тестового профиля для выбранной ревизии | 1С и заранее зарегистрированный профиль YAxUnit |

Отчёты открываются как JSON: это текстовые записи результатов. Проверьте
ревизию, итоговый статус и замечания. Ошибка запуска или отсутствие отчёта
не означают, что замечаний нет. Проверки 1С и тесты используют отдельные базы.

Нативные проверки могут занимать значительное место. Перед допуском нового
запуска проверяется свободный запас: 8 ГиБ на запуск сверх минимальных
4 ГиБ; действуют также лимиты накопленных результатов. Точная политика — в
[ресурсах нативных проверок](product/NATIVE-RESOURCES.md).

BSL-диагностика ищет определённые проблемы кода; она не подтверждает все
правила бизнеса. Компиляция проверяет свой набор условий, а тесты — только
те сценарии, которые заложены в выбранный профиль. Решение об изменении
принимается с учётом этих границ.

Точные требования: [BSL](product/EDITOR-BSL-CHECK.md),
[компилятор 1С](product/EDITOR-PLATFORM-CHECK.md), [YAxUnit](product/EDITOR-TESTS.md).

## Пример: к какой версии относится результат

Условный пример показывает порядок действий; названия и номера здесь
не заменяют ID вашего проекта.

| Этап | Что сохранено | Что вы можете проверить |
| :--- | :--- | :--- |
| Создали снимок А | Исходные файлы выбранного состояния | Код и пути модулей этого снимка |
| Сохранили черновик, ревизию 1 | Первое предложение изменения | Отличия ревизии 1 от снимка А |
| Доработали и сохранили ревизию 2 | Новую версию предложения | Отличия и результаты проверок ревизии 2 |
| Прочитали старый отчёт ревизии 1 | Результат прежней проверки | Только тот текст, который проверялся в ревизии 1 |

Перед дальнейшим решением откройте **ревизию 2** и проверьте её.
История сохраняет обе версии; новая проверка должна относиться к новой
сохранённой правке.

## Вернуться после прерывания

Если окно закрылось, истекло время или потерян ответ, сначала узнайте исход
**прежней операции**. Успешное завершение процесса и успешная операция — разные
факты; сохранённая квитанция помогает их проверить.

| Какая операция выполнялась | Команда чтения результата |
| :--- | :--- |
| Правка с локальной моделью | **«Рентген: проверить результат правки»** |
| Ручное сохранение черновика | **«Рентген: продолжить редактирование или получить результат»** |
| BSL-проверка | **«Рентген: результат проверки BSL»** |
| Проверка платформой | **«Рентген: результат проверки 1С»** |
| Тесты версии | **«Рентген: результат тестов»** |

Эти команды читают сохранённые записи. Они не вызывают модель или платформу
заново и не повторяют запись правки. Если итог остаётся неизвестным, сохраните
ID операции и журнал для разбора. Новый запуск правки создаёт другую попытку;
это не восстановление старой.

Для прерванного CLI-захвата используйте
[квитанцию публикации](product/CORE-INSTALLATION.md#прерванный-захват).

## Решить, применять ли изменение

Посмотрите отличия, проверьте смысл изменения и результаты доступных проверок.
Затем выберите отдельный поддержанный маршрут применения.

- [BSL в исходном файле](product/PROPOSAL-LIVE-APPLY.md): один существующий
  файл, один базовый слой Designer XML, ожидаемая версия и журнал операции;
  исходники и состояние должны находиться на одном томе файловой системы.
- [Метаданные в исходной выгрузке](product/METADATA-LIVE-APPLY.md): ограниченная
  операция переименования реквизита каталога, с собственными проверками и восстановлением.
- [Рабочая копия](product/METADATA-WORKSPACE.md): отдельная принадлежащая копия,
  проверка состава и команды возврата/восстановления.

Применение к файлам и обновление информационной базы 1С имеют разные границы.
Не каждый объект или предложенное изменение поддержано. Возврат по `undo`
проверяет состояние файлов и может отказать после посторонних изменений;
не считайте его безусловной заменой резервного копирования.
Подробная матрица — в [обзоре возможностей](CAPABILITIES.md#применение-правок).

## Хранение и передача материалов

Снимки и черновики содержат исходный код. Журналы правки могут содержать также
текст задания и предложение модели. Перед передачей отчётов другому человеку
проверьте их содержимое и правила доступа вашей команды.

Локальное ядро не делает профиль редактора полностью изолированным от сети.
Другие расширения и выбранный провайдер модели работают на своих условиях.
Права Рентгена также не изолируют его от других процессов того же
Windows-пользователя или администратора ОС.
